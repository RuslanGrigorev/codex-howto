# Восстановление файлов: Git не равен истории чата

## Чему вы научитесь

- Различать историю диалога в сессиях Codex CLI и фактическое состояние файловой системы в Git.
- Использовать команды точечного отката изменений (`git restore`) без деструктивного сброса всего репозитория.
- Анализировать diff-патчи перед отменой правок кода, внесенных агентом.
- Формировать контрольные точки сохранения перед рискованными операциями генерации кода.

## Что нужно перед началом

- Базовые навыки работы с Git (`status`, `diff`, `restore`, `commit`).
- Учебный Git-репозиторий без несохраненной ценной работы.
- Понимание, что продолжение или ветвление беседы (`resume`) не создает автоматических Git-коммитов.

## Схема процесса

Сравнение двух плоскостей состояния при работе с Codex CLI:

```
┌──────────────────────────────────────┐  ┌──────────────────────────────────────┐
│       Плоскость диалога Codex        │  │       Плоскость файлов Git           │
├──────────────────────────────────────┤  ├──────────────────────────────────────┤
│ Сессия UUID: 8a1b2c..                │  │ Рабочая директория: /repo            │
│ Сообщения, рассуждения, вызовы tools │  │ Файлы на диске, индекс, коммиты     │
│ Команды: /resume, /fork, /archive    │  │ Команды: git diff, git restore       │
└──────────────────┬───────────────────┘  └──────────────────┬───────────────────┘
                   │                                         │
                   ▼                                         ▼
[Сессия может быть продолжена,          [Файлы могут быть изменены агентом,
 но файлы в Git могли быть изменены      но Git коммит не создается
 или удалены внешней командой]           автоматически без команды оператора]
```

Откат сессии не откатывает файлы! Откат файлов не стирает сессию!

## Команды и параметры

Команды инспекции и безопасного восстановления:

```bash
# Проверка измененных файлов после работы агента
git status --short

# Построчный просмотр внесенных изменений
git diff -- discount.py

# Статистика изменений по всем файлам
git diff --stat

# Точечный откат изменений в конкретном файле (безопасно)
git restore -- discount.py

# Восстановление удаленного отслеживаемого файла
git restore --staged discount.py && git restore discount.py
```

## Разбор примера

Рассмотрим ситуацию, когда агент Codex в процессе рефакторинга случайно испортил алгоритм расчета скидки в `discount.py`:

1. Проверяем статус изменений в репозитории:
   ```bash
   git status --short
   # Вывод: M discount.py
   ```
2. Анализируем построчный diff:
   ```bash
   git diff -- discount.py
   ```
   Видим, что агент удалил проверку граничных условий и сломал расчет процентов.
3. Вместо деструктивной команды `git reset --hard HEAD` (которая уничтожит все несохраненные файлы во всем репозитории!), выполняем прицельное восстановление:
   ```bash
   git restore -- discount.py
   ```
4. Проверяем результат:
   ```bash
   git diff -- discount.py
   # Вывод пуст: файл возвращен к точному состоянию последнего коммита
   ```
5. В диалоге Codex сообщаем агенту о причинах отката и даем скорректированное задание с явными ограничениями.

## Ограничения и безопасность

- Никогда не используйте команды `git reset --hard` или массовое удаление каталогов `rm -rf` как стандартный способ «очистки сессии»: это приводит к безвозвратной потере незакоммиченной работы других разработчиков.
- Откат файла через `git restore` уничтожает незакоммиченные правки без возможности восстановления через корзину: убедитесь, что в файле нет нужного вам кода.
- Команда `git clean -fd` удаляет все неотслеживаемые файлы (включая временные тесты и конфигурации); используйте её только с флагом `--dry-run` (`-n`).

## Типовые ошибки

1. **Ожидание магии от /resume**: вера в то, что возобновление старой сессии вернет файлы на диске к тому состоянию, которое было в момент создания сессии.
2. **Глобальный сброс вместо точечного отката**: уничтожение ценных локальных правок через неосторожный `git checkout .` или `git reset --hard`.
3. **Игнорирование неотслеживаемых файлов**: создание агентом десятка временных файлов `test_temp_*.py`, которые не видны в `git diff`, но засоряют проект.

## Практика

1. В тестовом репозитории зафиксируйте коммитом начальное состояние файла `discount.py`.
2. Внесите тестовое изменение (например, добавьте опечатку или комментарий).
3. Проанализируйте изменение с помощью `git status --short` и `git diff`.
4. Выполните точечный откат файла с помощью `git restore -- discount.py` и подтвердите возврат к исходному состоянию.
