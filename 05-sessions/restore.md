# Восстановление файлов: Git не равен истории чата

## Чему вы научитесь

Сохранять исходную точку и осознанно отменять только собственные учебные изменения.

## Что нужно перед началом

Учебный Git-репозиторий. В ZIP без .git предварительно создайте отдельную копию для Git-практики; не экспериментируйте на чужой незакоммиченной работе.

## Как это работает

Продолжение или ветвление беседы сохраняет разговорный контекст, но не обязано создавать снимок файлов. Перед изменением кода нужно иметь отдельную проверяемую исходную точку.

Сначала посмотрите `git status`. Незакоммиченная работа может принадлежать пользователю. Её нельзя молча включать в учебный коммит или удалять ради чистоты проверки.

Команды восстановления способны уничтожить текущие изменения. Поэтому сначала читают diff, сохраняют нужную работу и выбирают конкретный файл. Глобальная очистка всего дерева для маленького упражнения не требуется.

## Разобранный пример

Безопасные команды наблюдения:

```bash
git status --short
git diff --stat
git diff -- discount.py
```

В своей одноразовой учебной копии после проверки diff можно разобрать `git restore -- discount.py`. Это действие отменяет текущую правку выбранного отслеживаемого файла; не выполняйте его над нужной работой.

## Самостоятельная практика

В отдельном учебном репозитории сохраните исходную версию файла обычным Git-процессом. Внесите одну небольшую правку и покажите diff. Объясните, что вы потеряете при восстановлении.

Только затем восстановите выбранный файл и снова сравните состояние. Не используйте `reset --hard` или удаление всей папки для этого урока.

## Ожидаемый результат

Восстановлен один согласованный файл; посторонняя работа не затронута. Вы можете объяснить различие между fork беседы и веткой Git.

<details>
<summary>Показать после самостоятельной попытки</summary>

Корректная последовательность: чистая учебная исходная точка → одна правка → просмотр diff → осознанное восстановление конкретного файла → повторный diff. Пустой diff в конце подтверждает только возврат отслеживаемого файла, а не удаление любой истории или временных файлов.

</details>

## Типовые ошибки

Считать /goal clear откатом; запускать восстановление без просмотра diff; затрагивать чужие незакоммиченные файлы.
