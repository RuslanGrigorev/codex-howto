# Урок 5: Сессии и восстановление в Codex CLI

## Цель урока
Понять модель сессий в Codex CLI: научиться сохранять контекст, возобновлять прерванный диалог (`resume`), ветвить обсуждение и четко отделять состояние разговора от состояния файлов в Git.

## Предпосылки
- Пройдены уроки «Введение в Codex CLI», «Точечное исправление бага», «Разрешения и безопасность» и «Инструкции проекта и AGENTS.md».
- Базовые навыки работы с Git (`git status`, `git diff`, `git restore`).

## Модель сессий в Codex CLI

Работая с Codex CLI, важно понимать фундаментальное разделение двух уровней состояния:

| Уровень | Чем управляется | Где хранится | Как сбрасывается/откатывается |
|---|---|---|---|
| **Контекст разговора (Session State)** | Codex CLI | Локальная база сессий Codex | Новая сессия (`codex`), переключение сессии |
| **Состояние файлов (Working Tree)** | Git / Файловая система | Файлы проекта в рабочем каталоге | `git restore`, `git checkout`, `git reset` |

> [!IMPORTANT]
> **Критическое правило:**
> Возобновление или откат разговора в Codex CLI **НЕ** откатывает измененные файлы на диске!
> Точно так же выполнение `git restore .` **НЕ** стирает из памяти агента историю уже отправленных сообщений и рассуждений.

### Основные команды управления сессиями

```bash
# Запуск новой сессии в текущем репозитории
codex

# Просмотр списка недавних сессий и их идентификаторов
codex session list

# Возобновление предыдущей сессии по ID
codex resume <session-id>

# Возобновление последней активной сессии
codex resume --last
```

### Ветвление и сохранение контекста

Когда вы работаете над сложной задачей, часто полезно исследовать альтернативную гипотезу:
1. Зафиксируйте текущий рабочий прогресс в Git (`git commit -m "wip: гипотеза 1"`).
2. При необходимости ответвления создайте новую ветку Git (`git checkout -b experiment`).
3. В Codex продолжите диалог в текущей сессии или начните новую с передачей контекста через краткую постановку задачи.

Если эксперимент неудачен:
- Для возврата файлов используйте стандартные команды Git (`git restore .` или `git checkout main`).
- Для очистки контекста рассуждений Codex запустите новую сессию, не таща за собой ошибочные предположения предыдущей сессии.

## Практическое упражнение: `session-restore`

В этом упражнении вам предстоит реализовать менеджер сессий `SessionManager`, который:
1. Хранит историю сообщений сессии изолированно от Git-репозитория.
2. Корректно возобновляет сессию по ее идентификатору.
3. Гарантирует, что очистка контекста сессии не приводит к несанкционированному удалению файлов проекта.
4. Отслеживает расхождение между состоянием файлов и историей сессии.

### Запуск проверки упражнения

```bash
python scripts/verify.py --exercise session-restore
```
