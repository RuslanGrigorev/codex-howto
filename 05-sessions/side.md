# Побочные вопросы и управление беседами

## Чему вы научитесь

- Использовать команды отвлечений (`/side`, `/btw`) для быстрых справок без разрушения основного контекста сессии.
- Управлять метаданными и идентификаторами сессий с помощью `/rename`, `/new`, `/archive` и `/delete`.
- Переключать режимы отображения интерфейса между терминальным TUI и выводом без оформления (`/raw`, `/tui`).
- Изолировать побочные гипотезы от изменений в рабочей директории проекта.

## Что нужно перед началом

- Понимание жизненного цикла сессий Codex CLI из урока [История сессий, возобновление и Git](resume.md).
- Установленный Codex CLI 0.160.0 с активным терминальным интерфейсом.
- Учебный репозиторий с базовой историей коммитов.

## Схема процесса

Разделение основного потока задачи и побочных запросов оператора:

```
[Основная ветка диалога: Рефакторинг auth.py] ──> Контекст задачи: 45K токенов
                       │
       Возник вопрос: "Как устроен jwt в PyJWT 2.8?"
                       │
                       ▼
       ┌───────────────────────────────┐
       │ Команда: /side или /btw       │
       └───────────────┬───────────────┘
                       │
                       ▼
[Изолированная подсессия / Side-turn]
├───────────────────────────────────────────────────────┤
│ 1. Вопрос задается модели без засорения основной цели │
│ 2. Ответ получен: краткая справка по синтаксису PyJWT │
│ 3. Файловая система и Git остаются нетронутыми        │
└──────────────────────┬────────────────────────────────┘
                       │
                       ▼
[Возврат в основной диалог: Фокус на auth.py сохранен]
```

## Команды и параметры

Управление беседами и параллельными вопросами в TUI:

```text
# Задать побочный вопрос без загрязнения контекста плана
/side Как устроен формат заголовка Authorization в Bearer токене?

# Быстрая справка по утилите без изменения фокуса
/btw какой флаг у curl выводит только HTTP-статус?

# Переименование текущей сессии для удобного поиска в истории
/rename refactor-auth-tokens

# Создание новой чистой сессии
/new

# Архивация или удаление текущей беседы
/archive
/delete
```

Переключение режимов вывода:
- `/raw` — вывод текста без форматирования и ANSI-кодов (удобно для копирования).
- `/tui` — возврат в полноэкранный интерактивный терминальный интерфейс.

## Разбор примера

Представьте ситуацию: агент реализует многоэтапный план обновления моделей данных. В середине работы вам необходимо уточнить синтаксис декоратора `@dataclass`:

1. Вместо отправки обычного сообщения в чат вводим:
   ```text
   /side Приведи пример frozen dataclass со значениями по умолчанию
   ```
2. Codex отвечает в модальном окне или временном блоке, не добавляя код примера в контекст текущей задачи рефакторинга.
3. Следующий запрос: «Продолжай выполнение шага 3 плана».
4. Агент продолжает модификацию целевых файлов, не пытаясь применить декоратор ко всем структурам подряд.

## Ограничения и безопасность

- Команды `/side` и `/btw` предназначены для консультаций и справочных вопросов: они не должны использоваться для параллельного вызова деструктивных команд изменения файлов.
- Удаление беседы (`/delete`) безвозвратно удаляет локальные журналы сессии из `.codex/sessions/`; перед удалением сохраните нужные выгрузки через `/export`.
- Побочные запросы расходуют токен-квоту учетной записи аналогично обычным обращениям к модели.

## Типовые ошибки

1. **Засорение контекста**: задание множества мелких сторонних вопросов в основном диалоге, приводящее к вытеснению проектных инструкций из памяти.
2. **Параллельная модификация файлов**: попытка через побочный вопрос отредактировать те же файлы, над которыми работает основной процесс.
3. **Случайное удаление истории**: вызов `/delete` вместо `/archive`, стирающий доказательства и контрольный журнал сессии.

## Практика

1. Начните интерактивную сессию решения задачи и назовите её с помощью `/rename task-investigation`.
2. В процессе выполнения задайте побочный вопрос с помощью команды `/side`.
3. Вернитесь в основной контекст и убедитесь, что агент помнит исходную задачу и не переключился на тему побочного вопроса.
4. Протестируйте переключение режимов `/raw` и `/tui`.

## Самопроверка

<details>
<summary>Подсказка и критерии самопроверки</summary>

- Убедитесь, что после выполнения команды `/side` последующий запрос `/status` или `/recap` показывает сохранение первоначальной цели.
- Проверьте, что имя сессии, заданное через `/rename`, корректно отображается в списке сессий `/resume`.
- Критерий успешности: побочный вопрос получил ответ, при этом рабочее дерево Git не содержит лишних изменений.

</details>
