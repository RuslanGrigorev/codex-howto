# Ветки, worktree и безопасное восстановление

## Чему вы научитесь

Использовать отдельное рабочее дерево Git для независимой задачи.

## Что нужно перед началом

Сначала пройдите: [Начало: что изучаем и как проверяем результат](../01-start/overview.md). Учебные файлы входят в поставку. Установленные программы и доступ к модели требуются только для соответствующей практики.

Git-ветка хранит историю коммитов; worktree даёт отдельный рабочий каталог. Это помогает разделить параллельные задачи, но не устраняет конфликтующие изменения автоматически. В Codex предусмотрена команда `/worktree`; сначала изучите её подсказки и текущее состояние репозитория.

Для прозрачной ручной подготовки в одноразовом репозитории:

```bash
git status --short
git worktree list
git worktree add ../course-second -b course-second
```

Не выполняйте пример рядом с чужим рабочим проектом, если каталог или ветка уже существуют. Перед восстановлением сохраняйте нужную работу и смотрите diff. Возвращайте конкретный учебный файл, а не все изменения команды. Не используйте массовое удаление каталогов как «очистку» сессии.

## Практика

Создайте два worktree, проверьте независимость файлов и веток. Попросите Codex назвать текущий каталог через `/pwd` и сравните с Git. После опыта удалите только специально созданный worktree штатными средствами Git, предварительно проверив отсутствие нужных изменений.

## Что считается выполнением в Codex

Без модели доступны весь текст, вопросы, исходники и локальные тесты. Они не подтверждают работу CLI. Для практики сохраните версию `codex --version`, модель, провайдера и обезличенный результат реального запуска. Отметку можно внести через `scripts/progress.py` после проверки, согласно [правилам валидации](../reference/validation.md). Самоотчёт ученика не заменяет выпускные доказательства проекта.
