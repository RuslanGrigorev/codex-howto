# Ветки, worktree и безопасное восстановление

## Чему вы научитесь

- Использовать Git worktree для полной физической изоляции рабочего каталога при параллельных экспериментах с Codex CLI.
- Применять команду `/worktree` и терминальные вызовы Git для создания независимых веток разработки.
- Предотвращать конфликты параллельной записи в одни и те же файлы разными сессиями агента.
- Безопасно очищать временные рабочие деревья без риска потери незакоммиченных изменений в основном репозитории.

## Что нужно перед началом

- Git репозиторий с хотя бы одним зафиксированным коммитом.
- Понимание различий между Git веткой (указателем на коммит) и Git worktree (отдельным рабочим деревом файлов).
- Установленный Codex CLI 0.160.0.

## Схема процесса

Изоляция рабочих деревьев Git для параллельных сессий Codex CLI:

```
┌────────────────────────────────────────────────────────┐
│               Основной репозиторий: /repo              │
│                     (ветка: main)                      │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ├──> git worktree add ../feature-a -b feature-a
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│           Изолированный Worktree: ../feature-a         │
│                   (ветка: feature-a)                   │
├────────────────────────────────────────────────────────┤
│ 1. Независимый каталог файлов                          │
│ 2. Сессия Codex CLI работает изолированно              │
│ 3. Изменения, сборка и тесты не аффектят /repo         │
│ 4. Общая база коммитов и .git объектов                 │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
[Готово к PR? ──> git merge / Cherry-pick ──> git worktree remove]
```

## Команды и параметры

Управление изолированными рабочими деревьями:

```bash
# Просмотр существующих рабочих деревьев
git worktree list

# Создание нового изолированного рабочего каталога и ветки
git worktree add ../codex-experiment-auth -b experiment/auth

# Запуск Codex CLI непосредственно в изолированном каталоге
cd ../codex-experiment-auth && codex

# Интерактивная проверка текущего рабочего каталога в сессии
/pwd

# Удаление временного рабочего дерева после завершения эксперимента
cd ../main-repo
git worktree remove ../codex-experiment-auth
```

В интерактивном TUI Codex доступна встроенная команда:
```text
/worktree
```
Она отображает статус текущего Git-окружения и позволяет переключать рабочие деревья при поддержке клиентом.

## Разбор примера

Рассмотрим сценарий рискованного рефакторинга ядра приложения, пока основной рабочий процесс занят отладкой текущего релиза:

1. Создаём worktree в соседнем каталоге:
   ```bash
   git worktree add ../refactor-core -b feature/refactor-core
   cd ../refactor-core
   ```
2. Запускаем сессию Codex CLI:
   ```bash
   codex "Переведи модуль storage на асинхронный движок aiofiles"
   ```
3. Агент перезаписывает файлы, удаляет синхронные вызовы и запускает тесты в `../refactor-core`.
4. Основной каталог `repo/` остаётся абсолютно чистым (`git status` показывает `nothing to commit`).
5. Если эксперимент неудачен: просто удаляем временное дерево `git worktree remove ../refactor-core --force`, не тратя время на откат коммитов в главной ветке.

## Ограничения и безопасность

- Не создавайте worktree внутри рабочего каталога текущего репозитория: размещайте их параллельно (например, `../repo-worktree-1`), чтобы избежать рекурсивного сканирования.
- В одном репозитории Git запрещает создание двух worktree на одну и ту же ветку: каждому дереву должна соответствовать уникальная ветка.
- Удаление рабочего дерева (`git worktree remove`) удаляет незакоммиченные файлы: перед удалением всегда проверяйте `git status` в целевом каталоге.

## Типовые ошибки

1. **Конфликт одновременной записи**: запуск двух экземпляров Codex в одной и той же директории на разных ветках без worktree.
2. **Случайное удаление корня**: вызов `rm -rf` вместо штатной команды `git worktree remove`.
3. **Забытые блокировки**: блокировка веток в Git из-за незакрытых рабочих деревьев на съемных дисках или удаленных сетевых путях.

## Практика

1. Создайте временный тестовый worktree командой `git worktree add ../sandbox-wt -b test/wt`.
2. Запустите Codex CLI в созданном каталоге и проверьте текущий путь командой `/pwd`.
3. Создайте тестовый коммит в ветке `test/wt`.
4. Вернитесь в исходный репозиторий, убедитесь в независимости состояния файлов и корректно удалите временное рабочее дерево через `git worktree remove`.

## Самопроверка

<details>
<summary>Подсказка и критерии самопроверки</summary>

- Убедитесь, что `git worktree list` выводит правильный список путей и веток.
- Проверьте, что изменения, сделанные в worktree, не видны в `git status` основного каталога проекта.
- Критерий успешности: временный worktree удален без ошибок, а основная ветка `main` сохранила исходное состояние.

</details>
