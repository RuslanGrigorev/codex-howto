# MCP-инструменты: список, вызов и ограничения

## Чему вы научитесь

- Инспектировать перечень инструментов, предоставляемых серверами Model Context Protocol (MCP).
- Использовать команды `codex mcp list` и слеш-команду `/mcp` для проверки активных инструментов.
- Понимать JSON-схемы аргументов инструментов и валидацию входных данных на стороне MCP-сервера.
- Изолировать доступ MCP-инструментов к файловой системе для предотвращения уязвимостей типа Path Traversal.

## Что нужно перед началом

- Знакомство с архитектурой MCP из урока [Локальный MCP через stdio и границы доступа](local-stdio.md) (схема D08).
- Настроенный локальный учебный сервер из упражнения `local-mcp`.
- Установленный Codex CLI 0.160.0.

## Схема процесса

Процесс обнаружения и исполнения MCP-инструмента:

```
[Пользовательский запрос: "Прочитай данные из docs/spec.md"]
                              │
                              ▼
┌────────────────────────────────────────────────────────┐
│             Диспетчер MCP в Codex CLI                  │
├────────────────────────────────────────────────────────┤
│ 1. Запрос tools/list к активным серверам               │
│ 2. Сопоставление с JSON-схемой аргументов:             │
│    {"name": "read_doc", "parameters": {"path": "..."}} │
│ 3. Проверка прав песочницы CLI                         │
└─────────────────────────────┬──────────────────────────┘
                              │
                              ▼ JSON-RPC: tools/call
┌────────────────────────────────────────────────────────┐
│            Локальный MCP-сервер (stdio)                │
├────────────────────────────────────────────────────────┤
│ 1. Валидация аргументов                                │
│ 2. Проверка выхода за пределы корня (Path Traversal):  │
│    if path.resolve().startswith(allowed_root):         │
│        return file_content                             │
│    else: return Error("Access Denied")                 │
└─────────────────────────────┬──────────────────────────┘
                              │
                              ▼
[Результат инструмента возвращается в контекст агента]
```

## Команды и параметры

Команды инспекции и вызова MCP-инструментов:

```bash
# Список зарегистрированных серверов и их статусов
codex mcp list

# Просмотр детальной информации по инструментам конкретного сервера
codex mcp inspect local-docs

# Проверка локального упражнения курса
python scripts/verify.py --exercise local-mcp --workspace .learning/workspaces/local-mcp
```

В интерактивном TUI сессии Codex:
- `/mcp` — интерактивный браузер подключенных MCP-серверов, ресурсов и инструментов.

Пример регистрации сервера с инструментами в `.codex/config.toml`:

```toml
[mcp_servers.local-docs]
command = "python"
args = ["-m", "mcp_server_docs", "--root", "./data"]
env = { DEBUG = "0" }
```

## Разбор примера

Рассмотрим вызов инструмента чтения документации:

1. В сессии вводим команду `/mcp`: сервер `local-docs` сообщает о доступности инструмента `get_document(rel_path: string)`.
2. Задаем вопрос: «Покажи разделы из `api_overview.md`».
3. Модель формирует JSON-RPC запрос:
   ```json
   {
     "jsonrpc": "2.0",
     "method": "tools/call",
     "params": {
       "name": "get_document",
       "arguments": {"rel_path": "api_overview.md"}
     },
     "id": 1
   }
   ```
4. Сервер проверяет, что файл находится строго внутри разрешенного каталога `./data/`, считывает его и возвращает структурированный ответ.
5. При попытке передать путь `../../../../etc/passwd` сервер возвращает ошибку `Invalid path: outside sandbox root`, предотвращая утечку приватных данных.

## Ограничения и безопасность

- Подключение MCP-сервера не означает автоматического доверия ко всем его инструментам: сервер выполняется как локальный процесс с правами вашей учетной записи.
- Сам MCP-сервер обязан самостоятельно проверять пути к файлам и параметры сетевых запросов: нельзя полагаться только на фильтрацию со стороны LLM.
- Ограничивайте время ожидания (timeout) вызова инструментов, чтобы зависший сервер не блокировал всю сессию Codex.

## Типовые ошибки

1. **Доверие непроверенным путям**: сервер принимает абсолютные пути и позволяет агенту читать системные файлы ОС.
2. **Путаница между инструментами и ресурсами**: попытка вызвать MCP Resource через протокол Tool Calling или наоборот.
3. **Неинформативные схемы аргументов**: отсутствие описаний полей в JSON-Schema инструмента, из-за чего модель галлюцинирует неверные параметры.

## Практика

1. Подготовьте учебное рабочее пространство `local-mcp` с помощью `scripts/verify.py --prepare local-mcp`.
2. Запустите независимую валидацию реализации протокола stdio:
   ```bash
   python scripts/verify.py --exercise local-mcp --workspace .learning/workspaces/local-mcp
   ```
3. Проверьте поведение сервера на двух сценариях: чтение корректного файла в каталоге данных и попытка выхода за пределы папки через `../`.
4. Убедитесь, что сервер не падает с необработанным исключением и продолжает обрабатывать последующие запросы.
