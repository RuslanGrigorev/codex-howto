# MCP-инструменты: список, вызов и ограничения

## Чему вы научитесь

Понимать, какие действия доступны через сервер, и проверять конкретный вызов.

## Что нужно перед началом

Учебный stdio-сервер из урока local-stdio. Используйте только безопасные файлы.

## Как это работает

Подключённый сервер не обязательно предоставляет нужный инструмент. Нужно отдельно проверить обнаружение сервера, список инструментов и контракт каждого вызова.

Имя, описание и схема аргументов помогают модели выбрать инструмент, но не заменяют ограничения самого сервера. Сервер должен проверять путь и входные данные даже тогда, когда запрос пришёл от доверенного клиента.

В учебном примере сервер читает ограниченный файл. Запрос наружу должен быть отклонён. Это локальный контур безопасности примера, а не доказательство, что любой MCP-сервер безопасен.

## Разобранный пример

В оболочке проверьте `codex mcp list`, а в Codex — `/mcp`. Затем попросите показать доступный учебный инструмент и прочитать конкретный файл внутри разрешённой папки.

Независимая транспортная проверка запускается через:

```bash
python scripts/verify.py --exercise local-mcp --workspace .learning/workspaces/local-mcp
```

Она дополняет, но не заменяет подключение настоящего клиента.

## Самостоятельная практика

Зафиксируйте имя инструмента и обязательные аргументы. Выполните одно успешное чтение и один запрос с выходом за корень учебных данных. Для отрицательной проверки используйте не секрет, а заранее известный безвредный путь.

Убедитесь, что после отказа сервер продолжает обслуживать допустимые запросы.

## Ожидаемый результат

Есть положительный и отрицательный результат конкретного инструмента; статус «сервер подключён» не выдан за всю проверку.

## Разбор решения

<details>
<summary>Показать после самостоятельной попытки</summary>

Успешный сценарий показывает правильное содержимое разрешённого файла. Неверный путь даёт отказ без утечки данных. После отказа повторный правильный вызов работает. Если список пуст, сначала диагностируют обнаружение сервера, а не переписывают учебный файл.

</details>

## Типовые ошибки

Считать list полным интеграционным тестом; доверять описанию вместо проверки входов; использовать реальные секреты в отрицательном примере.

## Проверка знаний

Ответьте на вопросы внизу страницы. В исходном репозитории они доступны в [файле вопросов](tools.quiz.json). Правильные ответы подтверждают понимание; выполнение практики фиксируется отдельно.
