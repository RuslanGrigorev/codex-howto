# Настоящий локальный MCP через stdio

## Чему вы научитесь

Запустить учебный stdio-сервер и проверить протокол отдельно от подключения к Codex.

## Что нужно перед началом

Сначала пройдите: [Начало: что изучаем и как проверяем результат](../01-start/overview.md). Учебные файлы входят в поставку. Установленные программы и доступ к модели требуются только для соответствующей практики.

MCP-сервер и учебный класс с похожими методами — не одно и то же. Для stdio нужен процесс, который читает JSON-RPC-сообщения из stdin и пишет ответы в stdout. Диагностика идёт в stderr: случайный `print` в stdout ломает протокол.

Сервер `examples/local-mcp/solution/mcp_server.py` реализует согласование `initialize`, уведомление инициализации, `tools/list`, `tools/call` и инструмент чтения ограниченного UTF-8-файла. Сообщения разделены переводами строк. Это небольшой учебный сервер, не универсальная промышленная библиотека MCP.

## Подключение в отдельном профиле

После подготовки упражнения используйте абсолютный путь к **своей** копии скрипта и безопасной папке с данными. Введите команду согласно `codex mcp add --help`:

```text
codex mcp add courseFiles -- python /ABSOLUTE/PATH/mcp_server.py --root /ABSOLUTE/PATH/data
codex mcp list
```

`/ABSOLUTE/PATH` — явное место подстановки, не существующий путь курса. Корневой каталог чтения передаётся обязательным аргументом сервера `--root` согласно конфигурации в [справочнике](../reference/config.md). Без подготовки данных сервер не следует направлять на рабочие документы.

## Практика и подсказка

Пройдите независимые тесты, затем подключите сервер к Codex в отдельном CODEX_HOME. Запросите список инструментов, прочтите один учебный файл и проверьте отказ для пути наружу. Процесс должен оставаться доступным после одного запроса. Уведомление без ID не получает JSON-RPC-ответ.

Сервер ограничивает пути и размер файла, но предназначен для доверенных лабораторных данных. Он не защищает от всех гонок и не даёт полного OS-изолятора. Реальный сценарий подключения проверяется отдельно от транспортного теста.

## Проверяемое упражнение

Выполняйте команды из корня репозитория или из `source` готового офлайн-пакета. Подготовка не перезаписывает существующую работу.

```bash
python scripts/verify.py --prepare local-mcp
# Измените файлы в .learning/workspaces/local-mcp
python scripts/verify.py --exercise local-mcp --workspace .learning/workspaces/local-mcp
```

Проверка запускает независимый `examples/local-mcp/test.py`, а не тест из рабочей папки. Эталон находится в `examples/local-mcp/solution`; открывайте его после собственной попытки. Тестируемый Python-код исполняется на вашей машине: запускайте только доверенные учебные файлы. Ограничение пути не является OS-песочницей.

## Что считается выполнением в Codex

Без модели доступны весь текст, вопросы, исходники и локальные тесты. Они не подтверждают работу CLI. Для практики сохраните версию `codex --version`, модель, провайдера и обезличенный результат реального запуска. Отметку можно внести через `scripts/progress.py` после проверки, согласно [правилам валидации](../reference/validation.md). Самоотчёт ученика не заменяет выпускные доказательства проекта.
