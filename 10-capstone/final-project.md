# Урок 10: Итоговая комплексная практика (Capstone Project)

## Цель урока
Объединить все изученные концепции Codex CLI в сквозном комплексном проекте:
1. Организация рабочего процесса с формулированием ограниченной задачи.
2. Соблюдение правил `AGENTS.md` и политик безопасности песочницы.
3. Разработка функциональности по методологии TDD (тесты, реализация, мутационное тестирование).
4. Проверка и валидация через автономный раннер проекта.

## Предпосылки
- Успешно пройдены все предыдущие 9 модулей курса:
  - 01-start, 02-workflow, 03-safety, 04-instructions, 05-sessions,
  - 06-skills, 07-mcp, 08-automation, 09-extensions.

## Сквозной сценарий проекта

В итоговом проекте вы создаете ядро аналитического модуля `CourseReportProcessor` для платформы автономного обучения. Модуль отвечает за консолидацию и статистическую обработку учебных результатов студентов:
- Прием и строгая валидация входящих данных тестирования.
- Вычисление процента успешности сдачи (`pass_rate`) и среднего балла (`average_score`).
- Ранжирование модулей по уровню усвоения материала.
- Безопасная обработка граничных случаев (пустые наборы данных, экстремальные значения оценок).

```text
[ Сырые отчеты JSON ]
         │
         ▼
[ Валидация схемы и диапазонов ] ──► (Ошибка при некорректных баллах)
         │
         ▼
[ Агрегация метрик и ранжирование ]
         │
         ▼
[ Итоговая аналитическая сводка ]
```

## Критерии качества кода

1. **Детерминированность:** Алгоритм должен возвращать строго воспроизводимый результат на одинаковых входных данных.
2. **Устойчивость к граничным случаям:** Обработка пустого входного списка не должна приводить к ошибкам деления на ноль (`ZeroDivisionError`).
3. **Безопасность:** Отсутствие зависимостей от внешней сети, абсолютных локальных путей и системных глобальных файлов.

## Практическое упражнение: `capstone-project`

Вам предстоит завершить реализацию класса `CourseReportProcessor` в каталоге `examples/capstone-project/`:
1. Реализуйте метод `process_reports(raw_reports)`.
2. Обеспечьте прохождение всех тестов в `test.py`.
3. Убедитесь, что все ошибочные мутации отклоняются проверочным раннером.

