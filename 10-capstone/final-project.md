# Итог: изменение, доказательства и воспроизводимость

## Чему вы научитесь

- Выполнять полный инженерный цикл разработки с Codex CLI: от постановки задачи до фиксации доказательств качества.
- Формировать проверяемые планы (`/plan`) и долгосрочные цели (`/goal`) с детерминированными критериями завершения.
- Разделять локальные тесты упражнений и доказательства реальной совместимости с CLI.
- Выполнять итоговое комплексное упражнение `capstone-project` с валидацией контрактов.

## Что нужно перед началом

- Освоение всех предшествующих модулей курса: от базового рабочего цикла до MCP, хуков и автоматизации.
- Подготовленное учебное рабочее пространство `.learning/workspaces/capstone-project`.
- Установленный Codex CLI 0.160.0 или использование автономного профиля проверки.

## Схема процесса

Комплексный сквозной цикл решения задачи Capstone:

```
[Постановка задачи: исправление правил валидации данных]
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│             Фаза 1: Планирование и анализ              │
├────────────────────────────────────────────────────────┤
│ 1. Изучение контракта в examples/capstone-project/test.py
│ 2. Согласование плана через /plan                      │
│ 3. Фиксация измеримых критериев приемки в /goal        │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│             Фаза 2: Реализация и тестирование          │
├────────────────────────────────────────────────────────┤
│ 1. Точечное изменение логики в workspace               │
│ 2. Запуск локального независимого теста (test.py)      │
│ 3. Проверка отсутствия регрессий в смежных модулях     │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│             Фаза 3: Аудит и фиксация доказательств     │
├────────────────────────────────────────────────────────┤
│ 1. Запуск ревьюера через навык $course-review          │
│ 2. Проверка git diff: только запрошенные изменения     │
│ 3. Сохранение контрольного отчета о валидации          │
└────────────────────────────────────────────────────────┘
```

## Команды и параметры

Команды подготовки, запуска и верификации итогового проекта:

```bash
# Подготовка чистого рабочего пространства для Capstone проекта
python scripts/verify.py --prepare capstone-project

# Проверка решения независимым тестовым скриптом
python scripts/verify.py --exercise capstone-project --workspace .learning/workspaces/capstone-project

# Запуск комплексной верификации всего курса в автономном режиме
python scripts/verify.py --profile offline
```

В интерактивной сессии Codex CLI:
```text
/plan Составить пошаговый план исправления модуля скидок
/goal Реализовать исправление и добиться прохождения независимых тестов
$course-review .learning/workspaces/capstone-project
```

## Разбор примера

Рассмотрим процесс выполнения итогового задания:

1. Готовим рабочее пространство командой `python scripts/verify.py --prepare capstone-project`.
2. Анализируем контракт: независимый тест `test.py` требует корректной обработки граничных условий, отсутствия утечек данных и правильного расчета скидок.
3. В сессии Codex формулируем цель:
   «Исправь логику в `validator.py` так, чтобы пустые строки и отрицательные значения вызывали `ValidationError`, не меняя при этом независимый тестовый файл».
4. Агент точечно модифицирует `validator.py`.
5. Запускаем верификатор:
   ```bash
   python scripts/verify.py --exercise capstone-project --workspace .learning/workspaces/capstone-project
   ```
6. Тест возвращает `PASS: All 12 test assertions completed successfully`.

## Ограничения и безопасность

- Никогда не модифицируйте файлы тестов `examples/capstone-project/test.py` ради получения фиктивного успешного статуса: тест запускается из защищенной эталонной папки.
- Успешное выполнение локального теста на Python доказывает корректность бизнес-логики, но не заменяет протокол реального прогона в Codex CLI.
- В отчете Capstone-проекта запрещено использовать выдуманные версии или заявлять о совместимости без указания точного хэша коммита и журнала запуска.

## Типовые ошибки

1. **Редактирование проверочных скриптов**: попытка подогнать независимый валидатор под некорректный ответ.
2. **Смешение профилей**: выдача результатов офлайн-тестов за подтвержденную совместимость с живым API провайдера.
3. **Отсутствие ревью**: коммит изменений без анализа diff и поиска скрытых сайд-эффектов.

## Практика

1. Подготовьте и выполните итоговое упражнение `capstone-project`:
   ```bash
   python scripts/verify.py --prepare capstone-project
   # Отредактируйте файлы в .learning/workspaces/capstone-project
   python scripts/verify.py --exercise capstone-project --workspace .learning/workspaces/capstone-project
   ```
2. Проведите аудит полученного diff с помощью наставника `$learn` или собственного навыка ревью.
3. Зафиксируйте итоговый отчет о выполнении с указанием затраченного времени, проверенных файлов и статусов тестов.
