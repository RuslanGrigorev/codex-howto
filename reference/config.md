# Конфигурация: минимальные рабочие контракты

Формат `config.toml` проверяется как TOML и как конфигурация выбранной версии. Одного синтаксического разбора недостаточно. Поставляемые примеры не являются полной локальной копией официальной схемы; строгая нативная проверка — отдельное релизное условие.

## Безопасное начало

```toml
approval_policy = "on-request"
sandbox_mode = "read-only"
web_search = "disabled"
```

`model` при необходимости задаётся строкой с доступным у провайдера именем. Не используйте таблицу `[model]` с вымышленной моделью. Настройки режима и разрешений не надо придумывать по аналогии с другими клиентами.

Для экспериментов создайте отдельный `CODEX_HOME`, не перезаписывая основной профиль. Запускайте `codex --strict-config`, затем проверяйте эффективные значения через `/debug-config`. Это может потребовать подготовленной авторизации для полного интерактивного запуска. Административные ограничения не отменяются простым указанием более позднего пользовательского поля.

## MCP stdio

Пример шаблона: замените оба абсолютных пути на подготовленные учебные каталоги. Он **не устанавливается автоматически**.

```toml
[mcp_servers.courseFiles]
command = "python"
args = ["/ABSOLUTE/PATH/mcp_server.py", "--root", "/ABSOLUTE/PATH/data"]
```

Секция называется `mcp_servers`, а не `mcp.servers`. Серверу нужен реальный читающий цикл stdin/stdout; образец включён в `examples/local-mcp`. Корень чтения задаётся его обязательным `--root`, это параметр нашего учебного сервера, не Codex. Для сетевого MCP используйте поддерживаемый `url` и предусмотренный механизм входа, не сохраняйте токен литералом в файле.

## Другие конфигурации — другие схемы

`AGENTS.md` содержит инструкции. `.agents/skills/NAME/SKILL.md` описывает навык. `.codex/agents/NAME.toml` — определение пользовательского субагента. `hooks.json` содержит нативные hooks. `.rules` относится к политике команд. Эти форматы нельзя считать взаимозаменяемыми.

`examples/hooks/hooks.json` предполагает рабочую папку с доверенным `hook_runner.py`; активировать его следует только в изолированном учебном профиле после просмотра кода. Изменение hook-определения может требовать повторного доверия.

## Профили и обновления

Текущая документация описывает `--profile NAME` как слой из `NAME.config.toml` в `CODEX_HOME`. Не копируйте старые примеры профилей без проверки выбранной версии. `-c key=value` подходит для осознанного разового изменения, но не заменяет проверку действующих ограничений.

При обновлении сравнивайте **полную** официальную схему, включая изменения значений существующих полей и вложенных определений, а не только список верхних ключей. Обновлятор курса сохраняет SHA-256 схемы и должен требовать пересмотра при его изменении.
