# Конфигурация Codex CLI: Полная спецификация и справочник

Целевая версия — **Codex CLI 0.160.0**. Конфигурационный файл использует формат **TOML** и валидируется на соответствие строгой схеме `config.schema.json`. Любые неизвестные ключи или невалидные типы данных вызывают ошибку при включённом флаге `--strict-config`.

---

## 1. Иерархия и приоритет слоёв конфигурации

Codex CLI применяет многоуровневую модель слияния конфигураций (Configuration Precedence). Значения на более приоритетных уровнях переопределяют настройки предыдущих уровней:

```text
┌────────────────────────────────────────────────────────┐  Высший приоритет
│ 1. Флаги командной строки (-c key=value, --sandbox...) │
├────────────────────────────────────────────────────────┤
│ 2. Именованный профиль (--profile NAME / NAME.toml)    │
├────────────────────────────────────────────────────────┤
│ 3. Конфигурация рабочей области (.codex/config.toml)   │
├────────────────────────────────────────────────────────┤
│ 4. Пользовательская конфигурация (~/.codex/config.toml)│
├────────────────────────────────────────────────────────┤
│ 5. Системная конфигурация (/etc/codex/config.toml)     │
├────────────────────────────────────────────────────────┤
│ 6. Встроенные значения по умолчанию (Defaults)         │  Низший приоритет
└────────────────────────────────────────────────────────┘
```

> **Важно**: Административные ограничения безопасности (например, блокировка записи в системные каталоги или запрет опасных инструментов) не могут быть ослаблены настройками проекта или пользователя.

## 2. Канонический пример конфигурации (Все 18 ключей)

Ниже приведён эталонный файл конфигурации `config.toml`, демонстрирующий все 18 канонических параметров Codex CLI 0.160.0:

```toml
# --- Ядро и Модель ---
model = "gpt-5"
system_prompt = "Ты — инженерный ассистент с упором на безопасность и точность тестов."
instructions = "Соблюдай строгие стандарты кодирования, проводи валидацию перед коммитом."
max_context_tokens = 128000
timeout_seconds = 600
temperature = 0.2
top_p = 0.95
stream = true
log_level = "info"

# --- Безопасность и Песочница ---
approval_policy = "untrusted"
sandbox_mode = "workspace-write"
web_search = false

# --- Ограничение инструментов ---
allowed_tools = ["read_file", "write_file", "run_command", "list_dir"]
blocked_tools = ["danger_delete_volume", "eval_untrusted_script"]

# --- Переменные среды для процессов инструментов ---
[environment_variables]
PYTHONUNBUFFERED = "1"
CODEX_MANAGED = "true"

# --- Внешние интеграции (MCP stdio / HTTP) ---
[mcp_servers.docs_server]
command = "python"
args = ["/usr/local/bin/mcp_docs_provider.py", "--db", "/data/docs.db"]

# --- Жизненный цикл (Hooks) ---
[hooks]
PreToolUse = ["python /usr/local/bin/pre_tool_validator.py"]

# --- Альтернативные профили ---
[profiles.audit]
sandbox_mode = "read-only"
approval_policy = "always"
web_search = false
```

## 3. Полный реестр канонических параметров

| Ключ | Тип | Значение по умолчанию | Допустимые значения / Ограничения | Назначение и поведение рантайма |
| :--- | :--- | :--- | :--- | :--- |
| `model` | `string` | `"gpt-5"` | Имя доступной модели | Идентификатор целевой языковой модели для сессии. |
| `approval_policy` | `string` | `"untrusted"` | `"untrusted"`, `"always"`, `"never"` | Политика подтверждений: запрашивать пользователя только на ненадёжных операциях (`untrusted`), на каждом действии (`always`) или отклонять интерактивные запросы (`never`). |
| `sandbox_mode` | `string` | `"workspace-write"` | `"read-only"`, `"workspace-write"`, `"danger-full-access"` | Режим изоляции ОС: строгое чтение, запись только в рабочей директории или полный доступ без ограничений песочницы. |
| `web_search` | `boolean` | `false` | `true`, `false` | Разрешение или запрет агенту обращаться к поисковой сети. При `false` сетевые запросы поиска не генерируются. |
| `system_prompt` | `string` | `""` | Строка текста | Базовый системный промпт, задающий глобальную идентичность и правила агента. |
| `instructions` | `string` | `""` | Строка текста | Пользовательские проектные инструкции (наследуются или дополняют системный промпт). |
| `max_context_tokens` | `integer` | Рантайм-зависимо | `minimum: 1000` | Максимальный лимит токенов контекстного окна, после которого срабатывает архивация и компактизация. |
| `timeout_seconds` | `integer` | `300` | `minimum: 1` | Таймаут ожидания ответа модели или выполнения шага агента в секундах. |
| `temperature` | `number` | `0.2` | `0.0` .. `2.0` | Температура генерации (0.0 — максимальная детерминированность, выше — креативность). |
| `top_p` | `number` | `1.0` | `0.0` .. `1.0` | Параметр nucleus sampling для фильтрации вероятностного распределения токенов. |
| `stream` | `boolean` | `true` | `true`, `false` | Потоковая отдача ответов токен за токеном (`true`) или ожидание полного блока ответа (`false`). |
| `log_level` | `string` | `"info"` | `"trace"`, `"debug"`, `"info"`, `"warn"`, `"error"` | Детализация логирования внутренних событий Codex в stderr и лог-файлы. |
| `allowed_tools` | `array[string]` | `[]` (все) | Список имён инструментов | Белый список допустимых инструментов. Если список не пуст, любые другие инструменты отключаются. |
| `blocked_tools` | `array[string]` | `[]` | Список имён инструментов | Чёрный список инструментов. Указанные инструменты безусловно блокируются рантаймом. |
| `environment_variables` | `table` | `{}` | Таблица пар `KEY = "VALUE"` | Переменные среды, передаваемые при исполнении команд через инструмент запуска процессов. |
| `mcp_servers` | `table` | `{}` | Таблица определений серверов | Конфигурация локальных серверов по протоколу Model Context Protocol (stdio или SSE). |
| `hooks` | `table` | `{}` | Таблица списков команд | Конфигурация хуков жизненного цикла (например, `PreToolUse`, `PostToolUse`). |
| `profiles` | `table` | `{}` | Вложенные конфигурации | Именованные наборы параметров, активируемые через флаг `--profile <NAME>`. |

## 4. Специфика таблиц и вложенных структур

### 4.1. Секция `[mcp_servers.<name>]`
Подключение локальных MCP-серверов по каналу stdio:
```toml
[mcp_servers.local_analyst]
command = "python"
args = ["/opt/mcp/analyst.py", "--data-dir", "/workspace/data"]
```
- Секция именуется `mcp_servers`, а не `mcp.servers`.
- Поля `command` и `args` обязательны для stdio-транспорта.
- Процесс сервера общается строго через потоки stdin/stdout в формате JSON-RPC 2.0.

### 4.2. Секция `[hooks]`
Перехват действий агента до их совершения:
```toml
[hooks]
PreToolUse = ["python /opt/codex/security_check.py"]
```
- Скрипт валидатора получает метаданные вызываемого инструмента в stdin в формате JSON.
- Код возврата `0` разрешает запуск; ненулевой код возврата блокирует вызов инструмента с сообщением об ошибке.

### 4.3. Секция `[environment_variables]`
Безопасная передача переменных окружения:
```toml
[environment_variables]
CI = "true"
GIT_AUTHOR_NAME = "Codex Automation"
```
- Переменные изолируются и не влияют на глобальное окружение родительской оболочки.
- Запрещено сохранять здесь секретные ключи API в открытом виде.

## 5. Валидация и диагностика конфигурации

1. **Строгая проверка при запуске**:
   ```bash
   codex --strict-config
   ```
   При обнаружении неизвестного ключа или невалидного типа запуск прерывается с кодом `1`.

2. **Инспекция эффективных значений (Debug Config)**:
   В интерактивном TUI введите:
   ```text
   /debug-config
   ```
   Команда выводит итоговые значения всех 18 ключей с указанием источника каждого значения (CLI, Profile, Project, Global, Default).
