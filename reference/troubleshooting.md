# Справочник по диагностике и устранению неполадок (Troubleshooting)

Целевая версия — **Codex CLI 0.160.0**. Данный справочник содержит быстрый реестр диагностических команд, кодов возврата и типовых ошибок при работе с CLI, конфигурацией, песочницей и MCP-серверами.

Для подробного изучения методологии диагностики см. практический урок [Диагностика, обновление и границы покрытия](../10-capstone/troubleshooting.md).

---

## 1. Экспресс-команды диагностики

```bash
# Проверка версии и путей исполняемого файла
codex --version
which codex

# Проверка конфигурации на соответствие строгой схеме
codex --strict-config

# Инспекция эффективных значений конфигурации (в интерактивном режиме)
# Введите в терминале Codex:
/debug-config

# Проверка состояния фоновых процессов и подключений
/status

# Сбор обезличенного отчёта для обращения в поддержку (без секретов!)
codex exec --sandbox read-only "Собери информацию об окружении ОС и версии Python"
```

## 2. Коды завершения (Exit Codes)

| Код | Символическое имя | Описание ситуации | Типичное решение |
| :--- | :--- | :--- | :--- |
| `0` | `SUCCESS` | Команда или ход выполнены успешно. | — |
| `1` | `GENERAL_ERROR` | Ошибка исполнения скрипта или модели. | Проверьте stderr и логи `~/.codex/logs`. |
| `2` | `USAGE_ERROR` | Неверные параметры CLI или конфликт флагов. | Выполните `codex --help` и проверьте флаги. |
| `13` | `CONFIG_INVALID` | Ошибка парсинга TOML или невалидный ключ при `--strict-config`. | Сверьтесь с [reference/config.md](config.md). |
| `43` | `SANDBOX_VIOLATION` | Попытка записи за пределами песочницы (`read-only` или выход за workspace). | Измените `--sandbox` или скорректируйте пути. |
| `69` | `SERVICE_UNAVAILABLE` | Сбой соединения с провайдером модели или таймаут сети. | Проверьте сетевое подключение и статус API. |
| `77` | `PERMISSION_DENIED` | Пользователь отклонил интерактивный запрос действия (Approval Denied). | Убедитесь в безопасности действия или согласуйте операцию. |

## 3. Матрица типовых неполадок и решений

### 3.1. Песочница и файловая система

| Симптом / Сообщение | Первопричина | Пошаговое устранение |
| :--- | :--- | :--- |
| `PermissionDenied (os error 13)` / `EPERM` | Запуск с `--sandbox read-only` при попытке модификации файла. | Если запись необходима, запустите с `--sandbox workspace-write`. |
| `PathOutsideWorkspaceError` | Попытка обратиться к `../` или абсолютным путям вне рабочей папки. | Используйте `--add-dir <DIR>` для явного добавления каталога в разрешённую зону. |
| `approval_policy = "never"` прерывает операцию | В неинтерактивном режиме политика `never` отклоняет все небезопасные действия. | Предоставьте явные правила в `.rules` (ALLOW) или запускайте в интерактивном TUI. |

### 3.2. Конфигурация и профили

| Симптом / Сообщение | Первопричина | Пошаговое устранение |
| :--- | :--- | :--- |
| `Unknown configuration key: foo` | Использование устаревшего или вымышленного параметра. | Сверьтесь с 18 каноническими ключами в [reference/config.md](config.md). |
| Профиль не применяется | Имя файла профиля не соответствует соглашению `NAME.config.toml`. | Разместите файл в `~/.codex/NAME.config.toml` и вызовите `codex --profile NAME`. |
| Конфликт приоритетов | Флаг командной строки переопределил значение из файла проекта. | Помните: CLI `-c` имеет высший приоритет над файлами проекта и глобальными настройками. |

### 3.3. Внешние интеграции (MCP и stdio)

| Симптом / Сообщение | Первопричина | Пошаговое устранение |
| :--- | :--- | :--- |
| `JSONRPC parse error: unexpected token` | Логи или отладочный вывод сервера пишутся в `stdout` вместо `stderr`. | Перенаправьте все отладочные сообщения в `sys.stderr`. В `stdout` допускаются только JSON-RPC строки. |
| Сервер MCP не отвечает (Timeout) | Блокирующий ввод или отсутствие сброса буфера (`flush`). | Добавьте `sys.stdout.flush()` после каждого отправленного JSON-сообщения. |
| `Server exit with code 127` | Не найден бинарник команды MCP-сервера в `$PATH`. | Укажите полный абсолютный путь к интерпретатору и файлу сервера в `args`. |

## 4. Безопасность при передаче отчётов об ошибках

При публикации логов или обращении за помощью:
1. **Никогда не копируйте токены и ключи API**: проверьте переменные окружения и `~/.codex/auth.json`.
2. **Анонимизируйте пути**: заменяйте реальные имена пользователей (`/Users/myname/...`) на плейсхолдеры (`/home/user/...`).
3. **Удаляйте коммерческий код из промптов**: при создании минимального воспроизводимого примера (MRE) используйте синтетические данные.
