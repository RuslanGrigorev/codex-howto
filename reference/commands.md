# Командная строка Codex CLI

Целевая версия — **0.160.0**. Команды здесь относятся к исполняемому файлу `codex`. Инструмент `openai` для работы с API — другой продукт. Справочник написан для локального чтения и не утверждает, что каждый сценарий уже прогнан на вашей ОС.

## Запуск и безопасные параметры

```bash
codex --version
codex --help
codex --sandbox read-only --ask-for-approval untrusted
codex --sandbox workspace-write --ask-for-approval untrusted
codex exec --json --sandbox read-only "Объясни проект, не изменяя файлы"
```

| Параметр | Назначение |
| --- | --- |
| `--cd`, `-C` | Рабочий каталог |
| `--add-dir` | Явная дополнительная область записи; не выдавайте лишнее |
| `--model`, `-m` | Выбранное доступное имя модели |
| `--config`, `-c` | Разовое переопределение `key=value` в синтаксисе TOML |
| `--profile`, `-p` | Дополнительный профиль; в актуальной документации это файл `NAME.config.toml` в CODEX_HOME |
| `--sandbox` | `read-only`, `workspace-write` или опасный `danger-full-access` |
| `--ask-for-approval`, `-a` | `untrusted`, `always` или `never`; `never` в неинтерактивном режиме отклоняет запросы |
| `--strict-config` | Ошибка на неподдерживаемой конфигурации |
| `--image`, `-i` | Существующее изображение в запросе |
| `--search` | Веб-поиск; не обязательный для курса сетевой сценарий |
| `--oss`, `--local-provider` | Подготовленный локальный провайдер, `ollama` или `lmstudio` |
| `--enable`, `--disable` | Явное управление именованными feature-флагами |
| `--no-alt-screen` | Представление без alternate screen |
| `--remote` | Подключение к поддерживаемой удалённой среде |
| `--remote-auth-token-env` | Имя переменной для авторизации удалённого соединения; не значение токена |

`--dangerously-bypass-approvals-and-sandbox`/`--yolo` и обход доверия hooks **не используются** в обязательной практике. Их наличие в справке не делает запуск безопасным. Не отключайте защиту ради зелёного теста.

## Подкоманды

| Команда | Для чего |
| --- | --- |
| `codex login`, `codex logout` | Вход, статус через `login status`, выход |
| `codex resume`, `codex fork` | Продолжение и ветвление беседы |
| `codex archive`, `codex unarchive`, `codex delete` | Управление сохранёнными беседами |
| `codex exec` | Неинтерактивное выполнение |
| `codex review` | Ревью через CLI |
| `codex mcp` | Подключения MCP; начните с `--help`, `list` |
| `codex mcp-server` | *Удалена / Историческая:* команда удалена из официального CLI; интеграции переведены на `codex app-server` |
| `codex app-server` | Протокол для собственного приложения-клиента (заменяет устаревший mcp-server) |
| `codex features` | Сведения о возможностях и флагах |
| `codex execpolicy` | Работа с политиками команд |
| `codex cloud` | Сетевые облачные задачи, требующие отдельного доступа |
| `codex completion` | Поддерживаемое завершение ввода в оболочке |
| `codex sandbox` | Диагностика песочницы на поддерживаемой ОС |
| `codex debug` | Диагностика; изучите локальную справку перед применением |
| `codex apply` | Применение доступного результата изменения; сначала проверьте diff |

Поддержка удалённого режима ограничена определёнными подкомандами; не добавляйте `--remote` к любому примеру автоматически. Для всех аргументов подкоманды используйте `codex ИМЯ --help`. Этот учебный список не заменяет построчную инвентаризацию всего CLI для заявления о 100% покрытии.

## exec: события и результат

`--json` выдаёт JSONL события, `--output-schema FILE` задаёт итоговую структуру, `--output-last-message FILE`/`-o FILE` сохраняет итог. `--ephemeral` не сохраняет обычную локальную сессию; это не обещание удаления данных у провайдера. `--skip-git-repo-check` применяйте только к заведомо безопасной учебной папке без Git.

`--color` управляет цветом. `--ignore-user-config` и `--ignore-rules` меняют загрузку настроек/правил и требуют отдельной оценки; они не должны молча присутствовать в учебных командах. Устаревающие псевдонимы не являются основой новых уроков. В частности, вместо `--full-auto` используйте явно выбранные разрешения и песочницу.

[Slash-команды](slash-commands.md) вводятся в интерактивном чате, а не в оболочке. [Урок JSONL](../08-automation/non-interactive.md) проверяет код процесса, ошибки и терминальное событие; [урок /goal](../02-workflow/plan-goal.md) — измеримую цель и управление ею.

## Диагностика и сопровождение установки

`codex doctor --help` показывает доступную диагностику. `codex update --help` относится к поддерживаемому механизму самообновления; не запускайте обновление во время контрольного прогона курса. `codex plugin --help` и `codex plugin marketplace --help` помогают проверить интерфейс работы с плагинами до установки. `codex remote-control --help` относится к удалённому управлению и требует отдельного анализа авторизации и доступа.

Эти команды описаны в текущем официальном справочнике. Их доступность нужно сверить с `codex --help` установленной версии: наличие страницы в онлайн-документации не гарантирует наличие команды в старом бинарном файле. В курсе не запускаются автоматическая установка, публикация или удалённое открытие доступа.
