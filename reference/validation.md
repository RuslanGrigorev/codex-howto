# Как проверять курс и результаты

## Принцип

PASS относится к конкретной проверке. Сто процентов согласованных требований означает, что каждое обязательное условие проверено; это не математическая гарантия безошибочности модели. Требования выпуска находятся в `validation.json`. Исходные 63 сценария OpenSpec сохранены с исходным методом приёмки для индивидуальной сверки, а не автоматически приравнены к агрегированному зелёному тесту.

## Локальный профиль

```bash
python scripts/verify.py --profile offline --report .learning/reports/offline.json
```

Он запускает проверку каталога, всех эталонов и отрицательных вариантов упражнений, ограниченного контракта конфигураций, сигнатур исходников, unit/regression-тестов, сборки и настоящего браузера. Playwright/Chromium подготавливаются заранее; при отсутствии браузера этап блокируется. Браузер запускается без внешней сети и открывает file://. Урокам не нужны сторонние шрифты или CDN.

## Реальный Codex

```bash
python scripts/verify.py --profile live --report .learning/reports/live.json
```

Без Codex будет BLOCKED. Для осознанного вызова модели нужен отдельный подготовленный CODEX_HOME, выбранная модель и явный флаг согласия. Пример ниже содержит места подстановки, не секреты:

```text
python scripts/verify.py --profile live --allow-model-call --model YOUR_AVAILABLE_MODEL --provider openai --codex-home .learning/codex-home
```

Варианты локального провайдера — `ollama` и `lmstudio`. Подготовка модели и вход не выполняются скриптом. Запрос может тарифицироваться. Автоматический live-профиль проверяет только CLI/exec; он **не выдаёт** PASS для наставника, goal, MCP, hooks и субагентов без отдельного протокола.

Для каждого LIVE-сценария сохраните версию CLI, модель, провайдера, ОС, команды, ожидаемое и фактическое поведение. Для `/goal` проверяются все операции управления и независимый результат задачи. Для разрешений и hooks нужны положительный и отрицательный случаи. Просмотр текста конфигурации не заменяет нативную загрузку.

## Прогресс ученика

Чтение, quiz, локальное exercise и codex_run хранятся отдельно. Браузер объединяет импортируемые поля, а не стирает остальные результаты. Изменение revision помечает старую работу для повторной проверки.

После реального самостоятельного опыта можно записать **самоотчёт**:

```text
python scripts/progress.py --record-codex-run workflow.plan-goal --evidence .learning/my-goal-notes.txt
```

Создайте файл заметок заранее, без секретов. Эта команда не является выпускным валидатором: она сохраняет локальную отметку и хеш указанного свидетельства. Импортируйте .learning/progress.json в браузер. Самоотчёт нельзя выдавать за независимую сертификацию.

## Пакет и допуск к релизу

```bash
python scripts/package_course.py --site .learning/site --output .learning/dist/codex-course-candidate.zip
python scripts/verify.py --profile release --evidence-dir .learning/evidence/release --artifact .learning/dist/codex-course-candidate.zip
```

Папка evidence-dir содержит только отчёты JSON по схеме verify.py. Файлы доказательств должны находиться в `.learning/evidence`, иметь актуальные SHA-256 и относительные пути. Каждый обязательный scenario_id встречается ровно один раз. Ручной отчёт включает reviewer и notes каждого случая; live-отчёт — environment с codex/model/provider. Проверка артефакта дополнительно требует artifact_sha256.

Нет отчёта, нет файла свидетельства, неверный хеш, другой код кандидата, дубль ID, неподтверждённая модель, SKIP/BLOCKED/NOT_RUN или FAIL — выпуск отклонён. Не исправляйте отчёт заменой статуса. Повторно выполните проверку после исправления кода. Отчёты старого кандидата не относятся к новому.

Хеши обеспечивают целостность и привязку, а не подлинность автора ручной записи. Редакционную полноту документации, чистоту настоящей истории Git и лицензии нельзя доказать одним синтетическим unit-тестом. До их проверки кандидат не объявляется публичным проверенным релизом.

## Исходные сценарии

Подробные формулировки находятся в `openspec/changes/adapt-course-for-codex-cli/specs` и traceability.json. Исторические указания на ещё не существующие отдельные test-функции — план, не свидетельство выполнения. Новый change `harden-codex-course` описывает применённую доработку.

## Ограничения среды браузерной проверки

Если политика управляемого Chromium запрещает `file://`, профиль возвращает BLOCKED. Настройки безопасности браузера не отключаются. Дополнительный `browser_check.py --mode embedded` проверяет только рендеринг и действия над локально переданным DOM. Он не доказывает file-навигацию и постоянное browser-хранилище и не заменяет обязательный CHK-BROWSER.
