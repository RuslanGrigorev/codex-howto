# Нативные hooks: вход, решение и доверие

## Чему вы научитесь

Разобрать нативный hook, его вход и решение, не приписывая ему свойства системной песочницы.

## Что нужно перед началом

Сначала пройдите: [Начало: что изучаем и как проверяем результат](../01-start/overview.md). Учебные файлы входят в поставку. Установленные программы и доступ к модели требуются только для соответствующей практики.

Hooks запускают ваш код на определённых событиях Codex. В примере используется реальное событие **`PreToolUse`**, а не выдуманные `pre-command` или `pre-commit` как названия событий клиента.

Пример `examples/hooks/hooks.json` настраивает обработчик, а `examples/extension-hook/solution/hook_runner.py` читает JSON из stdin. Для разрешённого события он возвращает пустой объект. Отказ задаётся через `hookSpecificOutput` с `hookEventName`, `permissionDecision` и причиной. Неподдерживаемый `continue: false` не следует считать эквивалентным отказом `PreToolUse`.

## Практика

В подготовленную рабочую папку скопируйте `hooks.json`, оставьте рядом `hook_runner.py` и изучите доверие к hooks в установленном Codex. Сначала проверьте локальный протокол: разрешён `git status --short`, запрещён произвольный shell-ввод. Только после просмотра кода установите пример в отдельный учебный профиль.

Реальный тест должен подтвердить, что разрешённое действие выполнилось, запрещённое — не выполнилось, а изменение hook-определения не осталось незамеченным. Удалите учебную настройку после опыта.

События отличаются фазой и допустимыми решениями: `PostToolUse` не является способом отменить уже выполненное действие. Hooks не заменяют OS-песочницу и не гарантируют перехват любого hosted-инструмента. Настройка курса не активирует hook в вашем рабочем профиле автоматически.

## Проверяемое упражнение

Выполняйте команды из корня репозитория или из `source` готового офлайн-пакета. Подготовка не перезаписывает существующую работу.

```bash
python scripts/verify.py --prepare extension-hook
# Измените файлы в .learning/workspaces/extension-hook
python scripts/verify.py --exercise extension-hook --workspace .learning/workspaces/extension-hook
```

Проверка запускает независимый `examples/extension-hook/test.py`, а не тест из рабочей папки. Эталон находится в `examples/extension-hook/solution`; открывайте его после собственной попытки. Тестируемый Python-код исполняется на вашей машине: запускайте только доверенные учебные файлы. Ограничение пути не является OS-песочницей.

## Что считается выполнением в Codex

Без модели доступны весь текст, вопросы, исходники и локальные тесты. Они не подтверждают работу CLI. Для практики сохраните версию `codex --version`, модель, провайдера и обезличенный результат реального запуска. Отметку можно внести через `scripts/progress.py` после проверки, согласно [правилам валидации](../reference/validation.md). Самоотчёт ученика не заменяет выпускные доказательства проекта.
