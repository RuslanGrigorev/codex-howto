# Урок 9: Хуки, субагенты и расширения в Codex CLI

## Цель урока
Понять архитектуру расширений Codex CLI: хуки жизненного цикла (hooks), субагенты и плагины. Научиться настраивать локальные хуки для автоматической проверки кода и гарантировать безопасность среды выполнения.

## Предпосылки
- Пройдены уроки по безопасности, AGENTS.md, навыкам и автоматизации.
- Понимание жизненного цикла выполнения команд в CLI.

## Архитектура расширений Codex

Codex CLI поддерживает модульные механизмы расширения поведения агента:

```text
┌─────────────────────────────────────────────────────────────┐
│                         Codex CLI                           │
├─────────────────┬─────────────────────────┬─────────────────┤
│  Skills (Навыки)│      Hooks (Хуки)       │   Subagents     │
│  Инструкции и   │  Действия до/после      │   Параллельные  │
│  методологии    │  выполнения инструментов│   субагенты     │
└─────────────────┴─────────────────────────┴─────────────────┘
```

### Жизненный цикл хуков (Hooks)

Хуки позволяют выполнять детерминированные локальные проверки в ключевые моменты работы:
- `pre-command`: вызывается перед запуском системной команды или скрипта. Позволяет заблокировать деструктивные вызовы.
- `post-command`: вызывается после выполнения команды для анализа результатов и форматирования.
- `pre-commit`: вызывается перед созданием коммита для проверки стиля и тестов.

### Конфигурация хуков в проекте

Хуки определяются в файле `.codex/hooks.json` или в секции конфигурации:

```json
{
  "hooks": [
    {
      "name": "check-syntax",
      "event": "pre-commit",
      "command": ["python", "-m", "py_compile", "src/main.py"],
      "block_on_failure": true
    }
  ]
}
```

## Безопасность расширений

> [!CAUTION]
> **Принципы изоляции расширений:**
> 1. Хуки должны быть строго изолированы внутри репозитория. Запрещено выполнение скриптов из внешних недоверенных путей.
> 2. При сбое критического хука (`block_on_failure: true`) основное действие агента обязано быть отменено.
> 3. Плагины и расширения не должны иметь скрытого доступа к глобальным файлам пользователя вне текущего проекта.

## Практическое упражнение: `extension-hook`

В этом упражнении вы реализуете модуль выполнения хуков `HookRunner`, который:
1. Валидирует события хука (допустимы: `pre-command`, `post-command`, `pre-commit`).
2. Блокирует опасные инъекции команд (попытки запуска сетевых скриптов, удаление системных каталогов).
3. Корректно завершает работу с ошибкой при сбое проверки хука.

### Запуск проверки упражнения

```bash
python scripts/verify.py --exercise extension-hook
```
