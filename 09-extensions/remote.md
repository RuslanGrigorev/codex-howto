# Удалённый Codex и облачные действия из CLI

## Чему вы научитесь

Различать локальную сессию, удалённое подключение и облачный запуск.

## Что нужно перед началом

Сначала пройдите: [Начало: что изучаем и как проверяем результат](../01-start/overview.md). Учебные файлы входят в поставку. Установленные программы и доступ к модели требуются только для соответствующей практики.

Удалённая среда и локальная папка — разные границы доступа. `--remote` применяется только к поддерживаемым командам клиента; наличие флага не означает, что любой подкоманде можно передать удалённый адрес. Команды облачных задач изучайте через `codex cloud --help`.

```bash
codex --help
codex cloud --help
codex app-server --help
```

Для соединений различайте защищённый удалённый канал и локальный loopback. Токен соединения не помещают в строку, которую сохранят в историю или публикуемый лог. Не выдавайте удалённому сервису доступ ко всем рабочим файлам ради учебного примера.

## Практика

Без сети составьте схему: где выполняется команда, где находятся файлы, кому передаются данные и как проверяется результат. При наличии подготовленной удалённой среды выполните только чтение учебного файла и сохраните сведения о разрешениях и транспортной защите. Недоступность сервиса должна дать явную ошибку, а не «успешную отправку» без проверки результата.

## Что считается выполнением в Codex

Без модели доступны весь текст, вопросы, исходники и локальные тесты. Они не подтверждают работу CLI. Для практики сохраните версию `codex --version`, модель, провайдера и обезличенный результат реального запуска. Отметку можно внести через `scripts/progress.py` после проверки, согласно [правилам валидации](../reference/validation.md). Самоотчёт ученика не заменяет выпускные доказательства проекта.
