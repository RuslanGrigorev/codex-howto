# Удалённый Codex и облачные действия из CLI

## Чему вы научитесь

- Различать режимы выполнения Codex CLI: локальный процесс, удаленный запуск (`--remote`) и облачные задачи (`codex cloud`).
- Понимать топологию передачи контекста и исходного кода при работе с удаленными средами.
- Использовать параметры аутентификации и защищенные каналы (TLS/SSH) без утечки токенов.
- Настраивать автономный офлайн-сценарий как приоритетный контур разработки.

## Что нужно перед началом

- Понимание локальной архитектуры Codex CLI и концепции `app-server`.
- Установленный Codex CLI 0.160.0.
- Знакомство с принципами сетевой безопасности из урока [Сеть, веб-поиск и передача контекста](../03-safety/network.md).

## Схема процесса

Топология режимов выполнения задач в Codex CLI:

```
┌────────────────────────────────────────────────────────┐
│             Режим 1: Локальное исполнение              │
│  [CLI на машине dev] ──> [Локальные файлы] ──> [LLM]   │
└────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────┐
│             Режим 2: Удаленный клиент (--remote)       │
│  [Локальный TUI] ──> mTLS/SSH ──> [Удаленный CLI]      │
│                                           │            │
│                                           ▼            │
│                                  [Файлы на сервере]    │
└────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────┐
│             Режим 3: Облачные задачи (codex cloud)     │
│  [CLI отправляет задачу] ──> [Изолированная VM в cloud]│
│                                           │            │
│                                           ▼            │
│                                   [Сборка PR в облаке] │
└────────────────────────────────────────────────────────┘
```

## Команды и параметры

Команды управления удаленными и облачными операциями:

```bash
# Просмотр параметров команд работы с облачными сценариями
codex cloud --help
codex app-server --help

# Проверка статуса облачных задач
codex cloud status

# Запуск задачи на удаленном сервере с явным указанием хоста
codex --remote https://codex-runner.internal.corp --token $RUNNER_TOKEN "Выполни тесты"
```

Конфигурация удаленного подключения в `.codex/config.toml`:

```toml
[remote]
endpoint = "https://codex-runner.internal.corp:8443"
tls_verify = true
timeout_seconds = 60
```

## Разбор примера

Рассмотрим выполнение тяжелой сборки проекта на выделенном удаленном сервере:

1. Разработчик инициирует удаленный запуск с локальной машины:
   ```bash
   codex cloud run "Собери Docker-образ и прогони нагрузочные тесты"
   ```
2. Codex CLI упаковывает контекст изменений Git и передает его по защищенному каналу TLS в изолированную виртуальную машину провайдера.
3. В облачной VM запускается процесс в контролируемой песочнице.
4. Потоковые логи возвращаются в локальный терминал оператора в реальном времени.
5. Локальный диск разработчика не нагружается тяжелой компиляцией.

## Ограничения и безопасность

- Флаг `--remote` поддерживается только определенным набором команд: не пытайтесь передавать его подкомандам, рассчитанным исключительно на локальную работу.
- Никогда не передавайте токены авторизации в открытом виде в аргументах командной строки (`--token secret`): используйте защищенные переменные окружения.
- При работе с закрытыми корпоративными данными убедитесь, что удаленный сервер соответствует стандартам безопасности компании.

## Типовые ошибки

1. **Утечка токенов в историю оболочки**: запуск команд с открытыми паролями и токенами, сохраняющимися в `.bash_history`.
2. **Путаница локального и удаленного путей**: передача локального абсолютного пути (`C:\repo\...`) на удаленный сервер под управлением Linux.
3. **Игнорирование статуса сети**: ожидание завершения облачной задачи без проверки состояния соединения.

## Практика

1. Изучите доступные параметры подкоманд `codex cloud` и `codex app-server`.
2. Составьте схему потоков данных для вашей команды: где хранятся файлы, где исполняется бинарник CLI и куда отправляются промпты.
3. Смоделируйте поведение клиента при потере связи с удаленным сервером и убедитесь в наличии корректного таймаута.
