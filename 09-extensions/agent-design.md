# Роли субагентов и передача результатов

## Чему вы научитесь

Разделять исследование, исполнение и ревью без конфликтующих изменений.

## Что нужно перед началом

Урок о субагентах и учебная задача с несколькими независимыми аспектами.

## Как это работает

Субагент полезен, когда его задача ограничена и результат можно проверить. «Сделай всё» для нескольких исполнителей создаёт конкуренцию, а не разделение работы.

Для исследователя и ревьюера разумно начинать с чтения. Исполнитель получает конкретную область файлов. Главный агент должен сопоставить результаты и проверить противоречия, а не просто объединить уверенные ответы.

Параллельность не гарантирует качество или экономию ресурсов. Для небольшой функции один агент часто проще. Роли вводят ради ясной ответственности, а не ради количества одновременно открытых задач.

## Разобранный пример

Откройте [пример ревьюера](../examples/subagents/reviewer.toml). Его задача — исследовать ограниченное изменение без записи.

Пример задания роли:

```text
Проверь только граничные случаи расчёта скидки.
Не изменяй файлы. Для каждой находки приведи вход,
ожидаемое поведение и способ проверки. Отделяй предположения.
```

Это задание для роли, а не новый API вызова субагента.

## Самостоятельная практика

Разделите небольшую задачу на исследование условий и проверку тестов. Назначьте непересекающиеся результаты. Через доступный интерфейс Codex проверьте, что роли действительно запущены и завершены.

Сопоставьте два вывода. Если они расходятся, выполните независимую проверку спорного случая, а не выбирайте более уверенный ответ.

## Ожидаемый результат

У каждой роли есть ограниченная область, выходной результат и проверка. Файлы не меняются конкурентно без координации.

## Разбор решения

<details>
<summary>Показать после самостоятельной попытки</summary>

Исследователь перечисляет условия функции, ревьюер проверяет конкретные случаи. Главный агент сверяет их с независимым тестом. При несовпадении утверждений решение определяется воспроизводимым примером, а не числом голосов агентов.

</details>

## Типовые ошибки

Давать всем одинаковое неограниченное задание; разрешать всем менять один файл; принимать консенсус моделей за тест.
