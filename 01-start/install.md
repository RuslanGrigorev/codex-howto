# Установка, обновление и платформы

## Чему вы научитесь

Научитесь выбирать подходящий метод установки Codex CLI под целевую операционную систему (Linux, macOS, Windows), фиксировать конкретную версию инструмента (0.160.0), верифицировать контрольные суммы исполняемых файлов, управлять переменными среды `PATH` и организовывать изолированное окружение без изменения системных конфигураций.

## Что нужно перед началом

1. Изучите материал урока [Подготовка среды: терминал, Python и Git](environment.md).
2. Подготовьте права локального пользователя (административные права требуются только при системной установке, но рекомендуется пользовательская установка).
3. Доступ в интернет требуется только на этапе предварительной загрузки дистрибутива до перехода в автономный режим.

## Схема процесса

Процесс подготовки и верификации установки Codex CLI состоит из четырёх этапов:

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. Выбор платформы и дистрибутива                           │
│    - Linux (x86_64, aarch64)                                │
│    - macOS (Apple Silicon arm64, Intel x86_64)              │
│    - Windows (x86_64 native или WSL2)                       │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│ 2. Установка фиксированной версии                           │
│    - npm: npm install -g @openai/codex@0.160.0              │
│    - или автономный бинарник: ~/.codex/bin/codex            │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│ 3. Настройка переменной PATH                                │
│    - Добавление каталога бинарника в профиль пользователя   │
│    - Проверка отсутствия дублирующихся устаревших версий    │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│ 4. Верификация окружения                                    │
│    - codex --version (строго 0.160.0)                       │
│    - codex --help (проверка полноты дерева подкоманд)       │
└─────────────────────────────────────────────────────────────┘
```

## Команды и параметры

Установка фиксированной версии через менеджер пакетов npm (рекомендуемый воспроизводимый способ при наличии Node.js):

```bash
# Установка строго зафиксированной версии 0.160.0
npm install -g @openai/codex@0.160.0

# Проверка установленной версии
codex --version

# Проверка доступности основных флагов
codex --help

# Удаление пакета при необходимости чистой переустановки
npm uninstall -g @openai/codex
```

Альтернативная автономная установка бинарного файла:
```bash
# Размещение бинарника в каталоге пользователя (Linux/macOS)
mkdir -p ~/.codex/bin
cp codex ~/.codex/bin/
chmod +x ~/.codex/bin/codex
export PATH="$HOME/.codex/bin:$PATH"
```

## Разбор примера

Рассмотрим опасность использования плавающего тега `@latest`:

Если установить CLI командой:
```bash
npm install -g @openai/codex@latest
```
То через некоторое время upstream выпустит версию 0.170.0 или 1.0.0, в которой могут измениться синтаксис конфигурации, удалиться подкоманды или модифицироваться схема хуков. В результате учебные упражнения и проверочные скрипты курса перестанут воспроизводиться.

Именно поэтому в курсе закреплён строгий baseline: **0.160.0** (`rust-v0.160.0`). Все примеры, команды и тесты гарантированно согласованы с этой версией.

## Ограничения и безопасность

1. **Не запускайте установку от root/Administrator**: глобальная установка npm без необходимости повышения привилегий настраивается через пользовательский каталог `npm config set prefix ~/.npm-global`. Не используйте `sudo npm install -g`.
2. **Не смешивайте среды Windows и WSL**: бинарный файл, скомпилированный для Linux ELF, не запустится напрямую в Windows cmd/powershell, и наоборот. Определитесь с одной средой на весь курс.
3. **Запрет автоматической установки**: проект курса принципиально не скачивает и не устанавливает бинарники самостоятельно. Ученик контролирует установку инструментов осознанно.

## Ошибки и диагностика

| Симптом | Причина | Способ диагностики и решения |
|---|---|---|
| `codex: command not found` после npm install | Каталог глобальных бинарников npm не включён в переменную `PATH`. | Выполните `npm bin -g` и добавьте выведенный путь в свой `.bashrc`, `.zshrc` или переменные среды Windows. |
| `codex --version` выводит старую версию (например, 0.140.0) | В системе присутствует другая копия бинарника, расположенная выше в `PATH`. | Проверьте `which -a codex` (в Linux/macOS) или `where.exe codex` (в Windows) и удалите старую копию. |
| `EACCES: permission denied` при установке | Попытка записи в системный каталог `/usr/local/lib`. | Настройте локальный npm prefix: `mkdir ~/.npm-global && npm config set prefix ~/.npm-global`. |

## Практика

1. Проверьте текущую версию или зафиксируйте статус отсутствия CLI:
   ```bash
   codex --version || echo "Codex CLI пока не установлен (статус: NOT_RUN)"
   ```
2. Составьте технический паспорт вашей установки:
   ```text
   ОС: Linux / macOS / Windows
   Архитектура: x86_64 / arm64
   Способ установки: npm / standalone binary
   Версия: 0.160.0 (или NOT_RUN)
   ```
3. Проверьте, что в каталоге репозитория отсутствуют посторонние бинарные файлы, не отслеживаемые Git.

## Самопроверка

Критерии завершения:
1. Вы понимаете, почему в учебной среде запрещено использовать тег `@latest`.
2. Вы умеете проверить эффективный путь к бинарнику через `which` или `where`.
3. Зафиксирован паспорт целевой среды для выполнения практических заданий.

<details>
<summary>Контрольные вопросы для самопроверки</summary>

- **Вопрос**: Удаляет ли команда `npm uninstall -g @openai/codex` пользовательские файлы сессий и настройки в `~/.codex/`?
- **Ответ**: Нет, npm удаляет только исполняемый бинарник и пакетные файлы; профиль пользователя, история сессий и `config.toml` остаются нетронутыми.
- **Вопрос**: Какая версия является закреплённым baseline данного практикума?
- **Ответ**: Версия **0.160.0** (соответствует тегу исходного кода `rust-v0.160.0`).

</details>
