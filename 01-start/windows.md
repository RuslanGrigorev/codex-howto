# Windows, WSL и пути к учебным файлам

## Чему вы научитесь

Выбирать одну среду запуска и диагностировать различия путей, оболочек и разрешений.

## Что нужно перед началом

Этот урок нужен пользователям Windows. На другой ОС прочитайте разбор как пример платформенных ограничений.

## Как это работает

PowerShell и WSL — разные среды. У них отличаются представление путей, доступные программы и настройки. Путь `C:\Projects\course` не является Linux-путём. Путь `/mnt/c/Projects/course` имеет смысл только внутри соответствующей WSL-среды.

Фиксируйте, откуда запущены Codex, Python и Git. Не считайте отказ доступа доказательством неправильной модели: причиной может быть песочница, права файловой системы или неверный путь.

Для первых упражнений выбирайте короткий путь без пробелов. Затем отдельно проверьте путь с пробелами, обязательно заключая его в кавычки. Это помогает отличить ошибку копирования команды от реального ограничения программы.

## Разобранный пример

Проверки, применимые в выбранной оболочке:

```text
codex --version
python --version
git --version
python -c "from pathlib import Path; print(Path.cwd())"
```

Для PowerShell сведения об исполняемом файле показывает `Get-Command codex`; в Bash — `command -v codex`. Не переносите синтаксис переменных окружения между оболочками пословно.

## Самостоятельная практика

Выберите PowerShell или WSL и подготовьте упражнение `small-fix` в этой среде. Откройте созданный файл тем же редактором, которым планируете пользоваться далее. Затем запишите, как выглядит путь в терминале и в редакторе.

При отказе песочницы сохраните обезличенный текст ошибки и `/status`. Не отключайте защиту, чтобы просто добиться запуска.

## Ожидаемый результат

Все инструменты работают с одной копией упражнения; в отчёте указаны ОС, оболочка и конкретный путь без секретов.

## Разбор решения

<details>
<summary>Показать после самостоятельной попытки</summary>

Корректное решение — не универсальная команда для всех оболочек, а последовательная среда. Если выбран WSL, выполняйте всю проверку внутри него и используйте соответствующие пути. Если выбран PowerShell, сохраняйте его синтаксис кавычек и переменных. Дополнительно проверьте одно чтение файла Codex в режиме ограниченных прав.

</details>

## Типовые ошибки

Смешивать пути двух систем; исправлять ошибки кавычек расширением прав; переносить Linux-команды в PowerShell без проверки.
