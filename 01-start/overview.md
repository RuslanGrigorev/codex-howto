# Начало: что изучаем и как проверяем результат

## Чему вы научитесь

Научитесь ориентироваться в структуре и маршрутах автономного практикума по Codex CLI 0.160.0, отличать роли терминального агента `codex` от API-клиента `openai`, понимать критерии независимой проверки знаний и практики, а также выбирать между автономным офлайн-маршрутом и интерактивным обучением с наставником.

## Что нужно перед началом

1. Современный веб-браузер для чтения материалов и прохождения офлайн-интерактива.
2. Установленный Python 3.11 или новее для запуска независимых проверочных тестов.
3. Установленный Git для инспекции diff и фиксации результатов практики.
4. Доступ к терминалу вашей операционной системы (bash, zsh или PowerShell).
5. Наличие бинарника `codex` и доступ к модели опциональны: курс полностью автономен и не требует обязательного запуска CLI для теоретической части и локальных проверок.

## Схема процесса

Обучающий процесс в практикуме разделён на четыре независимых контура:

1. **Теоретический контур (Чтение)**: изучение концепций, схем архитектуры, синтаксиса команд и ограничений безопасности по зафиксированному baseline версии 0.160.0.
2. **Интерактивная проверка знаний (Квиз)**: прохождение тестовых вопросов в конце урока с получением детальных объяснений правильных и неправильных вариантов ответов.
3. **Локальная практика (Упражнения)**: выполнение пошаговых заданий в изолированных рабочих копиях (`.learning/workspaces/`) с запуском независимых тестов `test.py`.
4. **Нативная практика (Codex CLI)**: запуск реального клиента при наличии установленного CLI и модели с обязательной фиксацией версии, провайдера и журнала запуска.

Переход между контурами последователен: чтение не заменяет прохождение квиза, а правильный ответ в тесте не является доказательством выполнения практического задания.

## Команды и параметры

Базовые команды проверки окружения перед началом работы:

```bash
# Проверка версии интерпретатора Python (требуется 3.11+)
python --version

# Проверка наличия Git
git --version

# Проверка доступности Codex CLI (если установлен)
codex --version
codex --help
```

## Разбор примера

Рассмотрим принципиальное отличие `codex` от других инструментов:

1. **`codex`**: автономный терминальный coding-агент. Он самостоятельно анализирует файловую систему проекта, планирует шаги через `/plan`, редактирует файлы в песочнице и запускает проверочные тесты.
2. **`openai` (API CLI)**: утилита прямого обращения к REST API платформы OpenAI для отправки разовых промптов или генерации эмбеддингов. Она не обладает агентным циклом, контекстной памятью проекта и инструментами песочницы.

В рамках курса изучается исключительно архитектура и возможности `codex`.

## Ограничения и безопасность

1. **Изоляция учебной работы**: все практические манипуляции с кодом должны выполняться в копиях каталогов внутри `.learning/workspaces/`, подготавливаемых командой `python scripts/verify.py --prepare <exercise>`. Никогда не редактируйте эталонные файлы в каталоге `examples/`.
2. **Защита секретов**: курс запрещает передачу и хранение токенов, ключей доступа, файлов `.env` и личных логов в исходниках репозитория.
3. **Честность статусов**: если Codex CLI не установлен или модель недоступна, статус нативной совместимости остаётся `NOT_RUN`. Автономные симуляции и тесты не подтверждают работу реального бинарника.

## Ошибки и диагностика

| Ситуация / Ошибка | Причина | Способ диагностики и решения |
|---|---|---|
| `codex: command not found` | CLI не установлен в системе или путь к бинарнику не добавлен в системную переменную `PATH`. | Это нормальная ситуация для автономного маршрута. Продолжайте обучение по текстовым материалам и локальным Python-тестам. |
| Прогресс сбрасывается при закрытии браузера | Браузер блокирует сохранение `localStorage` для локальных файлов протокола `file://`. | Используйте кнопки «Экспорт прогресса» в нижней панели для сохранения файла `codex-course-progress.json`. |
| Версия Python ниже 3.11 | В системе установлен устаревший Python (например, 3.8 или 3.9). | Установите Python 3.11+ через pyenv, winget или официальный установщик python.org. |

## Практика

1. Откройте терминал и выполните диагностическую команду:
   ```bash
   python scripts/check_project.py catalog
   ```
2. Убедитесь, что каталог курса валиден и все модули на месте (статус `PASS: catalog`).
3. Откройте файл `reference/commands.md` и найдите различия между интерактивным вызовом `codex` и пакетным неинтерактивным запуском `codex exec`.

<details>
<summary>Подсказка к заданию</summary>

Интерактивный запуск `codex` открывает полноэкранный терминальный интерфейс (TUI) с поддержкой многострочного ввода, подсветки синтаксиса и запросов подтверждения. Команда `codex exec "промпт"` выполняет задачу пакетно в пакетном режиме и завершает процесс сразу после генерации ответа или выполнения лимита шагов.

</details>

## Самопроверка

Критерии завершения урока:
1. Вы проверили версию Python в своей ОС (>= 3.11).
2. Вы чётко понимаете разделение 4 контуров обучения (чтение, квиз, локальное упражнение, реальный CLI).
3. Проверка `python scripts/check_project.py catalog` завершается со статусом `PASS`.

<details>
<summary>Контрольные вопросы для самопроверки</summary>

- **Вопрос**: Доказывает ли успешное чтение всех глав курса, что Codex CLI совместим с вашей операционной системой?
- **Ответ**: Нет, чтение подтверждает только освоение теоретического материала; нативная совместимость требует отдельного протокола реального запуска.
- **Вопрос**: Что такое `$learn` в рамках данного курса?
- **Ответ**: `$learn` — это проектный навык репозитория (`.agents/skills/learn/SKILL.md`), запускающий обучающий диалог с наставником, а не встроенная команда клиента.

</details>
