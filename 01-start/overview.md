# Модуль 1: Подготовка и первый запуск Codex CLI

## Цели модуля
- Понять назначение и архитектуру Codex CLI.
- Научиться запускать интерактивный и неинтерактивный режимы.
- Изучить основные флаги запуска, политики одобрений и песочницу (sandbox).

---

## 1. Введение и установка

Codex CLI — это терминальный AI-ассистент разработчика от OpenAI, позволяющий решать задачи кодинга, рефакторинга, написания тестов и автоматизации непосредственно в рабочей директории вашего проекта.

Проверка версии в терминале:
```bash
codex --version
```
Пример вывода:
```text
codex-cli 0.160.0
```

---

## 2. Интерактивный запуск

Для перехода в интерактивный режим (TUI) достаточно выполнить команду `codex` в корне вашего проекта:
```bash
codex
```
Или передать начальный запрос (промпт):
```bash
codex "Проанализируй структуру проекта и составь краткий обзор"
```

---

## 3. Режимы песочницы (Sandbox) и безопасность

Codex CLI по умолчанию запускается с ограничениями доступа к файловой системе для предотвращения случайного повреждения файлов за пределами проекта.

Флаг `-s, --sandbox <MODE>` поддерживает режимы:
1. `read-only` — модель может только читать файлы проекта, изменения на диск не записываются.
2. `workspace-write` (рекомендуемый рабочий режим) — разрешена запись только в пределах текущего рабочего каталога.
3. `danger-full-access` — полный неограниченный доступ к файловой системе компьютера.

Пример безопасного запуска для ознакомления с кодом:
```bash
codex -s read-only "Объясни назначение основных модулей"
```

---

## 4. Политика одобрения действий (--ask-for-approval)

Флаг `-a, --ask-for-approval <POLICY>` управляет запросами подтверждений у пользователя перед выполнением команд в терминале:
- `on-request` (по умолчанию) — модель запрашивает подтверждение, если действие может изменить файлы или требует повышенного внимания.
- `never` — модель выполняет команды без ручного подтверждения (используется в изолированных CI/CD контейнерах).

---

## 5. Работа с локальными моделями (--oss)

Codex CLI поддерживает подключение локальных провайдеров (Ollama, LM Studio) через флаги:
```bash
codex --oss --local-provider ollama
```
Это позволяет использовать Codex CLI полностью автономно без отправки данных во внешние облачные сервисы.

---

## 6. Локальный справочник основных подкоманд

| Подкоманда | Назначение |
|------------|------------|
| `codex exec` (`e`) | Неинтерактивный запуск для скриптов и CI/CD |
| `codex review` | Автоматический код-ревью незакоммиченных изменений |
| `codex resume` | Возобновление предыдущей сессии диалога |
| `codex fork` | Создание ответвления от сохраненной сессии |
| `codex doctor` | Диагностика локальной установки и окружения |
| `codex mcp` | Управление подключенными MCP-серверами |
| `codex plugin` | Управление плагинами и расширениями |

---

## Практическое задание
1. Запустите в терминале команду `codex --help` и ознакомьтесь со списком флагов.
2. Запустите `codex doctor` для проверки состояния установки.
3. Перейдите ко [второму модулю](../02-workflow/small-fix.md), чтобы освоить рабочий цикл формулирования задач и проверки diff.
