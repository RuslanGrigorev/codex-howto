# Терминальный интерфейс, справка и ввод

## Чему вы научитесь

Научитесь уверенно ориентироваться в полноэкранном терминальном интерфейсе (TUI) Codex CLI 0.160.0, использовать встроенные команды с префиксом `/` (slash commands) и проектные навыки с префиксом `$`, управлять фоновыми процессами через `/ps` и `/stop`, настраивать горячие клавиши через `/keymap` и безопасно очищать экран сессии.

## Что нужно перед началом

1. Изучите основы запуска терминала из урока [Подготовка среды: терминал, Python и Git](environment.md).
2. Понимание разницы между вводом shell-команд в ОС и вводом команд внутри интерактивной сессии TUI.
3. Ознакомьтесь с [каталогом slash-команд](../reference/slash-commands.md).

## Схема процесса

Структура взаимодействия с TUI интерфейсом Codex CLI представлена на схеме:

```text
┌─────────────────────────────────────────────────────────────┐
│ Поле ввода TUI (Prompt Input Buffer)                        │
├──────────────────────────────┬──────────────────────────────┤
│ 1. Префикс "/"               │ 2. Префикс "$"               │
│ Встроенные команды клиента   │ Проектные навыки (Skills)    │
│ /status, /plan, /compact     │ $learn, $diff-review         │
├──────────────────────────────┴──────────────────────────────┤
│ 3. Обычный текст: Промпт для модели                         │
│ "Исследуй структуру проекта и найди баг в auth.py"          │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│ Окно вывода событий (Event Stream View)                     │
│ ├── Рассуждения модели (Streaming text)                     │
│ ├── Вызовы инструментов (Tool Calls: read, edit, bash)      │
│ └── Интерактивные подтверждения: [y]es / [n]o / [a]lways    │
└─────────────────────────────────────────────────────────────┘
```

## Команды и параметры

Ключевые slash-команды TUI в версии 0.160.0:

```text
/status        # Текущее использование токенов, модель, песочница и ветка Git
/model         # Переключение языковой модели внутри активной сессии
/permissions   # Просмотр и изменение режима песочницы (read-only / workspace-write)
/plan          # Включение режима пошагового планирования задачи
/compact       # Сжатие длинной истории диалога
/keymap        # Просмотр и настройка сочетаний клавиш (включая режим Vim)
/ps            # Список активных фоновых процессов и задач
/stop          # Принудительная остановка зависшего инструмента или процесса
/clear         # Очистка экрана терминала (история сессии на диске сохраняется)
/exit          # Завершение сессии и возврат в терминал ОС (также Ctrl+D)
```

Горячие клавиши по умолчанию:
- `Ctrl+C`: прерывание текущего ответа модели.
- `Ctrl+D`: выход из клиента при пустой строке ввода.
- `Shift+Enter` или `Alt+Enter`: перенос строки в многострочном вводе.
- `Tab`: автодополнение доступных команд и имен файлов.

## Разбор примера

Рассмотрим правильную реакцию на зависший внешний процесс:

1. Модель запустила длительный тест или фоновый сервер:
   ```text
   Running tool: run_command (pytest -v)
   ```
2. Если процесс не отвечает, не закрывайте окно эмулятора терминала целиком:
   - Нажмите `Ctrl+C` для отправки сигнала прерывания (SIGINT).
   - Если процесс продолжает висеть в фоне, введите команду:
     ```text
     /ps
     ```
   - Найдите идентификатор задачи (`task_1`) и остановите её:
     ```text
     /stop task_1
     ```
3. Контекст сессии сохранится, и вы сможете продолжить работу без потери истории.

## Ограничения и безопасность

1. **Несмешиваемость оболочек**: команды оболочки (`ls`, `git status`, `pytest`) нельзя вводить в чат напрямую без инструмента `run_command` или специального префикса. Текст `git diff` в строке ввода будет воспринят моделью как текстовый промпт, а не исполнен в терминале.
2. **Команда `/clear` не удаляет данные**: `/clear` очищает только экранную буферизацию TUI. Полный лог ходов по-прежнему сохраняется в файле `~/.codex/sessions/*.jsonl` на диске.
3. **Безопасность копирования `/copy`**: при использовании команды `/copy` проверяйте скопированный фрагмент перед отправкой коллегам, чтобы исключить случайное попадание внутренних путей или конфиденциальных фрагментов кода.

## Ошибки и диагностика

| Симптом | Причина | Способ диагностики и решения |
|---|---|---|
| `Unknown command: /learn` | Символ `/` используется только для встроенных команд клиента. | Навыки вызываются через префикс `$`: `$learn`. |
| Ввод команды выполняет отправку вместо переноса строки | Нажатие клавиши `Enter` отправляет сообщение. | Для многострочного промпта используйте комбинацию `Shift+Enter` или `Alt+Enter`. |
| TUI отображает повреждённые символы (псевдографику) | Терминал не настроен на поддержку UTF-8 шрифтов или не поддерживает 24-битный цвет (truecolor). | Используйте современный эмулятор терминала (Windows Terminal, Alacritty, iTerm2). |

## Практика

1. Ознакомьтесь с полным списком 62 команд в справочнике [reference/slash-commands.md](../reference/slash-commands.md).
2. Найдите в справочнике команды управления памятью (`/memories`), отладки конфигурации (`/debug-config`) и переключения моделей (`/model`).
3. Сравните назначение команд `/plan`, `/goal` и навыка `$learn`.

## Самопроверка

Критерии завершения:
1. Вы знаете назначение основных slash-команд (`/status`, `/compact`, `/ps`, `/stop`).
2. Вы чётко различаете префиксы `/` (встроенные команды) и `$` (проектные навыки).
3. Вы умеете корректно прерывать зависшие команды без аварийного закрытия терминала.

<details>
<summary>Контрольные вопросы для самопроверки</summary>

- **Вопрос**: Какая команда отобразит текущую загрузку контекстного окна модели?
- **Ответ**: Команда `/status`.
- **Вопрос**: Что произойдёт при вызове `/stop` без параметров?
- **Ответ**: Команда выведет список активных задач либо остановит текущий выполняемый инструмент.

</details>
