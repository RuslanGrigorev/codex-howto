# Версии, обновление и возврат к проверенной установке

## Чему вы научитесь

Научитесь управлять жизненным циклом версий Codex CLI, осознанно выполнять обновления и безопасный откат (rollback) к проверенному релизу 0.160.0, сохранять резервные копии профилей перед обновлением и предотвращать несовместимость схем конфигурации при переходе между мажорными и минорными версиями.

## Что нужно перед началом

1. Изучите основы установки из урока [Установка, обновление и платформы](install.md).
2. Понимание версионирования SemVer (Major.Minor.Patch).
3. Доступ к терминалу для проверки версий.

## Схема процесса

Процесс безопасного обновления и процедуры отката к проверенной версии:

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. Фиксация текущей точки отсчёта                           │
│    - codex --version -> сохранение точного номера           │
│    - Резервное копирование: cp ~/.codex/config.toml ...     │
│    - Экспорт прогресса курса в JSON                         │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│ 2. Обновление (Только при наличии обоснованной потребности) │
│    - npm install -g @openai/codex@NEW_VERSION               │
│    - или codex update (если поддерживается сборкой)         │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│ 3. Смоук-тестирование (Smoke Test)                          │
│    - codex --version (сверка с ожидаемым номером)           │
│    - /status и проверка схемы конфигурации                  │
└───────────────────────────────┬─────────────────────────────┘
                                │
            ┌───────────────────┴───────────────────┐
      Успех │                                       │ Ошибка / Регрессия
┌───────────▼───────────┐             ┌─────────────▼─────────────┐
│ Штатная работа        │             │ Процедура отката (Rollback)│
│ на новой версии       │             │ npm install -g ...@0.160.0│
│                       │             │ Восстановление config.toml│
└───────────────────────┘             └───────────────────────────┘
```

## Команды и параметры

Команды управления обновлениями и проверкой версий:

```bash
# Точная проверка текущей установленной версии
codex --version

# Встроенная команда самообновления (для поддерживаемых дистрибутивов)
codex update

# Принудительный возврат к проверенному baseline курса (0.160.0) через npm
npm install -g @openai/codex@0.160.0

# Создание резервной копии профиля пользователя перед экспериментом
cp -r ~/.codex ~/.codex.backup_$(date +%Y%m%d)

# Сверка с версией baseline в файлах курса
python -c "import json; print('Курс рассчитан на:', json.load(open('sources.json'))['target_cli'])"
```

## Разбор примера

Рассмотрим сценарий регрессии при обновлении:

1. Ученик обновил CLI до экспериментальной версии 0.170.0.
2. В новой версии формат секций `config.toml` изменился, в результате чего команда `codex` начала выдавать предупреждение: `Warning: unknown key in config.toml`.
3. Вместо того чтобы переписывать рабочие файлы репозитория под нестабильный релиз, ученик применяет план быстрого отката:
   ```bash
   # 1. Откат бинарника к зафиксированной версии
   npm install -g @openai/codex@0.160.0
   # 2. Восстановление проверенного конфига из резервной копии
   cp ~/.codex.backup/config.toml ~/.codex/config.toml
   # 3. Проверка результата
   codex --version
   ```
4. Система возвращается в гарантированно рабочее состояние за одну минуту.

## Ограничения и безопасность

1. **Разделение бинарника и данных**: откат исполняемого файла не удаляет автоматически новые поля, которые более свежая версия могла успеть записать в базу данных сессий или кэш. Всегда делайте резервную копию каталога `~/.codex/` до обновления.
2. **Никаких секретов в бэкапах**: при создании архивов резервных копий профиля (`~/.codex.backup`) убедитесь, что они не попадают в публичный репозиторий Git и не загружаются на общедоступные файлообменники.
3. **Версия курса не равна версии CLI**: курс `codex-howto` имеет собственную версию релиза (например, 0.3.0), которая не обязана численно совпадать с версией CLI (0.160.0).

## Ошибки и диагностика

| Ошибка | Причина | Способ диагностики и решения |
|---|---|---|
| После обновления `codex` не запускается (`Segment fault` или ошибка динамических библиотек) | Новый бинарник скомпилирован с более новой версией glibc или требует других системных библиотек. | Немедленно выполните откат: `npm install -g @openai/codex@0.160.0`. |
| `codex --version` продолжает показывать старый номер | Менеджер пакетов установил бинарник в другой каталог, не являющийся первым в переменной `PATH`. | Проверьте пути: `which -a codex` (Linux/macOS) или `where.exe codex` (Windows). |
| Потеряны сохранённые заметки сессий | Обновление переписало формат файла заметок. | Восстановите каталог `~/.codex/memories/` из подготовленной резервной копии. |

## Практика

1. Проверьте версию, на которую рассчитан данный практикум:
   ```bash
   python -c "import json; print('Целевая версия курса:', json.load(open('sources.json'))['target_cli'])"
   ```
2. Создайте безопасную резервную копию вашего профиля настроек:
   ```bash
   mkdir -p .learning/backups
   test -f ~/.codex/config.toml && cp ~/.codex/config.toml .learning/backups/ || echo "Глобальный config.toml пока отсутствует"
   ```
3. Составьте персональный план действий на случай необходимости отката версии инструмента.

## Самопроверка

Критерии завершения:
1. Вы знаете точный номер целевой версии CLI практикума (0.160.0).
2. Вы умеете создать резервную копию настроек перед проведением обновлений.
3. Вы можете выполнить откат установленного пакета к зафиксированной версии.

<details>
<summary>Контрольные вопросы для самопроверки</summary>

- **Вопрос**: Почему небезопасно указывать только «latest» при описании рабочего окружения команды?
- **Ответ**: Потому что под тегом «latest» в разное время скрываются разные версии с несовместимыми изменениями и отличающимся поведением.
- **Вопрос**: Что нужно сделать перед обновлением CLI на рабочем компьютере?
- **Ответ**: Зафиксировать текущую рабочую версию, экспортировать прогресс обучения и создать резервную копию профиля настроек `~/.codex/`.

</details>
