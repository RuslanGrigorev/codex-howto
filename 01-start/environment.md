# Подготовка среды: терминал, Python и Git

## Чему вы научитесь

Научитесь подготавливать надёжное локальное окружение для прохождения курса, проверять установленные версии Python и Git, ориентироваться в рабочих каталогах репозитория и отличать команды терминала операционной системы от внутренних команд Codex CLI.

## Что нужно перед началом

1. Доступ к эмулятору терминала вашей ОС (Windows Terminal, Terminal на macOS, iTerm2, Alacritty или tmux на Linux).
2. Распакованные исходные файлы курса или автономного пакета.
3. Установленный Python 3.11 или новее.
4. Установленный Git для отслеживания версий и инспекции изменений.

## Схема процесса

Рабочая среда курса состоит из трёх независимых изолированных уровней:

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. Уровень представления: Браузер (HTML / CSS / JS)        │
│    - Чтение уроков, изучение схем, прохождение квизов       │
│    - Хранение прогресса в localStorage (автономно)          │
└────────────────────────────────┬────────────────────────────┘
                                 │
┌────────────────────────────────▼────────────────────────────┐
│ 2. Уровень независимой верификации: Python 3.11+            │
│    - Запуск локальных проверок scripts/verify.py            │
│    - Подготовка рабочих пространств .learning/workspaces/   │
│    - Исполнение тестов test.py в чистом окружении           │
└────────────────────────────────┬────────────────────────────┘
                                 │
┌────────────────────────────────▼────────────────────────────┐
│ 3. Уровень нативной практики: Codex CLI 0.160.0 (Опционально) │
│    - Полноэкранный терминальный агент TUI                   │
│    - Автоматизация через codex exec                         │
│    - Вызов навыков ($learn) и встроенных команд (/plan)     │
└─────────────────────────────────────────────────────────────┘
```

Каждый уровень функционирует автономно: неполадки в бинарнике Codex или отсутствие доступа к моделям не нарушают работу браузерного учебника и не мешают прохождению Python-тестов.

## Команды и параметры

Диагностические команды для проверки готовности окружения:

```bash
# 1. Проверка версии Python (требуется >= 3.11)
python --version
# При наличии нескольких версий проверьте: python3 --version

# 2. Проверка наличия Git
git --version

# 3. Проверка текущей рабочей директории и целостности курса
python -c "from pathlib import Path; print('Текущий каталог:', Path.cwd()); print('Курс на месте:', Path('course.json').is_file())"

# 4. Проверка состояния проектного каталога
python scripts/check_project.py catalog
```

## Разбор примера

Рассмотрим типичную ошибку новичка при смешении контекстов выполнения:

1. **Команда оболочки (Shell)**:
   ```bash
   python scripts/verify.py --prepare small-fix
   ```
   Выполняется в командной строке ОС (bash, zsh, powershell).
2. **Встроенная команда Codex (Slash command)**:
   ```text
   /plan
   ```
   Вводится строго внутри диалога Codex CLI в режиме TUI. Запуск `/plan` в bash приведёт к ошибке `bash: /plan: No such file or directory`.
3. **Вызов проектного навыка (Skill)**:
   ```text
   $learn start.environment
   ```
   Вводится в диалоге Codex CLI. Навык загружается из `.agents/skills/learn/SKILL.md`.

## Ограничения и безопасность

1. **Единая среда выполнения**: не смешивайте запуск команд между Windows PowerShell и WSL внутри одной сессии. Если вы начали выполнять упражнения в WSL, используйте Python, Git и пути WSL. Смешение путей `C:\...` и `/mnt/c/...` приводит к ошибкам разрешений и повреждению окончаний строк (CRLF vs LF).
2. **Неприкосновенность эталонов**: запрещено напрямую менять файлы в папках `examples/` и `scripts/`. Всегда используйте команду `--prepare` для создания изолированной копии.
3. **Безопасность переменных окружения**: скрипт проверки `clean_env` очищает потенциально чувствительные переменные (токены, ключи API) перед запуском тестов, предотвращая их случайную утечку.

## Ошибки и диагностика

| Симптом | Причина | Способ диагностики и исправления |
|---|---|---|
| `Курс на месте: False` | Команда запущена не из корня репозитория или каталога `source`. | Перейдите в корневой каталог проекта командой `cd` и повторите проверку. |
| `SyntaxError: invalid syntax` при запуске скрипта | Используется устаревшая версия Python (ниже 3.11), не поддерживающая современный синтаксис аннотаций типов. | Обновите Python до версии 3.11+ или активируйте виртуальное окружение с правильной версией. |
| `Git not recognized as internal or external command` | Git не установлен или не добавлен в системную переменную `PATH`. | Установите Git для вашей ОС и перезапустите терминал. |

## Практика

1. Создайте в корне проекта диагностический файл `environment.txt` с помощью команд терминала:
   ```bash
   python --version > environment.txt
   git --version >> environment.txt
   python -c "from pathlib import Path; print('course.json exists:', Path('course.json').is_file())" >> environment.txt
   ```
2. Подготовьте изолированное рабочее пространство для первого учебного упражнения:
   ```bash
   python scripts/verify.py --prepare small-fix
   ```
3. Убедитесь, что каталог `.learning/workspaces/small-fix/` создан и содержит рабочие файлы `discount.py` и `test.py`.

<details>
<summary>Подсказка к выполнению задания</summary>

Если при создании файла `environment.txt` команда `python` не найдена, попробуйте команду `python3`. В системах на базе Linux и macOS часто именно имя `python3` привязано к современному интерпретатору, тогда как алиас `python` может отсутствовать или указывать на устаревший Python 2.

</details>

## Самопроверка

Критерии завершения урока:
1. Создан файл `environment.txt`, содержащий информацию о версии Python (>= 3.11) и подтверждение наличия `course.json`.
2. Команда `python scripts/verify.py --prepare small-fix` успешно создала рабочее пространство.
3. Вы чётко различаете, где вводятся команды оболочки ОС, а где — команды Codex TUI.

<details>
<summary>Контрольные вопросы для самопроверки</summary>

- **Вопрос**: Что произойдёт, если запустить `codex exec` из каталога `.learning/site`?
- **Ответ**: Команда не найдёт проектные файлы `course.json` и `AGENTS.md`, так как `.learning/site` содержит только скомпилированные страницы веб-сайта. Все команды необходимо выполнять из корня репозитория.
- **Вопрос**: Зачем нужна утилита `clean_env` при проверке упражнений?
- **Ответ**: Она очищает переменные окружения родительского процесса, предотвращая утечку персональных токенов и гарантируя воспроизводимость тестов в чистом окружении.

</details>
