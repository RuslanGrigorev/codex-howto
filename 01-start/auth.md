# Авторизация и защита учётных данных

## Чему вы научитесь

Научитесь безопасно проходить процедуру авторизации в Codex CLI 0.160.0, выбирать между веб-аутентификацией через браузер, device-code потоком и переменными окружения, проверять статус входа командой `codex login status`, корректно изолировать профили через `CODEX_HOME` и предотвращать утечку токенов в историю команд и Git.

## Что нужно перед началом

1. Изучите основы установки из урока [Установка, обновление и платформы](install.md).
2. Понимание разницы между токенами доступа (access tokens) и файлами конфигурации проекта.
3. Доступ в интернет требуется только для первоначального получения токена при работе с реальными моделями.

## Схема процесса

Потоки авторизации и хранения учётных данных представлены на схеме:

```text
┌─────────────────────────────────────────────────────────────┐
│ Выбор метода авторизации в Codex CLI                       │
├──────────────────────────────┬──────────────────────────────┤
│ Вариант А: Интерактивный     │ Вариант Б: Автоматический    │
│ codex login                  │ export CODEX_API_KEY="..."   │
│ (Открытие браузера / OAuth)  │ (CI/CD и неинтерактивный)    │
└──────────────┬───────────────┴──────────────┬───────────────┘
               │                              │
┌──────────────▼──────────────────────────────▼───────────────┐
│ Системный менеджер учетных данных (Secure Token Store)     │
│ - macOS Keychain / Linux SecretService / Windows DPAPI      │
│ - Файл ~/.codex/auth.json (с правами 0600)                  │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│ Сессионная верификация                                      │
│ - codex login status (проверка срока действия токена)       │
│ - Завершение сеанса: codex logout (удаление ключа)          │
└─────────────────────────────────────────────────────────────┘
```

## Команды и параметры

Управление учётными данными в CLI:

```bash
# Интерактивный вход через браузер по умолчанию
codex login

# Просмотр параметров и альтернативных методов входа
codex login --help

# Проверка текущего статуса авторизации (без отображения секретов)
codex login status

# Завершение сеанса и отзыв локальных токенов
codex logout

# Авторизация через переменную окружения (предпочтительно для CI/CD)
export CODEX_API_KEY="sk-..."
```

## Разбор примера

Рассмотрим безопасный и небезопасный способы передачи секретов:

1. **Критически опасный способ (НЕ ДЕЛАТЬ!)**:
   ```bash
   # ОШИБКА: ключ остаётся в истории команд (.bash_history) и виден в выводе ps
   codex -c api_key=sk-secret12345 "Выполни задачу"
   ```
   Если сохранить ключ в `config.toml` или `AGENTS.md`, он будет закоммичен в публичный репозиторий Git, что приведёт к компрометации аккаунта.

2. **Безопасный способ**:
   Используйте команду `codex login`, которая сохраняет токен в защищённом хранилище ОС, либо передавайте переменную среды в текущую сессию:
   ```bash
   read -s CODEX_API_KEY
   export CODEX_API_KEY
   codex exec "Выполни задачу"
   ```

## Ограничения и безопасность

1. **Никаких секретов в репозитории**: запрещено помещать файлы `auth.json`, `.env`, токены или пароли в каталог проекта. В `.gitignore` репозитория добавлены шаблоны `.env`, `auth.json` и `*.pem`.
2. **Изоляция через `CODEX_HOME`**: при тестировании сторонних плагинов или проведении аудита используйте отдельный временный каталог: `export CODEX_HOME=$(mktemp -d)`. Обратите внимание: новый профиль не наследует авторизацию автоматически.
3. **Безопасность вывода**: при оформлении баг-репортов и отчётов об упражнениях всегда обезличивайте идентификаторы пользователей, организации и токены доступа.

## Ошибки и диагностика

| Симптом | Причина | Способ диагностики и исправления |
|---|---|---|
| `Authentication error: token expired` | Истёк срок действия сессионного токена. | Запустите `codex login` для обновления авторизации. |
| `Permission denied (model access)` | Учётная запись не имеет доступа к запрошенной модели (например, флаг `--model gpt-5-codex`). | Проверьте тарифный план аккаунта или переключитесь на доступную модель через `-c model=...`. |
| `Cannot open browser in headless environment` | Запуск `codex login` на удалённом сервере без графической оболочки. | Используйте флаг `codex login --device-code` или передайте переменную `CODEX_API_KEY`. |

## Практика

1. Проверьте текущий статус авторизации в вашей системе:
   ```bash
   codex login status || echo "Авторизация не настроена (статус: NOT_RUN)"
   ```
2. Убедитесь, что в файловой системе проекта отсутствуют скрытые файлы с секретами:
   ```bash
   git status --ignored
   ```
3. Проверьте, что переменная `CODEX_API_KEY` не экспортирована глобально со значением тестового токена.

## Самопроверка

Критерии завершения:
1. Вы знаете, где безопасно хранятся токены в вашей ОС.
2. Вы понимаете, почему ключи API категорически запрещено указывать аргументом командной строки `-c api_key=...`.
3. Убедились в отсутствии файлов `.env` и `auth.json` в рабочей копии Git.

<details>
<summary>Контрольные вопросы для самопроверки</summary>

- **Вопрос**: Что произойдёт, если удалить каталог `~/.codex/`?
- **Ответ**: Будет сброшена локальная авторизация и история сессий, при этом в удалённом аккаунте сессия останется активной до истечения срока токена или явного отзыва.
- **Вопрос**: Допустимо ли включать файл `auth.json` в архив отчёта об обучении?
- **Ответ**: Категорически запрещено! Файл содержит приватные токены доступа к API.

</details>
