# Авторизация и защита учётных данных

## Чему вы научитесь

Выбрать способ входа и не включить учётные данные в учебные файлы или отчёт.

## Что нужно перед началом

Сначала пройдите: [Начало: что изучаем и как проверяем результат](overview.md). Учебные файлы входят в поставку. Установленные программы и доступ к модели требуются только для соответствующей практики.

Способ входа и доступные модели зависят от выбранного провайдера и учётной записи. Начните с локальной справки, затем выполните поддерживаемый сценарий входа:

```bash
codex login --help
codex login
codex login status
```

Варианты входа через браузер, device code и API-ключ проверяйте по справке установленной версии. Не вставляйте секрет в командную строку, учебный чат, `AGENTS.md`, `config.toml` или Git. Передача ключа через предусмотренный CLI ввод или защищённое хранилище предпочтительнее сохранения литерала в истории оболочки.

Файлы авторизации и журналы могут содержать чувствительные данные. `CODEX_HOME` позволяет отделить учебное окружение от рабочего, но новый каталог не получает авторизацию автоматически. Не копируйте содержимое основного профиля без разбора. Для выхода используйте `codex logout`; удаление программы не является выходом из аккаунта.

## Практика и разбор ошибки

Проверьте статус, не публикуя токены. При отказе различите отсутствие входа, отсутствие сетевого доступа и отсутствие прав на модель. Не сохраняйте полный вывод с персональными данными в отчёт. Без сети этот урок можно изучить полностью; сетевой вход остаётся отдельным неподтверждённым действием.

## Что считается выполнением в Codex

Без модели доступны весь текст, вопросы, исходники и локальные тесты. Они не подтверждают работу CLI. Для практики сохраните версию `codex --version`, модель, провайдера и обезличенный результат реального запуска. Отметку можно внести через `scripts/progress.py` после проверки, согласно [правилам валидации](../reference/validation.md). Самоотчёт ученика не заменяет выпускные доказательства проекта.
