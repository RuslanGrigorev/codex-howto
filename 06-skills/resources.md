# Материалы и скрипты внутри навыка

## Чему вы научитесь

- Структурировать составной навык Codex CLI: разделять инструкции (`SKILL.md`), справочники (`references/`) и скрипты (`scripts/`).
- Использовать прогрессивную подгрузку справочных материалов только по явному запросу для экономии токенов.
- Безопасно запускать вспомогательные утилиты навыка и контролировать их аргументы.
- Организовывать относительные пути внутри пакета навыка для обеспечения портативности.

## Что нужно перед началом

- Понимание базовой структуры `SKILL.md` из предыдущего урока.
- Локальная среда с интерпретатором Python для запуска вспомогательных скриптов.
- Установленный Codex CLI 0.160.0.

## Схема процесса

Прогрессивная загрузка ресурсов навыка:

```
[Пользователь вызывает: "$data-migration migrate schema.sql"]
                              │
                              ▼
┌────────────────────────────────────────────────────────┐
│             Ядро навыка: SKILL.md (~200 токенов)       │
├────────────────────────────────────────────────────────┤
│ Читает базовые правила и определяет тип операции       │
└─────────────────────────────┬──────────────────────────┘
                              │
             Требуется справочник типов БД?
                              │
               ┌──────────────┴──────────────┐
              ДА                             НЕТ
               │                              │
               ▼                              ▼
┌─────────────────────────────┐  [Пропуск: экономия 15K токенов]
│ Чтение: references/types.md │               │
└──────────────┬──────────────┘               │
               │                              │
               └──────────────┬───────────────┘
                              │
                              ▼
┌────────────────────────────────────────────────────────┐
│         Вызов валидатора: scripts/validate_sql.py      │
├────────────────────────────────────────────────────────┤
│ 1. Проверка синтаксиса миграции без сетевого доступа   │
│ 2. Возврат кода завершения и ошибок в сессию           │
└────────────────────────────────────────────────────────┘
```

## Команды и параметры

Структура каталога составного навыка:

```text
.agents/skills/data-migration/
├── SKILL.md                   # Точка входа: frontmatter и базовый алгоритм
├── references/                # Каталог со справочной документацией
│   ├── postgres_types.md      # Таблица соответствия типов
│   └── naming_rules.md        # Соглашения по именованию индексов
└── scripts/                   # Автономные проверочные утилиты
    └── validate_sql.py        # Локальный линтер SQL
```

Пример ссылки на справочник в `SKILL.md`:

```markdown
---
name: data-migration
description: Проверка и генерация SQL-миграций по корпоративным стандартам.
---

## Порядок работы
1. При проверке структуры таблиц прочитай `references/naming_rules.md`.
2. Если в миграции используются типы JSON или UUID, обратись к `references/postgres_types.md`.
3. Перед выводом ответа запусти валидатор:
   `python scripts/validate_sql.py <путь_к_миграции>`
```

## Разбор примера

Рассмотрим выполнение задачи валидации файла миграции `001_create_users.sql`:

1. Пользователь вызывает `$data-migration 001_create_users.sql`.
2. Codex CLI считывает легкий манифест `SKILL.md`.
3. Агент видит в файле миграции определение колонки `uuid_id` и по правилу считывает `references/postgres_types.md`.
4. Справочник `naming_rules.md` не считывается, если в файле нет индексов, что экономит контекстное окно.
5. Агент запускает локальный проверочный скрипт:
   ```bash
   python .agents/skills/data-migration/scripts/validate_sql.py 001_create_users.sql
   ```
6. Скрипт возвращает `SQL_SYNTAX_OK`. Агент выводит итоговый отчет.

## Ограничения и безопасность

- Скрипты внутри папки `scripts/` выполняются с правами локального пользователя: перед вызовом проверьте, что скрипт не содержит деструктивных системных вызовов (`rm -rf`, сетевые сокеты).
- Никогда не используйте абсолютные пути файловой системы внутри `SKILL.md`: всегда используйте относительные пути от корня каталога навыка.
- Не включайте в каталог `references/` гигантские файлы (>100 КБ): разбивайте документацию на тематические разделы.

## Типовые ошибки

1. **Жадная загрузка контекста**: принудительное включение всех файлов из `references/` в каждый запрос, быстро переполняющее контекстное окно.
2. **Непроверенные скрипты**: запуск непроверенного исполняемого бинарника из стороннего навыка.
3. **Ошибки относительных путей**: ссылки на файлы вида `../../docs/rules.md`, которые ломаются при переносе навыка в глобальную папку `~/.codex/skills/`.

## Практика

1. Создайте структуру каталогов для учебного навыка с подпапками `references/` и `scripts/`.
2. Создайте справочный файл `references/rules.txt` и простой скрипт `scripts/lint.py`, возвращающий код `0` при успехе.
3. Опишите в `SKILL.md` условия, при которых агент должен обратиться к `rules.txt` и запустить `lint.py`.
4. Протестируйте поведение агента при перемещении файла справочника и убедитесь, что ошибка корректно обрабатывается.
