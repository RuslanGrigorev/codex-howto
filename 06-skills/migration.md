# Перенос повторяемых запросов и /import

## Чему вы научитесь

- Переносить повторяемые инженерные промпты и шаблоны в формат автономных навыков Codex CLI.
- Использовать встроенную команду `/import` для миграции существующих конфигураций из поддерживаемых сред.
- Адаптировать синтаксис вызова инструментов под нативные возможности Codex CLI без механической подмены имен.
- Очищать импортируемые инструкции от устаревших конструкций, чужих секретов и абсолютных путей.

## Что нужно перед началом

- Существующий текстовый шаблон промпта или набор инструкций из другого инструмента.
- Понимание структуры `SKILL.md` (frontmatter, инструкции, references).
- Установленный Codex CLI 0.160.0.

## Схема процесса

Миграция внешних инструкций в структуру навыка Codex CLI:

```
[Внешний шаблон / Промпт стороннего ассистента]
                        │
                        ├──> Команда: /import
                        │
                        ▼
┌────────────────────────────────────────────────────────┐
│             Анализ и трансформация контента            │
├────────────────────────────────────────────────────────┤
│ 1. Удаление проприетарных команд стороннего клиента    │
│ 2. Исключение личных путей, токенов и auth-файлов      │
│ 3. Выделение параметров задачи и формата отчета        │
│ 4. Формирование YAML frontmatter (name, description)   │
└───────────────────────┬────────────────────────────────┘
                        │
                        ▼
┌────────────────────────────────────────────────────────┐
│     Готовый автономный навык .agents/skills/<name>/    │
├────────────────────────────────────────────────────────┤
│ - SKILL.md: ядро инструкций с вызовом через $name      │
│ - references/: выделенная документация                 │
│ - scripts/: безопасные проверочные скрипты             │
└────────────────────────────────────────────────────────┘
```

## Команды и параметры

Команды миграции и инспекции импортированных инструкций:

```text
# Запуск мастера импорта поддерживаемых настроек в интерактивной сессии
/import

# Проверка распознавания импортированного навыка
/skills

# Тестовый вызов перенесенного навыка
$migrated-tool --dry-run
```

Сравнение синтаксиса вызовов при миграции:

| Внешний инструмент / Старый формат | Нативный формат Codex CLI 0.160.0 |
| :--- | :--- |
| `custom-prompts/review.md` | `.agents/skills/review/SKILL.md` |
| Вызов через слеш `/review` | Вызов через знак доллара `$review` |
| Неявные команды оболочки | Явные инструменты песочницы или scripts/ |
| Токены в теле инструкций | Переменные окружения без коммита в Git |

## Разбор примера

Рассмотрим адаптацию внешнего шаблона ревью кода:

1. Исходный текст стороннего инструмента содержал:
   «Используй команду `/claude-review` с правами sudo для проверки файла».
2. При миграции в Codex CLI:
   - Создаем каталог `.agents/skills/code-review/`.
   - Создаем `SKILL.md` с валидным YAML frontmatter:
     ```markdown
     ---
     name: code-review
     description: Автоматизированный анализ diff и поиск уязвимостей.
     ---
     ```
   - Заменяем внешние конструкции на стандартные правила: убираем `sudo`, указываем проверку через `git diff`, задаем русский язык для пояснений.
3. Проверяем регистрацию навыка командой `/skills`.
4. Вызываем навык: `$code-review`. Навык исполняется в соответствии с песочницей Codex CLI.

## Ограничения и безопасность

- Команда `/import` не гарантирует автоматическую работоспособность сложных хуков: логику вызовов необходимо проверять вручную.
- При миграции никогда не переносите файлы `auth.json`, cookies или закрытые токены API сторонних инструментов.
- Устраняйте любые попытки импорта запросов, требующих неограниченного доступа к файловой системе (`danger-all-access`).

## Типовые ошибки

1. **Слепое копирование синтаксиса**: попытка использовать команды чужих продуктов внутри Codex CLI без адаптации.
2. **Утечка авторизационных данных**: включение файлов персональной авторизации в каталог перенесенного навыка.
3. **Удаление лицензий третьих сторон**: стирание юридических сведений об авторских правах оригинальных шаблонов при адаптации.

## Практика

1. Возьмите любой произвольный текстовый шаблон системного промпта.
2. Преобразуйте его в стандартный навык `.agents/skills/my-adapted-skill/SKILL.md`.
3. Добавьте поля `name` и `description` во frontmatter.
4. Проверьте через `/skills`, что навык корректно зарегистрирован и доступен для вызова через префикс `$`.

## Самопроверка

<details>
<summary>Подсказка и критерии самопроверки</summary>

- Убедитесь, что в тексте `SKILL.md` отсутствуют следы специфических слеш-команд других AI-клиентов.
- Проверьте, что вызов `$my-adapted-skill` в диалоге активирует регламентированные инструкции.
- Критерий успешности: навык успешно инициализируется в сессии Codex CLI без вызова внешних сетевых сервисов.
