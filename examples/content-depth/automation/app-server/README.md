# A04: Stdio-клиент для долгоживущего Codex App-Server (ADR-CD-04)

Комплект A04 демонстрирует взаимодействие с официальным долгоживущим сервером приложений `codex app-server` в Codex CLI 0.160.0.

> **Важно**: в версии 0.160.0 устаревшая команда `codex mcp-server` удалена из активного интерфейса. Официальным протоколом для IDE и хост-приложений является `codex app-server` поверх stdio.

## Архитектура и протокол взаимодействия

1. **Разделение транспорта и протокола**:
   Используются абстракция `BaseJsonRpcTransport`, реализация `SubprocessStdioTransport` (процессный транспорт поверх потоков stdin/stdout дочернего процесса `codex app-server` с контролем EOF и завершения процесса) и фикстура `FixtureStdioTransport` для детерминированного тестирования.
2. **Атомарные переходы состояний (FSM)**:
   - При сбое `initialize` состояние гарантированно откатывается в `DISCONNECTED`, обеспечивая возможность безопасного повтора (retry).
   - При ошибке `turn/start` состояние возвращается в `READY`.
3. **Жизненный цикл сессии**:
   - Инициализация (`initialize`): handshake и согласование версий.
   - Создание треда (`thread/create`): изоляция рабочего каталога.
   - Исполнение ходов (`turn/start`): пошаговая генерация.
   - Отмена (`turn/cancel`): прерывание без падения процесса.

## Состав комплекта

- `README.md` — архитектура и последовательность протокола.
- `app_server_stdio_client.py` — автономный клиент app-server с конечным автоматом состояний, JSON-RPC 2.0 и stdio-транспортом.
- `scripts/mock_app_server.py` — тестовый дочерний процесс для проверки SubprocessStdioTransport.
- `test_app_server_client.py` — модульные проверки переходов состояний, stdio-транспорта, EOF, тайм-аутов и отката при сбоях.
