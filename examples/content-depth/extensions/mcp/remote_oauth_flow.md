# Протокол авторизации Remote MCP через OAuth 2.0

При подключении к удалённому MCP-серверу (например, корпоративному сервису или SaaS-платформе) процесс авторизации состоит из следующих фаз:

1. **Discovery (Обнаружение endpoint)**:
   Клиент запрашивает метаданные сервера по HTTPS:
   `GET https://mcp.company.com/.well-known/oauth-authorization-server`
2. **Инициализация OAuth**:
   Клиент открывает браузер пользователя на странице подтверждения доступа с указанием запрошенных скоупов (`tools:read`, `tools:call`).
3. **Получение токена (Token Exchange)**:
   После согласия пользователя локальный callback-сервер перехватывает `auth_code` и обменивает его на пару `access_token` и `refresh_token`.
4. **Безопасное хранение**:
   Токен сохраняется в защищённом системном хранилище учетных данных ОС (Keychain / SecretService / DPAPI) и никогда не коммитится в Git.
5. **Вызовы инструментов**:
   Каждый последующий запрос к MCP-серверу сопровождается заголовком:
   `Authorization: Bearer <access_token>`.
