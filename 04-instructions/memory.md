# Память, сжатие контекста и сводки

## Чему вы научитесь

- Использовать команды сжатия контекста (`/compact`) и генерации сводок (`/recap`) для длинных сессий Codex CLI.
- Различать оперативную память сессии, долгосрочную память (`/memories`) и статические правила проекта (`AGENTS.md`).
- Сохранять ключевые ограничения и результаты промежуточных проверок при автоматической компрессии диалога.
- Предотвращать утечку конфиденциальных данных и секретов в долгосрочную память агента.

## Что нужно перед началом

- Понимание устройства контекстного окна LLM и механизмов токенизации.
- Ознакомление со схемой контекста из урока [Контекст, память, история и файлы](context.md) (схема D04).
- Установленный Codex CLI 0.160.0.

## Схема процесса

Управление жизненным циклом контекста и сжатием диалога:

```
[Полнотекстовая история сообщений, вызовы tools, diff-патчи]
                             │
                             ▼
              [Размер контекста > Порог (напр. 80%)]
                             │
                             ▼
┌────────────────────────────────────────────────────────┐
│             Команда /compact (Сжатие контекста)        │
├────────────────────────────────────────────────────────┤
│ 1. Извлечение ключевых решений и статусов проверок     │
│ 2. Удаление подробных дампов терминала и tool_output   │
│ 3. Формирование краткой структурированной сводки       │
│ 4. Сохранение постоянных инструкций из AGENTS.md       │
└────────────────────────────┬───────────────────────────┘
                             │
                             ▼
[Сжатый контекст сессии: сохранена цель, сброшены промежуточные логи]
                             │
                             ▼
[Продолжение работы без превышения лимита токенов модели]
```

## Команды и параметры

Интерактивные команды управления памятью и сжатием контекста в TUI:

```text
# Сжатие истории текущей сессии с сохранением ключевых фактов
/compact

# Формирование актуальной сводки текущего состояния и незавершенных задач
/recap

# Просмотр и управление долгосрочными воспоминаниями агента
/memories

# Просмотр занятого объема контекстного окна и расхода токенов
/status
```

Параметры автоматического сжатия в `~/.codex/config.toml`:

```toml
[context]
auto_compact_threshold = 0.85
preserve_recent_turns = 4
```

## Разбор примера

Рассмотрим длительную сессию разработки, в ходе которой было выполнено 20 итераций правок кода и вывода тестов:

1. Размер контекста приблизился к лимиту (например, 110 000 из 128 000 токенов).
2. Вызываем интерактивную команду `/compact`.
3. Модель анализирует накопленную историю:
   - Исходные громоздкие логи тестов `pytest` сжимаются до факта: «Тесты `test_auth.py` и `test_tokens.py` успешно пройдены (PASS)».
   - Промежуточные diff-патчи заменяются финальным состоянием файлов.
   - Критические правила из `AGENTS.md` (например, «Не трогать auth.json») остаются нетронутыми в системном блоке.
4. Объем контекста уменьшается до 25 000 токенов, освобождая пространство для последующих задач.
5. Проверяем сохранение цели командой `/recap`.

## Ограничения и безопасность

- Сжатие контекста является алгоритмом обобщения с потерями: редкие детали, специфические имена исключений и номера строк могут быть опущены.
- Никогда не сохраняйте приватные токены, пароли или секреты в долгосрочную память (`/memories`), так как они могут непреднамеренно подставиться в последующие сессии в других репозиториях.
- Долгосрочная память не заменяет систему контроля версий Git и проектные файлы `AGENTS.md`.

## Типовые ошибки

1. **Потеря ограничений при сжатии**: отсутствие контроля за тем, что после `/compact` агент помнит запрет на изменение определенных модулей.
2. **Использование памяти вместо документации**: сохранение архитектурных требований проекта в `/memories` вместо коммита в `AGENTS.md`.
3. **Игнорирование переполнения контекста**: отказ от ручного сжатия, приводящий к резкой потере старых сообщений или отказу API провайдера с ошибкой контекстного окна.

## Практика

1. Запустите сессию Codex CLI и проведите серию диалоговых итераций с чтением нескольких файлов.
2. Вызовите команду `/status`, чтобы оценить текущее потребление токенов.
3. Примените команду `/compact`, после чего запросите у агента `/recap`.
4. Сверьте, сохранились ли все ключевые цели задачи и выявленные на предыдущих шагах ошибки.

## Самопроверка

<details>
<summary>Подсказка и критерии самопроверки</summary>

- Убедитесь, что после вызова `/compact` счетчик токенов в `/status` заметно снизился.
- Проверьте вывод команды `/recap`: агент должен четко помнить текущую задачу, прогресс и следующие шаги.
- Критерий успешности: агент не повторяет уже решенные подзадачи и сохраняет верность проектным правилам `AGENTS.md`.

</details>
