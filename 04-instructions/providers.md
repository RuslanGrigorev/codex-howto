# Локальный провайдер и границы автономного запуска

## Чему вы научитесь

- Подключать локальные LLM-провайдеры (Ollama, LM Studio) к Codex CLI через флаг `--oss`.
- Настраивать эндпоинты локальных моделей и параметры контекста в `config.toml`.
- Различать локальное исполнение инференса модели и сетевые вызовы внешних инструментов.
- Тестировать совместимость локальных моделей со стандартами Tool Calling и структурированного вывода.

## Что нужно перед началом

- Установленный локальный сервер инференса (Ollama или LM Studio), запущенный на локальном порту (например, `http://localhost:11434` или `http://localhost:1234`).
- Заранее скачанная модель с поддержкой Function/Tool Calling (например, `llama3.1`, `qwen2.5-coder`).
- Установленный Codex CLI 0.160.0.

## Схема процесса

Схема взаимодействия Codex CLI с локальным провайдером:

```
┌────────────────────────────────────────────────────────┐
│                      Codex CLI                         │
└──────────────────────────┬─────────────────────────────┘
                           │ HTTP REST API (локальный сокет)
                           ▼
┌────────────────────────────────────────────────────────┐
│     Локальный инференс-сервер (Ollama / LM Studio)     │
│             http://127.0.0.1:11434/v1                  │
├────────────────────────────────────────────────────────┤
│ 1. Прием промпта и определений инструментов (tools)    │
│ 2. Локальная генерация токенов на GPU/CPU (без облака) │
│ 3. Формирование tool_calls (JSON)                      │
└──────────────────────────┬─────────────────────────────┘
                           │ Ответ с вызовом функции
                           ▼
┌────────────────────────────────────────────────────────┐
│               Выполнение локального tool               │
│         (чтение файла, проверка через песочницу)       │
└────────────────────────────────────────────────────────┘
```

## Команды и параметры

Запуск Codex CLI с локальным провайдером:

```bash
# Запуск через Ollama с указанием модели
codex --oss --local-provider ollama --model qwen2.5-coder:7b --sandbox read-only

# Запуск через LM Studio на локальном порту
codex --oss --local-provider lmstudio --model local-model --sandbox read-only

# Проверка статуса подключения и контекста
codex /status
```

Конфигурация провайдера в `~/.codex/config.toml`:

```toml
# Переключение на локальный OSS провайдер
provider = "ollama"
model = "qwen2.5-coder:7b"

[providers.ollama]
base_url = "http://127.0.0.1:11434/v1"
temperature = 0.1
context_length = 32768
```

## Разбор примера

Рассмотрим запуск локальной сессии для анализа исходного кода:

1. Запускаем локальный демон Ollama:
   ```bash
   ollama run qwen2.5-coder:7b
   ```
2. Запускаем Codex CLI в безопасном режиме:
   ```bash
   codex --oss --local-provider ollama --model qwen2.5-coder:7b --sandbox read-only
   ```
3. Отправляем тестовый запрос: «Прочитай `README.md` и составь краткое резюме проекта».
4. Codex передает структуру инструмента `read_file` в локальную модель.
5. Локальная модель корректно возвращает структуру JSON вызова инструмента:
   `{"name": "read_file", "arguments": {"path": "README.md"}}`.
6. Codex выполняет локальное чтение файла в рамках песочницы и возвращает результат в модель для генерации финального ответа. Весь цикл проходит автономно без выхода во внешнюю сеть.

## Ограничения и безопасность

- Флаг `--oss` не устанавливает сам движок инференса (Ollama/vLLM) и не загружает веса моделей автоматически: окружение должно быть подготовлено заранее.
- Далеко не все компактные локальные модели (особенно <7B) стабильно поддерживают строгий синтаксис Tool Calling и многошаговые рассуждения.
- Работа с локальным провайдером не гарантирует отключение сетевых MCP-серверов или веб-поиска: для полной изоляции явно указывайте `--search disabled` и `--deny-network`.

## Типовые ошибки

1. **Попытка запуска без активного демона**: запуск с флагом `--oss`, когда сервер Ollama не запущен (ошибка `ConnectionRefused`).
2. **Неверный идентификатор модели**: передача имени облачной модели вместо локально загруженного тега.
3. **Галлюцинации схемы инструментов**: слабая модель генерирует некорректный JSON при вызове инструментов, приводя к сбою сессии.

## Практика

1. Подготовьте локальный сервер Ollama или LM Studio с любой доступной кодовой моделью.
2. Проверьте отклик сервера локальной командой `curl http://127.0.0.1:11434/api/tags`.
3. Запустите Codex CLI с флагом `--oss`, протестируйте чтение безопасного файла `marker.txt` и убедитесь в отсутствии внешнего трафика.

- Критерий успешности: файл прочитан без ошибок, а сетевой трафик во внешний интернет (api.openai.com) не фиксируется.

## Источники и доступность

Практика требует установленного Codex и доступной выбранной модели. Без модели выполните разбор примера и подготовьте ожидаемый результат; реальный запуск остаётся невыполненным. Целевая версия — 0.160.0. Документальная сверка: 2026-10-05; она не заменяет протокол запуска на вашей ОС.
