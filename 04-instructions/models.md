# Модели, провайдеры, reasoning и ограничения

## Чему вы научитесь

- Выбирать подходящую модель под тип задачи (быстрые правки, глубокий архитектурный анализ, тяжелый рефакторинг).
- Настраивать параметры модели и уровень рассуждений (`reasoning_effort`) в `config.toml` и аргументах запуска.
- Анализировать расход токенов и ограничения контекстного окна через `/status` и `/usage`.
- Диагностировать ошибки лимитов (Rate Limits) и недоступности выбранных провайдеров.

## Что нужно перед началом

- Базовые навыки работы с терминалом и конфигурационными файлами TOML.
- Понимание, что доступный перечень моделей определяется учетной записью провайдера.
- Установленный Codex CLI 0.160.0 или изучение справочника параметров.

## Схема процесса

Процесс выбора модели и инициализации параметров генерации:

```
[Пользовательский запуск задачи]
                 │
                 ├──> Параметры: --model, --provider, config.toml
                 │
                 ▼
┌────────────────────────────────────────────────────────┐
│            Оценка задачи и маршрутизация               │
├────────────────────────────────────────────────────────┤
│  Быстрая правка опечаток?   ──> Легковесная модель     │
│  Глубокий анализ архитектуры? ──> Модель с reasoning   │
└────────────────────────┬───────────────────────────────┘
                         │
                         ▼
┌────────────────────────────────────────────────────────┐
│            Инициализация сессии Codex CLI              │
├────────────────────────────────────────────────────────┤
│ 1. Загрузка параметров: model, reasoning_effort, temp  │
│ 2. Проверка контекстного окна (context window limit)   │
│ 3. Мониторинг квоты и токенов (input/output/cached)    │
└────────────────────────┬───────────────────────────────┘
                         │
        ┌────────────────┴────────────────┐
     В норме?                        Превышен лимит?
        │                                 │
        ▼                                 ▼
[Генерация ответа и tool_use]      [Ошибка 429: Rate Limit /
                                    Переход в graceful retry]
```

## Команды и параметры

Команды и параметры управления моделями:

```bash
# Запуск с указанием конкретной модели
codex --model o3-mini

# Переопределение провайдера и параметров генерации
codex --model gpt-4o --config model.reasoning_effort=high

# Инспекция активной конфигурации модели и квот в сессии
/model
/status
/usage
```

Настройка в файле `config.toml`:

```toml
# Выбор модели по умолчанию
model = "gpt-4o"

[model_settings]
reasoning_effort = "medium"  # low, medium, high
temperature = 0.2
max_output_tokens = 4096
```

## Разбор примера

Рассмотрим задачу исследования сложного race-condition бага в асинхронном коде:

1. Выбираем модель с поддержкой глубокого рассуждения:
   ```bash
   codex --model o3-mini "Найди причину deadlock в async_worker.py"
   ```
2. В процессе работы модель генерирует цепочку рассуждений (reasoning tokens), скрытую от оператора, но направляющую логику поиска.
3. Проверяем состояние сессии командой `/status`:
   ```text
   Model: o3-mini
   Reasoning effort: medium
   Tokens used: 1,420 input, 890 reasoning, 450 completion
   ```
4. Если задача простая (например, переименование переменной), переключение на базовую модель ускоряет ответ в 3–5 раз и экономит квоту токенов.

## Ограничения и безопасность

- Список доступных моделей не является статическим: провайдеры регулярно обновляют версии и удаляют устаревшие чекпоинты.
- Высокий уровень reasoning (`high`) существенно увеличивает время ожидания первого токена (TTFT) и расход вычислительных единиц.
- Не передавайте чувствительные токены и пароли в кастомных системных промптах конфигурации модели.

## Типовые ошибки

1. **Жесткая фиксация имени редкой модели**: прописывание в скриптах CI/CD версии модели, к которой у сервисного аккаунта нет доступа.
2. **Игнорирование лимитов контекста**: попытка скормить модели проект размером 500 МБ без фильтрации через `.codexignore`.
3. **Ошибочная диагностика исчерпания лимитов**: принятие сообщения `429 Too Many Requests` за ошибку синтаксиса или сбой в коде.

## Практика

1. Изучите текущий профиль конфигурации моделей с помощью интерактивных команд `/model` и `/status`.
2. Сравните поведение агента на простой задаче форматирования при разных настройках модели (если доступны альтернативные модели).
3. Настройте в тестовом `config.toml` параметры `reasoning_effort` и ограничение токенов вывода.
