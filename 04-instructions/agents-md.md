# AGENTS.md: инструкции проекта и области действия

## Чему вы научитесь

- Создавать структурированные инструкции `AGENTS.md` для управления поведением Codex CLI в проекте.
- Разграничивать глобальные, проектные и каталожные области действия правил.
- Формулировать детерминированные команды сборки, тестов и код-стайла без двусмысленности.
- Избегать включения секретов, абсолютных путей файловой системы и противоречивых требований.

## Что нужно перед началом

- Базовые знания о структуре репозитория и командной строке.
- Ознакомление со схемой наследования контекста из урока [Область действия AGENTS.md](scope.md).
- Учебный каталог с возможностью запуска проверочных скриптов.

## Схема процесса

Иерархия обнаружения и применения инструкций `AGENTS.md`:

```
[Пользовательский корень: ~/.codex/AGENTS.md] ──> Глобальные предпочтения
                        │
                        ▼
[Корень репозитория: /repo/AGENTS.md]         ──> Стандарты проекта, команды CI
                        │
                        ▼
[Подкаталог модуля: /repo/backend/AGENTS.md]  ──> Специфика стека (Python/pytest)
                        │
                        ▼
┌────────────────────────────────────────────────────────┐
│             Сборка контекста сессии Codex              │
├────────────────────────────────────────────────────────┤
│ 1. Чтение инструкций сверху вниз по иерархии           │
│ 2. Локальные правила подкаталога уточняют верхние      │
│ 3. Включение в системный промпт текущего диалога       │
└────────────────────────────────────────────────────────┘
```

## Команды и параметры

Управление инструкциями проекта:

```bash
# Инициализация базового шаблона AGENTS.md в текущем каталоге
codex init --agents

# Проверка того, какие файлы AGENTS.md обнаружены и прочитаны
codex context --inspect

# Запуск автономного проверяемого упражнения курса
python scripts/verify.py --prepare agents-rules
python scripts/verify.py --exercise agents-rules --workspace .learning/workspaces/agents-rules
```

Пример содержимого `AGENTS.md` в корне репозитория:

```markdown
# Стандарты разработки проекта

## Назначение
Этот проект — веб-сервис на FastAPI для аналитики метрик.

## Команды сборки и тестирования
- Запуск тестов: `pytest -q tests/`
- Проверка типов: `mypy src/`
- Линтер: `ruff check src/`

## Правила внесения изменений
- Не меняйте существующие тесты ради фиктивного прохождения (PASS).
- Не используйте абсолютные пути ОС; применяйте относительные пути от корня проекта.
- Не включайте секреты, токены и приватные переменные в код и логи.
```

## Разбор примера

Рассмотрим обработку задачи «Запусти регрессионные тесты и исправь баг»:
1. Codex находит `AGENTS.md` в корне рабочего каталога.
2. В секции `## Команды сборки и тестирования` агент считывает команду `pytest -q tests/` вместо того, чтобы наугад вызывать `python test.py` или `pytest --cov`.
3. Секция `## Правила внесения изменений` напрямую предотвращает фальсификацию тест-кейсов.
4. Ответ формулируется с соблюдением языка и стиля, заданных в правилах проекта.

## Ограничения и безопасность

- `AGENTS.md` считывается языковой моделью как промпт; модель следует ему вероятностно. Для критически важных системных блокировок используйте политики исполнения (`.rules`) и песочницу.
- Никогда не помещайте в `AGENTS.md` токены доступа, пароли к БД или личные токены: этот файл фиксируется в системе контроля версий Git.
- Избегайте слишком длинных инструкций (>500 строк): перегрузка системного промпта снижает способность модели удерживать рабочий контекст задачи.

## Типовые ошибки

1. **Размещение абсолютных путей**: прописывание путей вида `C:\Users\Mi\...` или `/home/dev/...`, ломающих работу в окружении других участников команды.
2. **Противоречивые правила**: указание взаимоисключающих инструкций («используй только async» и «сохраняй синхронный интерфейс»).
3. **Хранение секретов**: включение в текст реальных ссылок с токенами авторизации.

## Практика

1. Подготовьте файл `AGENTS.md` для тестового модуля, содержащий секции описания, команд проверки и ограничений.
2. Выполните автономное упражнение `agents-rules`:
   ```bash
   python scripts/verify.py --prepare agents-rules
   # Отредактируйте .learning/workspaces/agents-rules/AGENTS.md
   python scripts/verify.py --exercise agents-rules --workspace .learning/workspaces/agents-rules
   ```
3. Убедитесь, что независимый скрипт проверки `examples/agents-rules/test.py` подтверждает отсутствие секретов, наличие обязательных разделов и относительных путей.

## Самопроверка

<details>
<summary>Подсказка и критерии самопроверки</summary>

- Убедитесь, что в файле присутствуют понятные заголовки: назначение, команды, правила.
- Проверьте, что пути файлов указаны относительно корня каталога (например, `tests/`, а не `C:/project/tests/`).
- Критерий успешности: `python scripts/verify.py --exercise agents-rules` возвращает `PASS`. Все локальные тесты завершаются успешно.

</details>
