# config.toml: реальные ключи и приоритеты

## Чему вы научитесь

Объяснить приоритет настроек и проверить конфигурацию установленного CLI.

## Что нужно перед началом

Сначала пройдите: [Начало: что изучаем и как проверяем результат](../01-start/overview.md). Учебные файлы входят в поставку. Установленные программы и доступ к модели требуются только для соответствующей практики.

Конфигурация задаёт параметры клиента, а не текст урока. Минимальный пример расположен в `examples/config/minimal.config.toml`; не копируйте его поверх существующего профиля без просмотра.

```toml
approval_policy = "on-request"
sandbox_mode = "read-only"
web_search = "disabled"
```

Модель задаётся строковым ключом `model`, а не таблицей `[model]` с придуманным названием. Доступное имя зависит от провайдера. Разовый параметр можно передать через `-c key=value`; учитывайте TOML-кавычки внутри аргумента.

В текущей документации `--profile NAME` выбирает дополнительный файл `NAME.config.toml` в `CODEX_HOME`. Не переносите старые примеры `[profiles.NAME]` без сверки версии. Различайте системные ограничения, пользовательскую конфигурацию и доверенные настройки проекта: более специфичная настройка не обязательно может отменить административное ограничение.

## Практика

Скопируйте минимальный пример в отдельный учебный профиль, запустите `codex --strict-config` и изучите эффективную конфигурацию через `/debug-config`. Затем добавьте заведомо неизвестное поле только в учебную копию: строгая проверка должна его обнаружить. Сохраните оба результата без секретов.

Парсер TOML подтверждает только синтаксис. `scripts/check_project.py config` проверяет ограниченный контракт поставляемых примеров, не всю официальную схему и не фактическое поведение CLI.

## Что считается выполнением в Codex

Без модели доступны весь текст, вопросы, исходники и локальные тесты. Они не подтверждают работу CLI. Для практики сохраните версию `codex --version`, модель, провайдера и обезличенный результат реального запуска. Отметку можно внести через `scripts/progress.py` после проверки, согласно [правилам валидации](../reference/validation.md). Самоотчёт ученика не заменяет выпускные доказательства проекта.
