# Длительная задача: /plan и /goal

## Чему вы научитесь

Преобразовать согласованный план в ограниченную цель с проверяемым условием завершения.

## Что нужно перед началом

Сначала пройдите: [Ограниченное исправление: запрос, diff и тест](small-fix.md). Учебные файлы входят в поставку. Установленные программы и доступ к модели требуются только для соответствующей практики.

**`/goal` есть в целевой версии курса.** Это не самодельный менеджер задач и не функция нашего навыка `$learn`. Режим позволяет связать дальнейшую работу чата с явной целью. Начинать лучше с короткого плана и проверяемого результата, а не с просьбы «доведи всё до идеала».

## Сначала согласуйте границы

В подготовленной рабочей папке `small-fix` сформулируйте задачу через `/plan`. Уточните разрешённые файлы, команды проверки и действия, которые требуют отдельного согласования. План не заменяет исполнения. Цель не даёт дополнительных прав и не разрешает публикацию, установку зависимостей или изменение тестов.

```text
/plan
Составь план исправления discount.py. Не меняй тесты и не обращайся к сети.
```

Когда план понятен, задайте цель:

```text
/goal Исправить discount.py: тесты независимого проверяющего скрипта проходят, тесты не изменены, diff ограничен этим файлом. Не устанавливать зависимости и не публиковать изменения.
```

## Управление целью

| Ввод | Назначение |
| --- | --- |
| `/goal` | Посмотреть текущую цель и её состояние |
| `/goal edit` | Изменить формулировку |
| `/goal pause` | Приостановить работу по цели |
| `/goal resume` | Продолжить работу по цели |
| `/goal clear` | Убрать текущую цель |

Пауза, очистка цели и восстановление файлов — разные действия. Не предполагается, что `/goal clear` отменит сделанные изменения. Для возврата файлов нужен отдельный проверенный процесс с Git. Если задача заблокирована доступом, отсутствие необходимых прав не обходят ради завершения цели.

## Практика

Сохраните исходный diff. Задайте измеримую цель, проверьте её через `/goal`, приостановите, уточните и продолжите. После завершения самостоятельно запустите тест и сопоставьте изменённые файлы с ограничениями. Наконец очистите цель и снова проверьте статус. В протоколе должны быть фактические состояния и результат проверки, а не только копия команды.

Если короткая задача завершилась раньше паузы, повторите управление на другой безопасной многошаговой задаче. Не добавляйте искусственные задержки, бесконечные циклы или опасные операции. При отсутствии модели выполните офлайн-часть: составьте цель, критерии успеха и перечень подтверждений. Реальный сценарий `LIVE-GOAL` остаётся `BLOCKED`, а не `PASS`.

## Типичные ошибки

«Сделай хорошо» не содержит условия остановки. «Продолжай любой ценой» не задаёт безопасных границ. Успешный тест не доказывает, что запрещённые файлы не менялись: нужны и тест, и diff. Длинная сессия также не заменяет независимую проверку результата.

## Что считается выполнением в Codex

Без модели доступны весь текст, вопросы, исходники и локальные тесты. Они не подтверждают работу CLI. Для практики сохраните версию `codex --version`, модель, провайдера и обезличенный результат реального запуска. Отметку можно внести через `scripts/progress.py` после проверки, согласно [правилам валидации](../reference/validation.md). Самоотчёт ученика не заменяет выпускные доказательства проекта.
