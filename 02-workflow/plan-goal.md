# Длительная задача: /plan и /goal

## Чему вы научитесь

Научитесь формулировать и контролировать длительные инженерные задачи с помощью встроенного механизма `/goal` в Codex CLI 0.160.0, преобразовывать пошаговый план в управляемую автономную цель, использовать команды приостановки (`/goal pause`) и возобновления (`/goal resume`), а также фиксировать однозначные условия завершения без риска зацикливания или потери контроля над агентом.

## Что нужно перед началом

1. Изучите материал урока [Планирование в /plan: от требований к шагам](planning.md).
2. Подготовьте изолированное рабочее пространство `small-fix`.
3. Понимание того, что `/goal` — это встроенная возможность Codex CLI (определённая в кодовой базе `slash_command.rs`), а не самодельный скрипт.

## Схема процесса

Сквозной процесс постановки, контроля и достижения цели в Codex CLI:

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. Декомпозиция: /plan                                      │
│    - Анализ требований и формулирование шагов               │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│ 2. Фиксация цели: /goal <Критерии завершения>              │
│    - Формулирование целевого состояния (DoD)                │
│    - Ограничение границ файлов и запрет опасных действий    │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│ 3. Автономный цикл исполнения (Execution Loop)              │
│    ├── Шаг 1 -> Проверка -> Шаг 2 -> Проверка               │
│    ├── Управление ходом:                                    │
│    │   /goal pause  -> Приостановка (инспекция diff)        │
│    │   /goal resume -> Возобновление работы                 │
│    │   /goal edit   -> Корректировка формулировки цели      │
│    └── Проверка условия остановки                           │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│ 4. Приёмка и завершение                                     │
│    - Независимый тест: python test.py (PASS)                │
│    - Контроль diff: изменён строго целевой файл             │
│    - Очистка цели: /goal clear                              │
└─────────────────────────────────────────────────────────────┘
```

## Команды и параметры

Встроенные команды управления целями в сессии TUI:

```text
/goal <описание цели>   # Установка активной цели с условиями остановки
/goal                   # Просмотр текущей формулировки цели и её статуса
/goal pause             # Временная приостановка выполнения для инспекции
/goal resume            # Возобновление работы по приостановленной цели
/goal edit              # Редактирование формулировки цели на лету
/goal clear             # Завершение и снятие текущей цели из сессии
```

## Разбор примера

Рассмотрим полный сценарий работы с целью для исправления модуля `discount.py`:

1. Пользователь формулирует цель с явным условием остановки:
   ```text
   /goal Исправить discount.py:
   1. Независимый тест examples/small-fix/test.py проходит успешно.
   2. Сам тест test.py не изменён.
   3. Diff ограничен исключительно файлом discount.py.
   4. Не устанавливать внешние пакеты и не делать git commit/push.
   ```
2. В процессе работы пользователь решает проверить промежуточное состояние:
   ```text
   /goal pause
   ```
   Агент останавливает цикл после завершения текущего инструмента.
3. Пользователь проверяет промежуточный diff в терминале:
   ```bash
   git diff discount.py
   ```
4. Если всё в порядке, работа возобновляется:
   ```text
   /goal resume
   ```
5. После успешного прохождения тестов цель снимается:
   ```text
   /goal clear
   ```

## Ограничения и безопасность

1. **Команда `/goal clear` не откатывает файлы**: снятие цели очищает только внутреннее состояние целеуказания агента. Все изменения, уже внесённые на диск, остаются в рабочем дереве Git. Для отката используйте `git restore`.
2. **Обязательное условие остановки**: цель без чёткого условия завершения (например: «Сделай систему максимально надёжной») может привести к бесконечным циклическим правкам и перерасходу токенов.
3. **Безопасность прав доступа**: режим `/goal` не даёт агенту дополнительных прав в обход песочницы (`sandbox_mode`). Если операция заблокирована правилами безопасности, агент не имеет права обходить блокировку ради достижения цели.

## Ошибки и диагностика

| Симптом | Причина | Способ диагностики и решения |
|---|---|---|
| Агент бесконечно перебирает варианты правок | Недостижимый или противоречивый критерий цели. | Выполните `/goal pause` и скорректируйте формулировку через `/goal edit`. |
| Ошибка `Unknown command /goal` в командной строке ОС | Попытка ввода команды в bash/powershell. | Команда `/goal` вводится строго внутри интерактивного TUI Codex CLI. |
| Агент заявил о достижении цели, но тест падает | Модель галлюцинировала успех без запуска реальной проверки. | Всегда проверяйте результат независимой командой: `python scripts/verify.py ...`. |

## Практика

1. Подготовьте учебное пространство:
   ```bash
   python scripts/verify.py --prepare small-fix
   ```
2. Сформулируйте измеримую цель для задачи `small-fix` с 4 обязательными критериями (поведение, неизменность тестов, минимальный diff, запрет сети).
3. Проверьте статус цели через `/goal`, смоделируйте паузу `/goal pause` и завершение через `/goal clear`.

## Самопроверка

Критерии завершения:
1. Вы знаете все команды управления целью (`/goal`, `/goal pause`, `/goal resume`, `/goal edit`, `/goal clear`).
2. Вы понимаете, что `/goal clear` не заменяет команды Git для отката изменений.
3. Сформулирована корректная цель с проверяемым условием остановки.

<details>
<summary>Контрольные вопросы для самопроверки</summary>

- **Вопрос**: Что произойдёт, если во время выполнения `/goal` модель попытается изменить файл тестов при наличии явного запрета?
- **Ответ**: Это является прямым нарушением контракта задачи; изменения тестов должны быть немедленно отклонены пользователем при подтверждении или откатаны через Git.
- **Вопрос**: В чём отличие `/goal pause` от завершения сессии?
- **Ответ**: Пауза временно замораживает исполнение цикла для инспекции человеком, сохраняя цель и контекст активными в памяти сессии.

</details>
