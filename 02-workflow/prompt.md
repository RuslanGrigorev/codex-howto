# Постановка задачи с проверяемым результатом

## Чему вы научитесь

Описывать результат, ограничения и критерии завершения вместо неопределённого «сделай лучше».

## Что нужно перед началом

Учебная папка small-fix и понимание её основной функции.

## Как это работает

Запрос удобно разделить на четыре части: наблюдаемая проблема, желаемое поведение, допустимая область изменений и способ проверки. Это не специальный синтаксис Codex, а форма постановки учебной задачи.

Критерий должен быть проверяемым независимо от отчёта модели. «Код красивый» — оценка; «для нулевой скидки возвращается исходная цена, тесты не изменены» — проверка. Когда есть риск нескольких трактовок, сначала согласуйте пример входа и ожидаемого выхода.

Контекст должен быть достаточным, но не избыточным. Не прикладывайте весь домашний каталог. Указывайте существующие файлы, а ограничения формулируйте прямо: без сети, без установки пакетов, без публикации изменений.

## Разобранный пример

```text
Проблема: расчёт скидки ошибается на границах.
Результат: исправить discount.py для согласованных входов.
Границы: не изменять независимый тест и другие файлы;
не устанавливать пакеты, не обращаться к сети, не делать commit/push.
Проверка: сначала показать план и ожидаемые случаи, затем diff и результат теста.
Если требования неоднозначны — задать вопрос до изменения.
```

Это обычный запрос, не новая slash-команда.

## Самостоятельная практика

Перепишите просьбу «сделай проект надёжным» для одной функции. Добавьте два конкретных примера и одно запрещённое действие. Дайте запрос Codex сначала только для обсуждения, не для исполнения.

Попросите перечислить, чего всё ещё не хватает. Уточните не более одного спорного условия за раз.

## Ожидаемый результат

Задача допускает независимое решение «выполнено/не выполнено». У неё есть ограниченная область файлов и понятный способ проверки.

## Разбор решения

<details>
<summary>Показать после самостоятельной попытки</summary>

Удачная формулировка не требует от модели угадать предпочтения. Например: «Для скидки 0.0 вернуть исходную цену; для 1.0 вернуть 0; при скидке вне диапазона [0.0, 1.0] вызывать ValueError». Спорное поведение за пределами диапазона нужно уточнить заранее, а не объявить очевидным после исправления.

</details>

## Типовые ошибки

Требовать улучшить всё сразу; запрещать вопросы при неопределённых условиях; выдавать зелёный тест за доказательство сохранности остальных файлов.

## Проверка знаний

Ответьте на вопросы внизу страницы. В исходном репозитории они доступны в [файле вопросов](prompt.quiz.json). Правильные ответы подтверждают понимание; выполнение практики фиксируется отдельно.

## Источники и доступность

Практика требует установленного Codex и доступной выбранной модели. Без модели выполните разбор примера и подготовьте ожидаемый результат; реальный запуск остаётся невыполненным. Целевая версия — 0.160.0. Документальная сверка: 2026-10-05; она не заменяет протокол запуска на вашей ОС.
