# Исследование проекта без изменения файлов

## Чему вы научитесь

Получать карту незнакомого проекта и проверять утверждения агента по конкретным файлам.

## Что нужно перед началом

Пройдите подготовку среды. Работайте с учебным `small-fix`, а не с неизвестным репозиторием с личными данными.

## Как это работает

Хорошее исследование отвечает на вопросы: где точка входа, где поведение, где тест и какой результат считается правильным. Просьба «изучи проект» без границ часто приводит к длинному пересказу без полезного следующего шага.

Попросите только чтение, перечислите нужные вопросы и ограничьте объём ответа. Затем проверьте названные пути вручную. Агент может убедительно сослаться на несуществующий тест; путь и команда должны быть проверяемыми.

Режим чтения помогает сохранить исходную точку, но текстовое обещание «не менять» не заменяет настройку прав. После исследования ещё раз сравните файлы. Полученный список — карта для следующего действия, а не разрешение переписать проект.

## Разобранный пример

```bash
python scripts/verify.py --prepare small-fix
codex --cd .learning/workspaces/small-fix --sandbox read-only --ask-for-approval on-request
```

В Codex:

```text
Исследуй только текущую папку. Не изменяй файлы.
Назови основную функцию, её входы и граничные случаи.
Для каждого вывода укажи файл. Не предлагай новую архитектуру.
```

В этом упражнении независимый тест расположен вне рабочей папки: его путь дан в уроке об исправлении, а не должен быть выдуман агентом.

## Самостоятельная практика

Получите карту из пяти пунктов: цель кода, входы, выходы, граничные случаи, неизвестные детали. Откройте каждый названный файл. Если агент сделал предположение, попросите пометить его именно как предположение.

В конце сформулируйте одну небольшую задачу для следующего урока. Не переходите к исправлению в этой сессии.

## Ожидаемый результат

Короткая карта с существующими путями; нет изменений исходников и необоснованных утверждений о пройденных тестах.

## Разбор решения

<details>
<summary>Показать после самостоятельной попытки</summary>

Пример хорошего вывода: «Функция считает скидку; входы — цена и доля скидки; границы 0.0 и 1.0 требуют проверки; тест не найден внутри рабочей папки». Последняя часть не ошибка: агент должен честно обозначить границу доступного контекста, а не придумать успешную проверку.

</details>

## Типовые ошибки

Начинать рефакторинг вместо исследования; верить несуществующим путям; считать отсутствие теста в рабочей папке отсутствием тестов в курсе.

## Проверка знаний

Ответьте на вопросы внизу страницы. В исходном репозитории они доступны в [файле вопросов](inspect.quiz.json). Правильные ответы подтверждают понимание; выполнение практики фиксируется отдельно.
