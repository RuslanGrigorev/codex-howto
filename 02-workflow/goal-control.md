# Управление /goal: пауза, изменение и завершение

## Чему вы научитесь

Научитесь осуществлять оперативное управление активными целями в Codex CLI 0.160.0 через команды `/goal pause`, `/goal edit`, `/goal resume` и `/goal clear`, понимать различия между состоянием цели в диалоге и состоянием файлов на диске, безопасно останавливать зациклившиеся процессы и фиксировать результаты работы.

## Что нужно перед началом

1. Изучите основы постановки долгосрочных целей из урока [Длительная задача: /plan и /goal](plan-goal.md).
2. Подготовьте изолированную учебную директорию.
3. Понимание того, что очистка цели (`/goal clear`) не является аналогом команды `git restore`.

## Схема процесса

Конечный автомат (State Machine) состояний цели в сессии Codex CLI:

```text
       ┌────────────────────────┐
       │     Нет цели (None)    │
       └───────────┬────────────┘
                   │ /goal <текст>
                   ▼
       ┌────────────────────────┐
   ┌──►│     Активна (Active)   │◄──┐
   │   └───────────┬────────────┘   │
   │               │                │
   │ /goal resume  │ /goal pause    │ /goal edit
   │               ▼                │
   │   ┌────────────────────────┐   │
   └───┤  На паузе (Paused)     ├───┘
       └───────────┬────────────┘
                   │ /goal clear
                   ▼
       ┌────────────────────────┐
       │   Завершена (Cleared)  │
       └────────────────────────┘
```

## Команды и параметры

Команды управления жизненным циклом цели:

```text
/goal           # Отображает текущее состояние автомата и текст цели
/goal pause     # Переход из состояния Active в Paused (заморозка исполнения)
/goal edit      # Редактирование формулировки критериев завершения
/goal resume    # Переход из Paused обратно в Active
/goal clear     # Переход в состояние Cleared (цель удалена из сессии)
```

Инспекция состояния файлов после остановки:
```bash
# Проверка изменённых файлов на диске
git status --short
git diff
```

## Разбор примера

Рассмотрим пошаговую сессию управления целью при возникновении непредвиденной блокировки:

1. Установлена цель:
   ```text
   /goal Реализовать модуль кэширования в cache.py и покрыть тестами
   ```
2. Модель сообщает, что для реализации требуется библиотека `redis`, которой нет в окружении.
3. Чтобы предотвратить попытку модели скачать пакет из сети или впасть в бесконечный цикл ошибок, пользователь ставит цель на паузу:
   ```text
   /goal pause
   ```
4. Пользователь уточняет формулировку через `/goal edit`:
   ```text
   /goal edit Реализовать модуль кэширования в cache.py с использованием встроенного словаря (in-memory dict) без сторонних библиотек.
   ```
5. Пользователь возобновляет работу:
   ```text
   /goal resume
   ```
6. Модель успешно завершает задачу в рамках скорректированных условий, после чего пользователь очищает цель:
   ```text
   /goal clear
   ```

## Ограничения и безопасность

1. **Разделение сущностей диалога и файлов**: команда `/goal clear` сбрасывает статус задачи у модели, но оставляет все модифицированные файлы на диске нетронутыми. Если вы хотите полностью отказаться от результатов работы модели, выполните `git restore .`.
2. **Не расширяйте права из-за тупика**: если цель заблокирована нехваткой прав песочницы (например, попытка записи в `/etc`), правильным решением является корректировка цели, а не запуск клиента с опасным флагом `--danger-full-access`.
3. **Контроль зацикливаний**: если модель делает более 3 попыток исправить один и тот же тест без прогресса, поставьте цель на паузу через `/goal pause` и вмешайтесь лично.

## Ошибки и диагностика

| Ситуация / Ошибка | Причина | Способ решения |
|---|---|---|
| `/goal resume` выдаёт ошибку «No paused goal» | Цель уже была завершена или очищена через `/goal clear`. | Проверьте статус через `/goal` и при необходимости задайте цель заново. |
| Ожидание, что `/goal clear` вернёт исходный код | Смешение концепций цели агента и истории Git. | Для отката кода используйте `git restore <файл>` или `git checkout`. |
| Модель не реагирует на `/goal pause` во время долгого шага | Команда поставлена в очередь и применится после завершения текущего инструмента. | Если инструмент завис, используйте `Ctrl+C` или `/stop`. |

## Практика

1. Откройте сессию Codex в учебном пространстве.
2. Задайте простую цель: `/goal Назови 3 правила оформления кода из AGENTS.md`.
3. Последовательно проверьте состояния:
   - Проверьте `/goal`.
   - Вызовите `/goal pause`.
   - Измените условие через `/goal edit`.
   - Возобновите через `/goal resume`.
   - Завершите через `/goal clear`.
4. Зафиксируйте полученные выводы в протоколе практики.

## Самопроверка

Критерии завершения:
1. Вы понимаете схему переходов между 4 состояниями цели.
2. Вы умеете приостанавливать агента при отклонении от намеченного курса.
3. Вы разделяете отмену цели в чате и откат изменений в репозитории Git.

<details>
<summary>Контрольные вопросы для самопроверки</summary>

- **Вопрос**: В каком состоянии цель может быть отредактирована через `/goal edit`?
- **Ответ**: Редактирование доступно как в активном состоянии, так и в состоянии паузы (`Paused`), что позволяет скорректировать требования до возобновления генерации.
- **Вопрос**: Что нужно сделать, если после очистки цели `/goal clear` необходимо отменить все сделанные агентом изменения в файлах?
- **Ответ**: Выполнить команду отката Git: `git restore .` или `git checkout -- .`.

</details>
