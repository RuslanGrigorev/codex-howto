# Ревью изменений и независимая проверка

## Чему вы научитесь

Научитесь проводить всесторонний аудит изменений (Code Review) с помощью Codex CLI 0.160.0, использовать команду `/review` и утилиту `codex review`, анализировать сгенерированный diff с помощью Git, выявлять скрытые регрессии и побочные эффекты, а также совмещать рецензирование языковой моделью с детерминированными тестами.

## Что нужно перед началом

1. Изучите основы рабочего цикла из урока [Ограниченное исправление: запрос, diff и тест](small-fix.md).
2. Подготовьте изолированную учебную ветку в репозитории с небольшим изменением.
3. Понимание разницы между эвристическим анализом кода моделью и точным исполнением автоматических тестов.

## Схема процесса

Двухуровневый процесс верификации изменений перед коммитом:

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. Анализ изменений в Git (Git Diff Inspection)            │
│    - git diff --stat (объём затронутых файлов и строк)      │
│    - git diff (детальная инспекция каждого блока изменений) │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│ 2. Семантическое ревью моделью (/review)                    │
│    - Аудит граничных условий и обработки исключений         │
│    - Проверка на утечки секретов и приватных данных         │
│    - Контроль соблюдения архитектурных стандартов AGENTS.md │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│ 3. Независимый детерминированный тест (Test Verification)   │
│    - Запуск независимого скрипта pytest / test.py           │
│    - Код завершения 0: PASS / Код завершения 1: FAIL        │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│ 4. Итоговое решение (Verdict)                               │
│    - APPROVE: diff минимален, тесты зелены, замечаний нет   │
│    - CHANGES_REQUESTED: найден дефект, требуется доработка   │
└─────────────────────────────────────────────────────────────┘
```

## Команды и параметры

Команды проведения ревью в терминале и сессии TUI:

```bash
# Инспекция подготовленного diff в терминале Git
git diff --stat
git diff

# Неинтерактивный вызов процедуры ревью изменений текущей ветки
codex review --help
codex review

# Внутри интерактивной сессии TUI:
/diff       # Просмотр текущего diff прямо в интерфейсе клиента
/review     # Запуск специализированного субагента для ревью
```

## Разбор примера

Рассмотрим пример ревью diff с дефектом в обработке границы скидки:

1. В ветке сделано исправление:
   ```diff
   --- a/discount.py
   +++ b/discount.py
   @@ -1,3 +1,3 @@
    def apply_discount(price: float, discount: float) -> float:
   -    return price * discount
   +    if discount > 0 and discount < 1:
   +        return price * (1.0 - discount)
   +    return price
   ```
2. Команда ревью:
   ```text
   /review Проверь корректность обработки границ 0.0 и 1.0 в discount.py
   ```
3. Модель указывает на дефект:
   ```text
   Замечание к строке 2:
   Условие `discount > 0 and discount < 1` является строгим.
   Для скидки 0.0 (скидка 0%) и 1.0 (скидка 100%) функция вернёт исходную цену вместо 0.0.
   Рекомендация: используйте нестрогое сравнение `0.0 <= discount <= 1.0` и при discount == 1.0 возвращайте 0.0.
   ```
4. Разработчик вносит правку, запускает независимый тест и получает `PASS`.

## Ограничения и безопасность

1. **Ревью моделью не заменяет тесты**: модель может пропустить тонкий баг переполнения или состояние гонки. Зелёный вердикт ревьюера ценен только в сочетании с успешно пройденными детерминированными тестами.
2. **Опасность деструктивных команд при отмене**: если при ревью найдены критические замечания, не используйте команду `git reset --hard` в основном репозитории, чтобы случайно не уничтожить незакоммиченные наработки. Используйте точечный откат конкретного файла: `git restore <file>`.
3. **Безопасность диффов**: перед отправкой diff на ревью убедитесь, что в него случайно не попали служебные файлы с токенами (`.env`, `auth.json`, ключи SSH).

## Ошибки и диагностика

| Симптом | Причина | Способ решения |
|---|---|---|
| Модель выдаёт поверхностный ответ («Код выглядит хорошо») | В запросе не были указаны критерии ревью. | Задайте чёткий чек-лист: «Проверь граничные условия, обработку ошибок и минимальность diff». |
| `codex review` не видит изменений | В репозитории отсутствуют незакоммиченные правки. | Сделайте правку или укажите диапазон коммитов: `codex review main..HEAD`. |
| Изменения затрагивают файлы тестов | Модель скорректировала тесты под неверную логику. | Проверьте `git diff --stat`: список изменённых файлов должен содержать только файлы реализации. |

## Практика

1. В учебном пространстве `small-fix` внесите намеренную ошибку в функцию `discount.py` (например, строгое сравнение `< 1.0` вместо `<= 1.0`).
2. Проинспектируйте diff в терминале:
   ```bash
   git diff discount.py
   ```
3. Запросите ревью через сессию Codex или проверьте код независимым тестом `examples/small-fix/test.py`.
4. Исправьте ошибку и убедитесь, что тест проходит успешно.

## Самопроверка

Критерии завершения:
1. Вы умеете инспектировать diff через `git diff --stat` и команду клиента `/diff`.
2. Вы понимаете, почему ревью языковой моделью должно всегда дополняться независимым запуском тестов.
3. Вы устранили тестовую ошибку без использования деструктивных команд Git.
