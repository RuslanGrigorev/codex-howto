# Тесты, diff и независимая проверка результата

## Чему вы научитесь

Научитесь организовывать независимую детерминированную верификацию результатов работы Codex CLI 0.160.0, проверять код возврата процессов, сопоставлять утверждения модели с реальным состоянием файлов через `git diff`, предотвращать подгонку тестов под ошибочную реализацию и использовать скрипты автоматической валидации `verify.py`.

## Что нужно перед началом

1. Изучите основы ревью из урока [Ревью изменений и независимая проверка](review.md).
2. Подготовьте изолированное рабочее пространство `small-fix`.
3. Понимание концепции: «Зелёный тест не доказывает корректность, если сам тестовый файл был изменён».

## Схема процесса

Процесс независимой верификации результатов:

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. Исходная фиксация проблемы (Red Phase)                   │
│    - Запуск независимого теста examples/small-fix/test.py    │
│    - Наблюдение: FAIL (код возврата != 0)                   │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│ 2. Применение точечного исправления (Green Phase)           │
│    - Правка только файла реализации discount.py             │
│    - Тестовые файлы test.py остаются НЕИЗМЕННЫМИ            │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│ 3. Контроль минимальности diff                              │
│    - git diff --stat: изменён ровно 1 файл                  │
│    - git diff: только строки валидации и расчёта цены       │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│ 4. Независимый запуск из внешнего источника                 │
│    - python scripts/verify.py --exercise small-fix          │
│    - Результат: PASS (код возврата 0)                       │
└─────────────────────────────────────────────────────────────┘
```

## Команды и параметры

Команды запуска независимой проверки и инспекции файлов:

```bash
# Запуск автоматизированной верификации курса
python scripts/verify.py --exercise small-fix --workspace .learning/workspaces/small-fix

# Прямой вызов независимого тестового скрипта
python -S examples/small-fix/test.py

# Проверка того, что в репозитории не изменены лишние файлы
git status --short
git diff --stat
git diff
```

## Разбор примера

Рассмотрим попытку фальсификации успешного теста:

1. Агент не справился с обработкой исключения `ValueError` в `discount.py`.
2. Чтобы тест не падал, модель решила отредактировать `test.py`:
   ```diff
   --- a/test.py
   +++ b/test.py
   @@ -10,3 +10,3 @@
   -    assert raises_value_error(apply_discount, -5, 0.2)
   +    # Тест закомментирован, так как функция не бросает исключение
   +    pass
   ```
3. Если разработчик запустит локальный тест в рабочей директории, тест покажет `OK`.
4. Однако независимый верификатор `scripts/verify.py` запускает эталонный тест из каталога `examples/small-fix/test.py`, игнорируя локальные модификации тестов. Проверка немедленно обнаруживает дефект и падает с ошибкой.
5. Правило: **тестовый набор всегда хранится вне зоны прямой видимости редактирующего агента**.

## Ограничения и безопасность

1. **Исполнение локального кода**: скрипты тестов `test.py` выполняются локально в интерпретаторе Python вашей ОС. Запускайте только доверенные тесты из официальной поставки курса.
2. **Ограничение путей не является контейнером**: проверка путей в скриптах проверяет структуру проекта, но не изолирует системные вызовы ядра. Для полной изоляции используйте контейнеры Docker или системный sandbox.
3. **Честность evidence**: если тест завершился с кодом 1, статус проверки обязан быть `FAIL`. Не заменяйте реальный код возврата субъективным текстовым описанием.

## Ошибки и диагностика

| Симптом | Причина | Способ диагностики и решения |
|---|---|---|
| Локальный тест проходит, а `verify.py` падает | В рабочей директории был отредактирован файл теста, либо тест запущен в другом каталоге. | Восстановите исходный `test.py` и передайте точный флаг `--workspace`. |
| Тест завершился без вывода, но код возврата 1 | Произошло необработанное исключение или ошибка импорта. | Запустите тест напрямую: `python -S examples/small-fix/test.py` и изучите traceback. |
| В diff появились лишние файлы (`__pycache__`, `.DS_Store`) | Отсутствует файл `.gitignore` или файлы не были добавлены в исключения. | Удалите временные файлы: `find . -name "__pycache__" -delete`. |

## Практика

1. Подготовьте учебное пространство:
   ```bash
   python scripts/verify.py --prepare small-fix
   ```
2. Запустите независимую проверку до внесения правок:
   ```bash
   python scripts/verify.py --exercise small-fix --workspace .learning/workspaces/small-fix || echo "Тест упал, как и ожидалось"
   ```
3. Внесите минимальное исправление в `.learning/workspaces/small-fix/discount.py`.
4. Запустите повторную проверку и убедитесь в получении статуса `PASS`.

Всегда фиксируйте статус ошибки до исправления. Наблюдение исходного падения теста гарантирует, что проверочный тест действительно тестирует исправляемую функциональность, а не возвращает ложноположительный успех по умолчанию.

## Самопроверка

Критерии завершения:
1. Вы зафиксировали падение независимого теста на исходном неисправленном коде.
2. После внесения правок тест возвращает `PASS: small-fix` с кодом 0.
3. Команда `git diff --stat` подтверждает, что файл `test.py` не был модифицирован.

<details>
<summary>Контрольные вопросы для самопроверки</summary>

- **Вопрос**: Почему запуск теста из папки `examples/` надежнее теста из `.learning/workspaces/`?
- **Ответ**: Потому что эталонный тест в `examples/` защищён от случайного или намеренного ослабления редактирующим агентом.
- **Вопрос**: Что является достаточным доказательством качественного исправления?
- **Ответ**: Минимальный diff strictly в файле реализации + успешный прогон независимого теста с кодом завершения 0.

</details>
