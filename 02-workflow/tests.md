# Тесты, diff и независимая проверка результата

## Чему вы научитесь

Проверять исправление по тесту и фактическим изменениям, а не по сообщению «готово».

## Что нужно перед началом

Подготовленное упражнение small-fix. Для Git-команд используйте собственный учебный репозиторий.

## Как это работает

Две проверки отвечают на разные вопросы. Тест показывает, выполняются ли конкретные условия. Diff показывает, какие изменения были внесены. Зелёный тест не объясняет, не удалил ли агент неудобную проверку или не изменил ли посторонний файл.

Независимый тест хранится вне редактируемой папки упражнения. Так агент не может случайно принять свой же ослабленный тест за доказательство. Но это не песочница: проверяемый Python-код всё равно исполняется на вашей машине.

В отчёте нужны команда, код завершения, краткий вывод и область diff. Отдельно укажите непроверенное поведение. Фраза «должно работать» не равна «проверено».

## Разобранный пример

Из корня исходников:

```bash
python scripts/verify.py --exercise small-fix --workspace .learning/workspaces/small-fix
```

В Git-копии проекта дополнительно:

```bash
git status --short
git diff --stat
git diff --check
git diff
```

В исходном ZIP без `.git` Git-команды не работают; это ожидаемо. Сравнивайте рабочий файл с исходным вручную или используйте заранее подготовленный учебный репозиторий.

## Самостоятельная практика

Сначала запустите проверку на неизменённой заготовке и запишите ожидаемую ошибку. Исправьте функцию, повторите ту же команду. Убедитесь, что независимый тест не редактировался.

Объясните каждый изменённый участок. Если изменение не относится к задаче, не принимайте его только потому, что тесты зелёные.

## Ожидаемый результат

В отчёте есть неуспешная исходная проверка и успешная повторная; изменение ограничено согласованными файлами.

## Подсказка

<details>
<summary>Показать подсказку</summary>

Проверьте, что команда после исправления та же самая. Иногда «успех» получается из-за запуска другого теста или другого каталога.

</details>

## Разбор решения

<details>
<summary>Показать после самостоятельной попытки</summary>

Достаточный результат: заготовка не прошла; после правки независимый тест завершился с нулевым кодом; тестовый файл не изменён; diff соответствует задаче. Если Git отсутствует, это указывают отдельно, а не прикладывают вымышленный вывод git diff.

</details>

## Типовые ошибки

Менять тест ради успеха; запускать другой файл; игнорировать ненулевой код процесса; утверждать полную корректность по одному набору случаев.
