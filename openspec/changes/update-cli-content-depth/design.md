# Архитектурные решения для глубины курса

## Контекст

Основа — существующие `course.json`, `sources.json`, `validation.json`, Python/Jinja/Markdown и автономный сайт. Предшествующий аудит: `docs/superpowers/plans/2026-10-05-codex-cli-coverage-audit-and-plan.md`. Действующие specs продолжают действовать. Этот change не утверждает, что найденные пробелы уже исправлены.

## Зафиксированные решения

### ADR-CD-01 Единый реестр и конечная область

`course.json` остаётся каталогом обучения, `sources.json` — реестром источников и покрытия. Новый отдельный изменяемый каталог возможностей не вводится. Допускаются поставляемые неизменяемые upstream-фикстуры в `reference/upstream/` с происхождением, лицензией и SHA-256, но статусы, связи и классификация хранятся только в `sources.json`.

T01 снимает **один** baseline 0.160.0: справка публичных подкоманд/флагов, исходный статический перечень slash-команд, известные динамические команды, публичные feature flags и все достижимые поля закреплённой схемы конфигурации. Вложенные ключи нормализуются в dotted paths, пользовательские имена — в `*`; внутреннее определение без пути из корня схемы не считается самостоятельной настройкой. Ссылки `$ref` и рекурсивные типы не должны порождать бесконечный обход.

Официальные тематические страницы ограничены 20 областями аудита и зарегистрированными источниками плюс страницами SDK, app-server, GitHub Action, environment variables и CLI customization. Полный crawl ChatGPT Learn запрещён. Применимость к CLI устанавливается отдельно от наличия ссылки. Baseline фиксируется по итогам T01; новые релизы и дополнительные темы после этого — follow-up, не расширение текущего контракта.

Каждый пункт получает ровно одну категорию: `core`, `advanced`, `reference_only`, `historical_removed`, `out_of_scope`. У `out_of_scope` обязательно обоснование. Действующая публичная CLI-возможность не может исключаться только из-за отсутствия модели, доступа или бюджета. У `reference_only` есть локальная карточка синтаксиса, применимости, результата и риска, а не пустая ссылка. Детальные how-to обязательны для конечного перечня сценариев в `verification.yaml`; все прочие применимые поля получают полноценный справочный пункт.

### ADR-CD-02 Качество важнее числа страниц

Все исходные 62 ID сохраняются. Десять модулей не переименовываются ради внешнего образца. Новые уроки допускаются только для результатов SDK, remote и cloud, которых нет в самостоятельном материале; прочие углубляются на месте. ID новых уроков задаются до их регистрации и не зависят от позиции.

Каждый существующий урок получает содержательные цель, предпосылки, механизм, разобранный пример, самостоятельное задание, подсказку, разбор, наблюдаемый критерий и источник. Нельзя засчитать формальный набор заголовков. Квота слов не вводится. Проверяющий оценивает, может ли ученик выполнить задание без догадки и внешнего how-to. Для темы без исполняемого клиента достаточна законченная локальная аналитическая практика, но она не заменяет live-сценарий.

### ADR-CD-03 Схемы без сетевого runtime

Двенадцать фиксированных схем размещаются в `reference/diagrams/`: исходник `.mmd`, локальный `.svg` и описание. Выбранная архитектура — предварительно подготовленные SVG, не Mermaid через CDN и не выполнение рендера в браузере ученика. Девелоперский renderer допустим только как отдельно закреплённая зависимость подготовки; обычные offline-проверки используют уже поставленные SVG. Ручное SVG допустимо при редакционной проверке соответствия исходнику.

SVG не содержит script, foreignObject, обработчики событий, внешние шрифты/ресурсы или внешние ссылки загрузки. Файл копируется в автономный пакет. В уроке есть текстовый эквивалент и объяснение всех значимых узлов/стрелок. Без JS схема и объяснение читаются.

### ADR-CD-04 Реальные примеры и честные стенды

Девять существующих упражнений не заменяются имитацией Codex. Новые комплекты создаются в `examples/content-depth/`; создаваемая учеником работа — только `.learning/workspaces` через штатный `--prepare` с отказом при существующей папке.

Локальные стенды проверяют Python-обработчик, формат данных, workflow или протокол клиента, но не подтверждают работу модели. Записанные события маркируются фикстурами. Каждый клиент отделяет внешний процесс от проверяемой логики и имеет таймаут/отмену/ошибку. Никакая лаборатория не включается сама при открытии сайта или запуске offline.

SDK выбран **Python**: один клиент на официальном `openai-codex`, версия выбирается и закрепляется по совместимости baseline до реализации клиента. Версию нельзя брать из памяти или использовать незакреплённый `latest`. Зависимость и подготовка изолированы от базовых stdlib-упражнений и offline-сборки. TypeScript SDK получает локальную справочную карту, но второй клиент не входит в этот контракт.

App-server: минимальный клиент stdio; remote-лаборатория использует loopback и объясняет WSS/SSH для нелокального применения без создания публичного listener. CI-template хранится в examples, не активируется в `.github/workflows`. Плагин поставляется как учебный пакет, без регистрации marketplace и публикации.

### ADR-CD-05 Три независимых уровня доказательств

`classification_complete`, редакционная полнота и native verification — разные показатели. Расширение формата sources сохраняет совместимость существующих потребителей либо обновляет их в том же ограниченном этапе.

Реестр не получает массовый VERIFIED по числу страниц. Редакционное доказательство содержит ID, rubric, конкретный путь/anchor, результат каждого пункта, reviewer и хеш просмотренного файла. Сценарный отчёт содержит command, exit code, status, candidate hash, spec hash, версии среды, относительные пути и хеши обезличенных журналов. Один пройденный пример не подтверждает все интеграции.

Для M1 `tested_cli` не заполняется документальной сверкой или `--version`. У закрытого сценария M1 может отдельно оставаться `native_status: NOT_RUN`; это явно показано в интерфейсе. В release это не успех. Действующие release/live-инварианты не ослабляются.

### ADR-CD-06 Ограниченная оркестрация

T01 → T02 → T03 → T04 → T05 → T06 выполняются последовательно. У каждой задачи отдельный стабильный task_id и ledger. Только главный оркестратор передаёт работу developer/reviewer; developer не вызывает reviewer. Текущий SHA проверяется один раз; fix-verification относится только к изменённому SHA.

Нельзя объявить закрытым критерий с отсутствующим тестом, неисполнимым обязательным сценарием или старым доказательством. Environment error записывается отдельно и не превращается в PASS; для symlink-тестов требуется реально способный runner, без silent skip, удаления проверки или самовольного изменения прав ОС.

## Разрешённые и запрещённые действия

Разрешены локальная документация, тесты, сборка и явное получение публичных источников для baseline. Новые зависимости сначала определяются и фиксируются, затем ставятся отдельно только в согласованную проектную среду. В offline запрещены сеть, установка пакетов, модельные запросы и изменение профиля.

Запрещены глобальные `~/.codex`/`~/.agents` и конфигурация desktop app, чтение/копирование auth, ключей и личных логов, публикация, git push, создание release, подключение аккаунтов и автоматическая активация hooks/MCP/plugins. Удаление LICENSE, старых обязательных сценариев и пользовательской работы запрещено.

## Совместимость и конфликтующие изменения

`repair-learning-experience` не архивируется автоматически. Реализация сверяет фактическое дерево в начале каждой задачи и сохраняет чужие правки. При настоящем конфликте нормативных требований применяется более строгий сохраняющий данные вариант; неоднозначность фиксируется ADR в пределах frozen scope, не удалением старой проверки.
