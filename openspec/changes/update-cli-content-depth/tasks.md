# Задачи реализации M1

Порядок обязательный. Детальная приёмка — `verification.yaml`; контракты — `contracts/Txx/TASK_CONTRACT.yaml`. Подпункты чеклиста не добавляют новые acceptance criteria. Галочка ставится только после фактического закрытия соответствующего результата.

## T01 Достоверность и baseline
- [ ] T01.1 Исправить маршрут mcp-server и регрессию ложного PASS справки.
- [ ] T01.2 Снять закреплённую инвентаризацию CLI, slash-команд, flags, feature flags, конфигурации и тематических источников.
- [ ] T01.3 Связать каждую возможность с категорией, локальным материалом/планом, применимостью и источником; зафиксировать baseline и хеши.
- [ ] T01.4 Исправить UTF-8 чтение/захват вывода без отключения symlink-проверок; определить пригодный runner.
- [ ] T01.5 Реализовать stage-проверку и отрицательные фикстуры T01; получить fresh evidence и review.

## T02 Визуальная инфраструктура и эталон MCP
- [ ] T02.1 Добавить доставку безопасных локальных SVG и исходников схем без CDN.
- [ ] T02.2 Создать схемы D01–D08 и объяснить их в уроках.
- [ ] T02.3 Переработать stdio-MCP в эталонный полный материал с успешным и ошибочным сценариями.
- [ ] T02.4 Проверить file://, мобильный viewport и отсутствие JS/сети; получить review эталона.

## T03 Основной CLI и локальный справочник
- [ ] T03.1 Углубить сценарии B01–B04, карточки всех применимых команд и конфигурационных полей.
- [ ] T03.2 Переработать содержательные разделы уроков модулей 01–06 без новых произвольных уроков.
- [ ] T03.3 Связать иллюстрации, примеры, quiz, источники и сохраняемый прогресс; проверить ограничения платформ и доступности.
- [ ] T03.4 Выполнить автоматические и редакционные проверки T03.

## T04 Расширения и шаблоны
- [ ] T04.1 Создать схемы D09–D11 и hooks-лаборатории H01–H04; документировать остальные события закреплённой карты.
- [ ] T04.2 Добавить роли исследователя/ревьюера/исполнителя и законченный сценарий явной делегации.
- [ ] T04.3 Добавить четыре готовых навыка, учебный plugin bundle и полноценные stdio/HTTP-OAuth материалы.
- [ ] T04.4 Выполнить локальные положительные/отрицательные сценарии E01–E04 и редакционную приёмку.

## T05 Продвинутая автоматизация
- [ ] T05.1 Завершить exec/JSONL/schema/retry сценарий A01 и учебный workflow A02.
- [ ] T05.2 Закрепить SDK-зависимость и создать один Python SDK-клиент A03 с локальным тестовым адаптером.
- [ ] T05.3 Создать схему D12 и stdio app-server клиент A04, материалы remote/cloud A05.
- [ ] T05.4 Уточнить самостоятельные уроки SDK/remote/cloud и зарегистрировать их без изменения прежних ID.
- [ ] T05.5 Выполнить сценарии T05; нигде не объявлять стенд реальной совместимостью.

## T06 Итоговая редактура и кандидат
- [ ] T06.1 Завершить редакционную рубрику всех 62 исходных и добавленных в рамках этого change уроков.
- [ ] T06.2 Пройти capstone C01, проверяющий совместную работу нативных механизмов через явный live-маршрут и локальный самостоятельный вариант.
- [ ] T06.3 Пройти полный offline, content contract, исходные regression checks и package validation на одном кандидате.
- [ ] T06.4 Проверить распакованный ZIP через file:// при заблокированной сети; проверить диаграммы, материалы, поиск, quiz и импорт/экспорт прогресса.
- [ ] T06.5 Сопоставить отчёты и хеши; записать ACCEPTED_M1_CANDIDATE без присвоения совместимого релиза; получить финальный review и сводку ledger.

## M2 Отдельный допуск к релизу
- [ ] M2.1 Получить отдельно согласованные внешние условия и выполнить действующие live-сценарии с реальным CLI/моделью, включая требуемые повторения наставника.
- [ ] M2.2 Провести ручные/платформенные сценарии и release gate именно этого кандидата.
- [ ] M2.3 Получить явное решение о выпуске. Публикация не разрешена автоматически ни M1, ни данным чеклистом.

M2 не входит в acceptance M1, но его незавершённость остаётся видимой и блокирует заявление о совместимом выпуске.
