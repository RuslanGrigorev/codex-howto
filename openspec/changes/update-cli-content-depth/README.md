# Спецификация наполнения курса Codex CLI

Пакет подготовлен по аудиту от 5 октября 2026 года для последующего запуска M1 в `/goal` с явной делегацией реализации и проверки. Реализация и live-проверки не запущены.

## Что читать

- `proposal.md` — результат M1, отличие от M2 и границы изменения.
- `TASK_CONTRACT.yaml` — замороженный контракт M1: 11 критериев приёмки.
- `design.md` — шесть обязательных архитектурных решений.
- `specs/*/spec.md` — 14 новых нормативных требований и 24 GIVEN/WHEN/THEN сценария, добавленных к действующим спецификациям.
- `verification.yaml` — конечная матрица сценариев, 12 схем, 18 how-to единиц, рубрики, evidence и распределение по этапам.
- `contracts/T01` — `contracts/T06` — шесть самостоятельных frozen контрактов для developer/reviewer.
- `tasks.md` — последовательный чеклист реализации.
- `orchestration.md` — роли, preflight, ledger, review-режимы, dedup и конечный арбитраж.
- `GOAL_PROMPT.md` — готовый пользовательский запрос для запуска; он согласует только M1.

## Условия готовности

M1 требует полного офлайн-кандидата, действительных PASS всех обязательных M1 сценариев и исходных локальных регрессий, редакционной приёмки материалов и нуля открытых P0/P1. Это не утверждение о реальном запуске CLI, совместимости всех платформ или разрешении публиковать курс.

M2 — отдельная последующая приёмка реальным Codex с согласованными внешними условиями и действующим release gate. `tested_cli`, native и release не заполняются чтением документации, локальными стендами или `--version`.

`scripts/check_content_contract.py` и новые сценарные тесты здесь **заданы как результат реализации**, а не представлены уже существующими командами. T01 реализует общий интерфейс и свои проверки, следующие этапы — соответствующие методы. Отсутствующая проверка не даёт PASS.

## Проверка самого пакета

Из корня проекта:

```powershell
openspec validate update-cli-content-depth --strict --no-interactive
```

Контракты созданы штатным `convergence_tools.py init-contract` и окончательно уточнены до начала реализации. Локальные копии состояния находятся в `.learning/convergence/state`, не в глобальном CODEX_HOME. Перед исполнением сверять SHA-256 сохранённых контрактов; будущие ledger принадлежат оркестратору и не являются evidence о выполнении.

Согласование спецификации и запуск реализации — отдельное действие пользователя. Данный пакет не меняет активный курс, глобальные настройки, права ОС, подключённые сервисы или опубликованный сайт.
