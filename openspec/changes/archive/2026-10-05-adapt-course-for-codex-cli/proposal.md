# Русскоязычный автономный курс Codex CLI

## Why

Нужен курс, который можно полностью изучать без внешнего интернета, а затем применять в Codex CLI. Исходный claude-howto уже содержит пригодную статическую сборку и тесты, но учебное содержание, конфигурации и навыки привязаны к Claude.

## What Changes

**Решение: доработать имеющийся проект в отдельном форке.** Новое имя репозитория допустимо; новая кодовая база и параллельная поддержка Claude не нужны. Исходный архив остаётся точкой возврата и источником атрибуции.

- **BREAKING:** русский язык и Codex CLI становятся единственным активным направлением. Claude-инструкции, прежние трекеры и язык по умолчанию заменяются. Старые зачёты не мигрируют как навыки Codex.
- Готовый ZIP содержит учебник, справочник, вопросы, задания, исходники, подсказки и решения. Открытие через file://; сеть, сборщик и учётная запись для чтения не нужны.
- Один навык `$learn` использует те же локальные материалы, что сайт. Он не обещает работу облачной модели без сети и не подменяет выполненное упражнение записанным диалогом.
- Один каталог курса, один реестр источников/совместимости и единый переносимый JSON прогресса заменяют дублирование.
- Сохраняются подход к сборке и полезные существующие проверки. Добавляются две точки обслуживания: `scripts/verify.py` и `scripts/check_updates.py`.
- Каждый сценарий получает проверку. Формальная полнота спецификации и реальная приёмка продукта фиксируются отдельно.

Не создаём backend, SPA-фреймворк, базу данных, аккаунты, собственный терминал, RAG, обязательный MCP, автообновлятор или платформу для нескольких AI-клиентов. EPUB и распространение самого курса как плагина отложены; учебная тема плагинов сохранена в модуле расширений.

## Capabilities

### New Capabilities

- `offline-delivery`: автономная готовая поставка и контролируемые предварительные зависимости.
- `course-content`: единый русский маршрут, корректный CLI-синтаксис и проверяемое обучение.
- `codex-tutor`: один наставник, использующий локальный курс и реальные результаты проверок.
- `learning-progress`: локальные раздельные результаты с ручным импортом и экспортом.
- `release-maintenance`: проверяемая совместимость и небольшой процесс обновления.
- `acceptance-validation`: полнота сценариев и доказательная приёмка выпускаемых файлов.

### Modified Capabilities

Нет: в исходном архиве не обнаружен каталог действующих OpenSpec-спецификаций. Все шесть возможностей вводятся как ADDED в системе спецификаций, хотя часть кода переиспользуется. Это не заявление о разработке приложения с нуля. Основные specs появятся при архивировании завершённого change.

## Impact

Затронуты `scripts/build_website.py`, шаблоны и JavaScript сайта, `scripts/vendor_assets.py`, учебные Markdown, тесты, `.github/workflows/`, прежние `.claude/skills/` и `local-progress/`. Конкретный перенос описан в [migration-map.md](migration-map.md).

Первый подтверждаемый профиль: Linux x86_64, Python 3.11+, Git и целевая Codex CLI 0.160.0. Версии браузеров и модели фиксируются в отчёте реального прогона. Другие ОС и локальные модели не объявляются протестированными автоматически. Статический пакет не привязывается намеренно к этой ОС, но заявления о совместимости ограничиваются доказательствами.

Кандидат версии CLI выбран по официальному релизу; пока `tested_cli = null`. Источники и границы проверки: [sources.md](sources.md). Этот пакет не содержит готового курса и не отмечает разработческие задачи выполненными.
