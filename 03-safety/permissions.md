# Разрешения, песочница и безопасные пути

## Чему вы научитесь

Выбрать минимальные права для задачи и проверить действующие ограничения.

## Что нужно перед началом

Сначала пройдите: [Начало: что изучаем и как проверяем результат](../01-start/overview.md). Учебные файлы входят в поставку. Установленные программы и доступ к модели требуются только для соответствующей практики.

**Песочница** ограничивает возможности процесса; **политика подтверждений** определяет запросы разрешения. Эти настройки связаны, но не взаимозаменяемы.

```bash
codex --sandbox read-only --ask-for-approval on-request
codex --sandbox workspace-write --ask-for-approval on-request
```

`read-only` предназначен для сценария без записи. `workspace-write` допускает запись в установленных границах. Дополнительную область через `--add-dir` нужно обосновать. `--ask-for-approval never` не означает «разрешить всё»: действие, которому нужны отсутствующие права, должно завершиться отказом. Для учебного маршрута не используйте обход песочницы и подтверждений.

## Практика путей

Напишите `validate_target_path`, который возвращает нормализованный `Path` для файла внутри переданного корня и возвращает `None` для недопустимого пути: соседний каталог, `..`, абсолютный путь, Windows-диск и символическую ссылку наружу. Строковый `startswith` ошибочен: `/work/repo-other` начинается с `/work/repo`, но не находится внутри него.

Эта функция — вспомогательное упражнение по путям, **не эмулятор безопасности Codex**. Она не защищает от всех гонок файловой системы и не создаёт OS-песочницу. Реальную конфигурацию Codex проверяйте отдельно в одноразовой папке: чтение разрешено, запрещённая запись не должна происходить.

## Проверяемое упражнение

Выполняйте команды из корня репозитория или из `source` готового офлайн-пакета. Подготовка не перезаписывает существующую работу.

```bash
python scripts/verify.py --prepare safety-guard
# Измените файлы в .learning/workspaces/safety-guard
python scripts/verify.py --exercise safety-guard --workspace .learning/workspaces/safety-guard
```

Проверка запускает независимый `examples/safety-guard/test.py`, а не тест из рабочей папки. Эталон находится в `examples/safety-guard/solution`; открывайте его после собственной попытки. Тестируемый Python-код исполняется на вашей машине: запускайте только доверенные учебные файлы. Ограничение пути не является OS-песочницей.

## Что считается выполнением в Codex

Без модели доступны весь текст, вопросы, исходники и локальные тесты. Они не подтверждают работу CLI. Для практики сохраните версию `codex --version`, модель, провайдера и обезличенный результат реального запуска. Отметку можно внести через `scripts/progress.py` после проверки, согласно [правилам валидации](../reference/validation.md). Самоотчёт ученика не заменяет выпускные доказательства проекта.
