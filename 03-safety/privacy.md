# Секреты, журналы и подготовка к публикации

## Чему вы научитесь

- Исключать API-ключи, токены авторизации и персональные данные из контекста Codex CLI.
- Настраивать списки игнорирования (`.gitignore`, `.codexignore`) для защиты чувствительных файлов.
- Проверять журналы сессий и экспортируемые материалы перед отправкой или публикацией.
- Запускать локальные скрипты аудита безопасности и сигнатурного поиска секретов.

## Что нужно перед началом

- Базовые знания о структуре проекта и файлах конфигурации.
- Отсутствие реальных секретов в рабочей копии учебного репозитория.
- Понимание, что добавление файла в `.gitignore` не удаляет его из предыдущих коммитов Git.

## Схема процесса

Конвейер предотвращения утечек при работе с Codex CLI:

```
[Рабочий репозиторий: код, тесты, окружение]
                 │
                 ├──> [.env, auth.json, private_keys]
                 │                 │
                 │                 ▼
                 │       [.codexignore / .gitignore]
                 │                 │
                 ▼                 ▼
  [Контекст агента Codex: фильтрация файлов]
                 │
                 ▼
  [Генерация логов сессии: .codex/sessions/]
                 │
                 ▼
┌────────────────────────────────────────────────────────┐
│             Локальный аудит безопасности               │
├────────────────────────────────────────────────────────┤
│  1. python scripts/check_publication.py                │
│  2. Сканирование энтропии и шаблонов токенов (gitleaks)│
│  3. Проверка истории Git коммитов                      │
└────────────────────────┬───────────────────────────────┘
                         │
        ┌────────────────┴────────────────┐
     Чисто?                           Утечка?
        │                                 │
        ▼                                 ▼
[Готово к публикации / PR]       [1. Отзыв/ротация ключа]
                                 [2. Очистка истории git]
                                 [3. Исправление фильтров]
```

## Команды и параметры

Команды аудита и проверки чистоты репозитория перед экспортом:

```bash
# Базовая проверка рабочей копии на наличие секретов и запрещенных артефактов
python scripts/check_publication.py

# Глубокая проверка всей истории Git коммитов
python scripts/check_publication.py --git-history

# Очистка локальных кэшей и временных снимков сессий
rm -rf .learning/workspaces/*/sessions/
```

Конфигурация исключений в `.codexignore`:

```text
# Исключение файлов авторизации и переменных окружения
.env
.env.*
auth.json
*.pem
*.key
**/credentials*
**/logs/*.log
```

## Разбор примера

Рассмотрим процедуру подготовки проекта к публикации или передаче коллегам:

1. Создаём конфигурацию `.codexignore` с перечнем масок приватных файлов.
2. Проверяем, что агент Codex при вызове инструментов поиска по репозиторию не считывает `.env`:
   - Агент вызывает `list_dir` или `find_files` — файл `.env` скрыт из выдачи.
3. Перед созданием архива запускаем сигнатурный валидатор:
   ```bash
   python scripts/check_publication.py
   ```
4. Если утилита находит подозрительную строку (например, паттерн `sk-proj-...`):
   - Немедленно отзываем скомпрометированный ключ в панели провайдера.
   - Удаляем секрет из файла и добавляем переменную в окружение среды CI/CD.
   - Повторяем проверку до получения статуса `CLEAN: no leaks detected`.

## Ограничения и безопасность

- Файлы `auth.json`, системные токены и личные логи никогда не должны включаться в архив практикума или репозиторий.
- Сигнатурный поиск по шаблонам не дает 100% гарантии: пароли с низкой энтропией или нестандартные токены могут быть пропущены.
- Никогда не отправляйте реальные пароли или токены в чат языковой модели с запросом: «Проверь, безопасен ли этот ключ?».

## Типовые ошибки

1. **Коммит секретов с последующим удалением**: удаление файла новым коммитом оставляет секрет в истории Git.
2. **Публикация журнала сессий**: передача файлов трассировки `.jsonl`, содержащих дампы переменных окружения процесса.
3. **Игнорирование скриншотов и артефактов**: публикация снимков экрана терминала с открытыми ключами API.

## Практика

1. Создайте в тестовой папке файл `.codexignore` и внесите правила для защиты секретов.
2. Проверьте поведение сканера `check_publication.py` на эталонном безопасном дереве файлов.
3. Составьте чек-лист проверки репозитория перед созданием архива релиза:
   - Отсутствие `.env` и `auth.json`.
   - Проверка статуса `git status --ignored`.
   - Запуск независимого скрипта проверки публикаций.
