# Как принять исправленную версию

Проверка применения патча, проверка курса и разрешение публикации — разные результаты. Статус APPLIED относится только к точному содержимому файлов. Этот документ не утверждает, что каждый нативный сценарий уже пройден.

## 1. Проверка исходников

Установщик находится во внешней папке патча. Выполните `--verify --strict` и сохраните JSON-квитанцию в `.learning/patch-application.json`. Требуются `status: APPLIED`, `source_tree_exact: true`, отсутствие несовпадений, лишних исходников и оставшихся удалённых файлов. Не правьте манифест для прохождения этой проверки.

После собственной правки курс закономерно перестаёт совпадать с патчем: сохраните квитанцию до правок и отдельно зафиксируйте новый коммит. Не выдавайте старые доказательства за проверку нового дерева.

## 2. Подготовка среды

Заранее нужны Python 3.11+, зависимости из `scripts/requirements-dev.txt`, Node.js 22+ для JavaScript-тестов и Chromium для Playwright. Установка зависимостей не является частью автономного учебного маршрута.

```bash
python -m pip install -r scripts/requirements-dev.txt
python -m playwright install chromium
```

В среде без сети используйте заранее подготовленное окружение. Не объявляйте отсутствие программы успешной проверкой.

## 3. Локальные проверки

Из корня проекта:

```bash
python scripts/check_coverage.py
python -m pytest scripts/tests -q
python scripts/check_project.py exercises
python scripts/verify.py --profile offline
```

`check_coverage.py` проверяет связи 62 уроков, но возвращает `meaning: STRUCTURAL_MAPPING_ONLY`. Это не доказательство полноты документации. `--require-complete` пока должен завершаться неуспешно: открытые вопросы перечислены в sources.json.

Профиль offline собирает сайт, проверяет локальные ссылки, конфигурации, тесты, публикационные файлы и настоящий file://. Браузерный запрет даёт BLOCKED; дополнительный режим `embedded` или `http` не снимает этот блокер.

## 4. Пакет, который получит ученик

```bash
python scripts/build_website.py --output .learning/site
python scripts/check_site.py --site .learning/site
python scripts/browser_check.py --site .learning/site --mode file
python scripts/package_course.py --site .learning/site
```

Распакуйте `.learning/dist/codex-course-candidate.zip` в новую папку вне исходного дерева. Откройте её `index.html` через настоящий file:// в профиле браузера без внешнего доступа. Проверяйте именно распакованный пакет, не только исходную папку сборки. Ученик не обязан запускать сервер.

Проверьте главную и десять модулей, поиск `/goal`, переход между уроками, четыре ссылки материалов у каждого из девяти упражнений, чтение и скачивание эталона, неправильные и правильные ответы, импорт/экспорт JSON, перезагрузку и переход на другую страницу. Обе темы и ширины 390/768/1440 пикселей не должны давать общего горизонтального переполнения. Проверьте клавиатуру и масштаб 200% вручную. Правила хранилища file:// различаются между браузерами: недоступность сохранения должна быть видима, а экспорт должен оставаться доступным.

Исходники исполняются из `source/`. До проверки упражнения создаётся редактируемая копия через `--prepare`; тест запускается из независимой папки examples. Выполнение Python-кода — не системная песочница для недоверенных программ.

## 5. Реальный Codex

Без установленного Codex и доступной модели профиль live возвращает BLOCKED. Не подменяйте это учебным JSON, скриншотом чужого прогона или текстом модели.

```bash
python scripts/verify.py --profile live
```

Для разрешённого реального вызова сначала подготовьте изолированный `.learning/codex-home` и авторизацию вне Git. Затем укажите `--allow-model-call --model ИДЕНТИФИКАТОР_ДОСТУПНОЙ_МОДЕЛИ --codex-home .learning/codex-home`. Возможна тарификация. Не включайте эти параметры автоматически. Базовый live-профиль не заменяет отдельные сценарии `/goal`, `$learn`, разрешений, MCP, hooks и субагентов.

## 6. Публикация

Проверьте историю Git отдельным сканером, зависимости, права workflow, происхождение ресурсов и лицензии. LICENSE и NOTICE должны входить в релиз. Для DOCS-SCOPE-REVIEW недостаточно пометить задачи выполненными: нужна действительная сверка официального индекса и всех зарегистрированных тем.

Сохраняйте результаты по схемам [правил валидации](reference/validation.md); release gate проверяет хеши текущего дерева и доказательств. Не запускайте публикацию при FAIL, BLOCKED, SKIP, NOT_RUN или отсутствии обязательного случая. Официальную OpenSpec-валидацию запускайте установленным CLI, не выдавая структурное чтение YAML за её результат.
