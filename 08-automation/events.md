# JSONL: ход выполнения, ошибки и итоговый ответ

## Чему вы научитесь

- Глубоко понимать семантику каждого типа событий в потоке JSONL неинтерактивного режима `codex exec`.
- Извлекать метаданные расхода токенов (`usage: input_tokens, output_tokens`) из события `turn.completed`.
- Корректно определять граничные состояния: обрыв потока, частичный JSON, терминальные сбои `turn.failed`.
- Строить надежные пайплайны обработки данных без риска ложноположительных срабатываний (False Success).

## Что нужно перед началом

- Прохождение предыдущего урока [codex exec: процесс и события JSONL](non-interactive.md).
- Понимание принципов работы потоковых генераторов в Python/Node.js.
- Установленный Codex CLI 0.160.0.

## Схема процесса

Автомат состояний обработки потока событий JSONL:

```
                  ┌──────────────────────┐
                  │    START: Ожидание   │
                  └──────────┬───────────┘
                             │ thread.started
                             ▼
                  ┌──────────────────────┐
                  │   ACTIVE: В работе   │◄──────────────┐
                  └──────────┬───────────┘               │
                             │                           │ item.completed
               ┌─────────────┴─────────────┐             │ (message / tool)
               │                           │             │
               ▼ turn.failed               ▼ item.*      │
    ┌──────────────────────┐    ┌──────────────────────┐ │
    │   FAILED: Ошибка     │    │  PROCESSING: Разбор  ├─┘
    └──────────────────────┘    └──────────┬───────────┘
                                           │ turn.completed
                                           ▼
                                ┌──────────────────────┐
                                │   SUCCESS: Финал     │
                                └──────────────────────┘
```

## Команды и параметры

Пример получения и анализа потока событий в консоли:

```bash
# Генерация потока событий с фильтрацией через утилиту jq
codex exec --json --sandbox read-only "Получи версию из package.json" | jq -c 'select(.type == "item.completed")'

# Подсчет потребленных токенов из финального события
codex exec --json --sandbox read-only "Сделай аудит src/" | jq 'select(.type == "turn.completed") | .usage'
```

Примеры типов событий в потоке:

```json
{"type": "thread.started", "thread_id": "thr_992"}
{"type": "turn.started", "turn_id": "turn_001"}
{"type": "item.completed", "item": {"type": "tool_call", "name": "read_file", "path": "package.json"}}
{"type": "item.completed", "item": {"type": "agent_message", "text": "Версия пакета: 1.4.0"}}
{"type": "turn.completed", "usage": {"input_tokens": 1250, "output_tokens": 42}}
```

В случае ошибки:
```json
{"type": "turn.failed", "error": {"code": "context_length_exceeded", "message": "Context window limit reached"}}
```

## Разбор примера

Рассмотрим обработку сбойного сценария:

1. Запускаем команду с намеренно невыполнимым условием:
   ```bash
   codex exec --json --sandbox read-only "Запиши лог в /etc/shadow"
   ```
2. Поток возвращает:
   - `thread.started`
   - `turn.started`
   - `item.completed` (агент пытается вызвать команду записи)
   - `turn.failed` (песочница блокирует попытку записи с кодом `PermissionDenied`)
3. Обработчик событий проверяет тип терминального сообщения:
   - Событие `turn.completed` **отсутствует**.
   - Событие `turn.failed` **присутствует**.
4. Скрипт перехватывает ошибку, логирует поле `error.message` и завершает конвейер с ненулевым статусом ошибки, не пытаясь извлечь текст несуществующего успешного ответа.

## Ограничения и безопасность

- Никогда не считайте задачу успешной только потому, что последняя полученная строка синтаксически валидна: она может быть событием ошибки `turn.failed`.
- При внезапном прерывании процесса (SIGKILL / OOM-killer) поток просто обрывается без терминального события: обработчик обязан детектировать незавершенный поток.
- Избегайте сохранения сырых дампов JSONL в общедоступных директориях, если обрабатываемый код содержит конфиденциальные фрагменты.

## Типовые ошибки

1. **Проверка только последней строки**: если перед завершением CLI вывел пустую строку или предупреждение, парсер последней строки упадет с ошибкой JSONDecodeError.
2. **Игнорирование поля usage**: отсутствие мониторинга расхода токенов в автоматических циклических сценариях.
3. **Ложное срабатывание при аварии**: принятие сообщения об ошибке из `agent_message` за полезный результат работы агента.

## Практика

1. Напишите Python-скрипт, построчно читающий `sys.stdin` и классифицирующий события по трем категориям: жизненный цикл, действия инструментов, терминальный статус.
2. Протестируйте скрипт на трех фикстурах: успешный запуск, ошибка валидации схемы и оборванный поток данных.
3. Добавьте проверку того, что при получении `turn.failed` скрипт завершается с `sys.exit(1)`.
