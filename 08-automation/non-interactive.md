# codex exec: процесс и события JSONL

## Чему вы научитесь

- Запускать Codex CLI в пакетном неинтерактивном режиме с помощью команды `codex exec`.
- Парсить структурированный поток событий JSONL (`--json`) в режиме реального времени.
- Обрабатывать жизненный цикл событий: `thread.started`, `turn.started`, `item.completed`, `turn.completed`, `turn.failed` и `error`.
- Реализовывать надежные клиентские обработчики для CI/CD конвейеров и скриптов автоматизации.

## Что нужно перед началом

- Базовые знания о потоках ввода-вывода (stdout, stderr) и формате JSON Lines.
- Понимание механизмов песочницы из модуля [Безопасность и песочница](../03-safety/permissions.md).
- Установленный Codex CLI 0.160.0.

## Схема процесса

Поток событий JSONL при выполнении команды `codex exec --json`:

```
[Запуск процесса: codex exec --json "задача"]
                   │
                   ▼
       stdout (потоковые строки JSONL)
  ┌────────────────────────────────────────────────────────┐
  │ {"type": "thread.started", "thread_id": "thr_01"}      │
  │ {"type": "turn.started", "turn_id": "turn_01"}         │
  │ {"type": "item.completed", "item": {"type": "tool"}}   │
  │ {"type": "item.completed", "item": {"type": "message"}}│
  └────────────────────────┬───────────────────────────────┘
                           │
             ┌─────────────┴─────────────┐
          Успех                       Ошибка
             │                           │
             ▼                           ▼
  {"type": "turn.completed"}     {"type": "turn.failed", "error": ...}
             │                           │
             ▼                           ▼
     [Exit code: 0]              [Exit code: 1]
```

## Команды и параметры

Параметры запуска неинтерактивного режима:

```bash
# Запуск автономной команды с выводом событий в формате JSONL
codex exec --json --sandbox read-only "Проанализируй безопасность src/auth.py"

# Перенаправление потока событий в лог-файл для аудита
codex exec --json --sandbox workspace-write "Запусти тесты и исправь баг" > run_events.jsonl

# Запуск подготовки и проверки автономного упражнения
python scripts/verify.py --prepare cli-stream
python scripts/verify.py --exercise cli-stream --workspace .learning/workspaces/cli-stream
```

Пример строки события `item.completed` с текстовым сообщением агента:

```json
{
  "type": "item.completed",
  "item": {
    "id": "msg_01",
    "type": "agent_message",
    "text": "Анализ завершен: уязвимостей в auth.py не обнаружено."
  }
}
```

## Разбор примера

Рассмотрим обработку потока вывода парсером автоматизации:

1. Запускаем команду `codex exec --json --sandbox read-only "cat version.txt"`.
2. Читаем `stdout` построчно:
   - Строка 1: `thread.started` ➔ сохраняем идентификатор сессии.
   - Строка 2: `turn.started` ➔ инициализируем таймер оборота.
   - Строка 3: `item.completed` (tool call) ➔ фиксируем вызов чтения файла.
   - Строка 4: `item.completed` (agent_message) ➔ накапливаем итоговый текст ответа.
   - Строка 5: `turn.completed` ➔ фиксируем успешное завершение оборота.
3. Процесс завершается с кодом `0`. Скрипт автоматизации возвращает накопленный текст ответа.

## Ограничения и безопасность

- В режиме `codex exec` диалоговые запросы подтверждения невозможны: если требуется подтверждение, а флаг `--ask-for-approval` не выставлен в `never`, операция будет отклонена.
- Не судите об успехе задачи только по наличию строки `agent_message`: обязательно проверяйте терминальное событие `turn.completed` и код возврата процесса.
- При возникновении ошибки `turn.failed` агент может вывести поясняющий текст, но статус выполнения задачи является аварийным.

## Типовые ошибки

1. **Попытка парсить весь stdout как один JSON-объект**: чтение всего вывода через `json.loads(output)` вместо построчной итерации по JSONL.
2. **Игнорирование stderr**: потеря критических предупреждений песочницы или ошибок компиляции, которые пишутся в `stderr`, а не в JSON-поток.
3. **Преждевременное чтение ответа**: извлечение текста из незавершенного блока, когда модель еще не закончила генерацию.

## Практика

1. Подготовьте рабочее пространство упражнения `cli-stream`:
   ```bash
   python scripts/verify.py --prepare cli-stream
   ```
2. Реализуйте в `.learning/workspaces/cli-stream/` устойчивый парсер потока JSONL, корректно распознающий события `turn.completed`, `turn.failed` и сообщения агента.
3. Запустите независимый тест упражнения:
   ```bash
   python scripts/verify.py --exercise cli-stream --workspace .learning/workspaces/cli-stream
   ```
4. Убедитесь, что тест `examples/cli-stream/test.py` подтверждает правильную обработку как успешных потоков, так и аварийных сценариев с ненулевым кодом завершения.
