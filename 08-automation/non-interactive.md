# codex exec: процесс и события JSONL

## Чему вы научитесь

Запустить неинтерактивную задачу и корректно обработать завершение процесса и события.

## Что нужно перед началом

Сначала пройдите: [Начало: что изучаем и как проверяем результат](../01-start/overview.md). Учебные файлы входят в поставку. Установленные программы и доступ к модели требуются только для соответствующей практики.

Для автоматизации используйте `codex exec`, а не выдуманный флаг переключения интерактивного клиента. `--json` выдаёт последовательность событий JSONL: каждую строку разбирают отдельно.

```bash
codex exec --json --sandbox read-only "Объясни структуру учебного проекта без изменений"
```

Типовые события: `thread.started`, `turn.started`, `item.completed`, `turn.completed`, `turn.failed`, `error`. Текст ответа находится в завершённом элементе `agent_message`. Не каждое событие содержит текст; неизвестные расширения формата нужно обработать явно.

## Условие успеха

Недостаточно найти одну красивую строку ответа. Проверьте корректность JSON, завершение оборота, отсутствие ошибки и код завершения процесса. Пустой или оборванный поток не успешен. `turn.failed` не должен превращаться в PASS только потому, что процесс ещё выводил сообщения.

В учебном парсере сохраняются ошибки и предупреждения; stdout и stderr не смешиваются. Дополнительные неизвестные события не должны молча подменять терминальное состояние.

## Практика

Реализуйте парсер и проверьте успешный поток, ошибку модели, неверный JSON, пустой ввод и ненулевой exit code. Затем сравните с реальным `exec`. Заранее записанный поток проверяет парсер, но не доступность модели и не работу CLI.

## Проверяемое упражнение

Выполняйте команды из корня репозитория или из `source` готового офлайн-пакета. Подготовка не перезаписывает существующую работу.

```bash
python scripts/verify.py --prepare cli-stream
# Измените файлы в .learning/workspaces/cli-stream
python scripts/verify.py --exercise cli-stream --workspace .learning/workspaces/cli-stream
```

Проверка запускает независимый `examples/cli-stream/test.py`, а не тест из рабочей папки. Эталон находится в `examples/cli-stream/solution`; открывайте его после собственной попытки. Тестируемый Python-код исполняется на вашей машине: запускайте только доверенные учебные файлы. Ограничение пути не является OS-песочницей.

## Что считается выполнением в Codex

Без модели доступны весь текст, вопросы, исходники и локальные тесты. Они не подтверждают работу CLI. Для практики сохраните версию `codex --version`, модель, провайдера и обезличенный результат реального запуска. Отметку можно внести через `scripts/progress.py` после проверки, согласно [правилам валидации](../reference/validation.md). Самоотчёт ученика не заменяет выпускные доказательства проекта.
