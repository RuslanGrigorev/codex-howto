# Итог по JSON Schema и продолжение exec

## Чему вы научитесь

Получить итог по JSON Schema и не перепутать его с потоком JSONL.

## Что нужно перед началом

Сначала пройдите: [Начало: что изучаем и как проверяем результат](../01-start/overview.md). Учебные файлы входят в поставку. Установленные программы и доступ к модели требуются только для соответствующей практики.

События выполнения и итоговая структура — разные данные. `--json` выбирает JSONL-события, а `--output-schema` задаёт схему итогового ответа. Схема примера находится в `examples/automation/result.schema.json`.

```bash
codex exec --sandbox read-only --output-schema examples/automation/result.schema.json -o result.json "Кратко опиши проект. Укажи, были ли изменены файлы"
```

`result.json` создаётся в текущем каталоге: выполняйте пример только в подготовленной папке. Проверьте итог JSON независимым валидатором схемы, а утверждение об изменениях — реальным сравнением файлов. Структурно правильный ответ может быть фактически неверным.

## Практика

Получите результат по схеме, затем намеренно удалите обязательное поле в копии и убедитесь, что валидатор отклоняет её. Изучите `codex exec resume --help` и повторите безопасный запрос в продолженной сессии. Не считайте `--ephemeral` способом отзыва уже переданных провайдеру данных: он относится к локальному сохранению сессии.

## Что считается выполнением в Codex

Без модели доступны весь текст, вопросы, исходники и локальные тесты. Они не подтверждают работу CLI. Для практики сохраните версию `codex --version`, модель, провайдера и обезличенный результат реального запуска. Отметку можно внести через `scripts/progress.py` после проверки, согласно [правилам валидации](../reference/validation.md). Самоотчёт ученика не заменяет выпускные доказательства проекта.
