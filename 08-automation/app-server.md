# Граница CLI, MCP server и app-server

## Чему вы научитесь

Различать обычный CLI, MCP server и app-server и выбрать подходящий интерфейс интеграции.

## Что нужно перед началом

Сначала пройдите: [Начало: что изучаем и как проверяем результат](../01-start/overview.md). Учебные файлы входят в поставку. Установленные программы и доступ к модели требуются только для соответствующей практики.

`codex exec` удобен для одноразовой автоматизации. `codex app-server` предоставляет протокол для приложения-клиента; `codex mcp-server` — другой интерфейс. Не направляйте ответы одного протокола в парсер другого только из-за общего слова JSON.

```bash
codex app-server --help
codex mcp-server --help
```

Создание собственной оболочки не нужно для прохождения этого курса. В продвинутой интеграции сначала фиксируют версию протокола, инициализацию, отмену, ошибки и разрешения. JSONL-парсер нашего упражнения проверяет события `exec`, а не универсально любые сообщения Codex.

## Практика

Выберите интерфейс для трёх задач: одноразовый отчёт CI, управление чатами из собственного приложения и предоставление Codex как MCP-инструмента. Обоснуйте выбор и выпишите проверки жизненного цикла. Реальную интеграцию app-server отмечайте отдельно; прочитанная схема не означает работающего клиента.

## Что считается выполнением в Codex

Без модели доступны весь текст, вопросы, исходники и локальные тесты. Они не подтверждают работу CLI. Для практики сохраните версию `codex --version`, модель, провайдера и обезличенный результат реального запуска. Отметку можно внести через `scripts/progress.py` после проверки, согласно [правилам валидации](../reference/validation.md). Самоотчёт ученика не заменяет выпускные доказательства проекта.
