# Автоматизация в CI без выдачи лишних прав

## Чему вы научитесь

Спроектировать проверяемый запуск в CI с минимальными правами и явными условиями отказа.

## Что нужно перед началом

Сначала пройдите: [Начало: что изучаем и как проверяем результат](../01-start/overview.md). Учебные файлы входят в поставку. Установленные программы и доступ к модели требуются только для соответствующей практики.

CI запускает код репозитория, поэтому недоверенный pull request и рабочие секреты нельзя соединять без оценки границ доверия. Для первого шага автоматизируйте только локальные тесты курса. Модельные вызовы должны быть отдельными, явно разрешёнными и ограниченными по времени.

```bash
python scripts/verify.py --profile offline
```

Эта команда не выполняет платный запрос к модели. Нативный профиль `live` требует явных параметров и подготовленного CODEX_HOME. В публикационных проверках недостаток доступа даёт `BLOCKED`, а не успех.

## Практика

Спроектируйте процесс, где обычный PR запускает тесты без API-ключа, а доверенный ручной запуск — ограниченный Codex smoke test. Сохраняйте код завершения и обезличенный артефакт проверки. Не запускайте код стороннего PR в контексте `pull_request_target` с секретами.

Официальный Codex GitHub Action — отдельный способ интеграции; его версию и входные параметры необходимо закрепить и проверить до включения. Курс не устанавливает action с модельной авторизацией автоматически.
